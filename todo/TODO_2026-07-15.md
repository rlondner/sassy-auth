## Risky patterns / missing tests called out

### 1. Email normalization is untested in the OTP path
`otp-sender.spec.ts` only exercises lowercase addresses. The case-normalization gap in
bug-0236 (and the store/gate disagreement) would not be caught by the current suite. Add a
mixed-case active-user test that asserts `outcome: 'sent'`.

### 2. Fire-and-forget email delivery swallows all errors
`sendSignInOtp` does `void emailer.send(...).catch(() => {})`. Delivery failures are
reported inside `EmailService`/Sentry by design, but the empty `.catch` means a
misconfigured emailer produces a neutral "sent" log with no local signal. Confirm the
EmailService-side Sentry capture actually fires in production, otherwise dropped codes are
invisible here.

### 3. `parseSessionCookie` regex is a known fragile spot
`apps/admin/app/login/actions.ts` documents that its comma-splitting regex "may fail when
Node concatenates multiple Set-Cookie headers with ', ' and one contains an Expires date."
It is safe today because BetterAuth returns a single cookie, but any future auth change
that emits a second Set-Cookie will silently break session forwarding. Consider swapping in
`set-cookie-parser` before that happens (already noted in-code).
