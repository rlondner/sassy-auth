## Risky patterns observed

1. **Privilege escalation via permission naming** — bug-0183 is the most severe finding today. `createPermission` has no guard on the `platform.*` prefix, allowing any admin with `platform.permissions.manage` to mint arbitrary platform privileges. Combined with the existing bug-0096 (rename to `platform.*`), the permission system has two independent privilege escalation vectors.

2. **BetterAuth table indexes missing** — bug-0179. The three BetterAuth tables (`Session`, `Account`, `Verification`) all lack indexes on their most-queried columns. This is a ticking time bomb — authentication performance will degrade linearly as the user base grows. The SassyAuth tables have proper indexes, so this is an oversight rather than a design choice.

3. **Unauthenticated endpoint hardening gap** — bug-0184. The invitation accept endpoint accepts unbounded password lengths for scrypt hashing. Combined with no rate limiting (bug-0080), this is a practical DoS vector.

4. **Phantom type fields** — bug-0186. The admin `User` type promises `lastLoginAt` and `createdAt` that the API never delivers. This pattern creates a false contract that wastes developer time and masks missing features.
