## Items needing attention

### 1. Verify `bug-0149` login redirect round-trip
The authorize endpoint now redirects unauthenticated users to `${ADMIN_URL}/login?next=<originalPath>`. Verify the admin's `/login` page honors the `next` query param and redirects back to the authorize endpoint with the original OAuth params after login. If it doesn't, users authenticate but never complete the OAuth flow.

### 2. Review `bug-0152` behavior tightening
`updateUser` now blocks `pending→active` status transitions without a completed invitation. Any admin scripts or API consumers that flip user status directly will break. Confirm no legitimate caller relies on this path.

### 3. Monitor `bug-0166` middleware fetch timeout under load
The admin middleware session validation has a 3-second fetch timeout. If auth-server p99 latency exceeds 3s under production load, every admin request bounces to `/login`. Watch ops metrics.

### 4. Monitor `bug-0209` timing guard CPU cost
The dummy scrypt verify on every user-not-found login attempt adds ~100ms of CPU cost. Combined with the 10 req/min/IP rate limit, single-IP abuse is bounded. But a distributed attacker (many IPs) can still consume ~100ms per rejected attempt. Monitor CPU under load.
