## Missing test coverage

The tests will pass even if guards are removed. Add at least one test per controller verifying that an unauthenticated/unauthorized request is rejected.
- [ ] **No cross-org authorization tests anywhere** — the `targetOrgId` parameter of `checkPermission` is never tested in any service spec. All specs mock `checkPermission` to succeed. Critical for validating the fix to bug-0024/0025.
- [ ] **Permissions matrix partially inaccurate** — `roles.list` and `roles.get` in `permissions-matrix.ts` require `['platform.permissions.manage', 'org.permissions.manage']`, but `roles.create/update/delete` require only `['platform.permissions.manage']`. The matrix treats them as equivalent gates.
- [ ] **Matrix spec files are all `it.skip` placeholders** — the 5 matrix spec files exist but contain no actual test logic yet (noted "matrix populated in PR 3").
- [ ] **Previous gaps still open from 2026-05-31**: `parseSessionCookie` unit tests, admin nav session-expiry test, admin e2e negative login paths, accept-invite flow, auth-origin helper tests, cross-org access tests, `RequestLoggingMiddleware` spec, `SentryExceptionFilter` integration test, `packages/ui` primitives tests.

## Risky patterns (architectural)

- [ ] **Tenant isolation not enforced in new CRUD surfaces** — `PermissionsService` and `RolesService` both skip `targetOrgId` in `checkPermission` calls. This is the highest-priority fix from today's review. Tracked as **bug-0024** and **bug-0025**.
- [ ] **Schema uniqueness gaps** — Permission `name` is globally unique (should be per-app), and Role `name` has no unique constraint at all. Tracked as **bug-0026** and **bug-0027**.
- [ ] **TOCTOU race conditions in role/permission creation** — both services validate app/permission existence outside the transaction, then create inside it. If the validated resource is deleted between check and creation, the FK constraint fires with an unhelpful error. Consider moving validation inside the transaction.
- [ ] **Hardcoded `take: 50` in permission/role detail views** — `getPermission` and `getRole` fetch at most 50 associated roles/users. The response includes accurate `roleCount`/`userCount` totals but the arrays silently truncate. No pagination or "more" indicator in the admin UI.
- [ ] **Redundant count queries** — `getPermission` and `getRole` both issue separate `count()` queries for roles and users after already fetching the relations. These are additional roundtrips that could be avoided.
- [ ] **Agent worktree submodule artifacts still in git** — tracked as bug-0023 from 2026-05-31, still unfixed.

## Admin UI follow-ups

- [ ] **No loading indicator during delete operations** — `DeleteAlertDialog` doesn't disable buttons or show a spinner while the async delete is in progress. User can double-click.
- [ ] **No toast/success feedback after mutations** — drawers close immediately after create/update/delete with no confirmation message. User has to observe the table refresh to know it worked.
- [ ] **Duplicated pagination component** — both `PermissionsTable` and `RolesTable` have identical inline pagination markup. Extract to a shared `<TablePagination>` component.
- [ ] **`NAME_REGEX` defined locally in multiple files** — the permission name regex is duplicated in `permission-create-drawer.tsx` and `permission-edit-drawer.tsx`. Should be a shared constant.
- [ ] **Server actions have no Sentry integration** — unlike `lib/api.ts` which logs breadcrumbs, the server actions in `permissions/actions.ts` and `roles/actions.ts` don't report mutations to Sentry.
