## Additional items found (not tracked as standalone bugs)

### Authorization pattern inconsistency

The `listUsers` method correctly passes `targetOrgId: -1` when no org filter is specified, forcing platform-level permission. The `listRoles`, `listPermissions`, `getRole`, and `getPermission` methods do NOT follow this pattern. This is a systemic issue beyond bug-0076 -- every listing endpoint should be audited for consistent `targetOrgId` usage.

### Schema constraint gaps

Both `SaRole` (bug-0078) and `SaPermission` (bug-0079) have constraint issues. A database migration should fix both simultaneously to avoid partial states. The migration should:
1. Add `@@unique([appId, name])` to `SaRole`
2. Change `SaPermission` from `name @unique` to `@@unique([appId, name])`
3. Include a data check ensuring no existing duplicates would violate the new constraints

### Rate limiting scope

Bug-0080 covers direct login and invitation endpoints. A broader audit should check whether BetterAuth's built-in rate limiting (if any) covers the `/api/auth/*` routes, and whether the OAuth authorize/token endpoints also need throttling. Consider a global rate limit (e.g., 100 req/min per IP) plus stricter per-endpoint limits for auth-sensitive routes.

### Admin UI form state issues

Multiple admin drawers (role edit, org edit, user create) have minor state management issues where component state doesn't fully reset when the underlying entity changes without a close/reopen cycle. These are UX polish items, not tracked as individual bugs, but worth a systematic cleanup pass across all drawer components.
