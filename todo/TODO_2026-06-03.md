## Risky patterns (architectural)

- [ ] **FastAPI token exposure to JavaScript** (bug-0042) — Demo app stores JWT in `sessionStorage` and passes it via `Authorization` header from client JS. Acceptable for a reference app, but should be documented as insecure for production. Consider a BFF pattern where the FastAPI backend holds the token in a server-side session.
- [ ] **JWKS cache lifespan** — PyJWKClient caches keys for 600 seconds (10 minutes). If the auth server rotates keys, old tokens remain valid for up to 10 minutes on the resource server. Document this or shorten the lifespan.
- [ ] **TOCTOU in `resolveAppScopedIds`** (carried from 2026-06-02) — `resolvePermissionIdsForApp()` and `resolveRoleIdsForApp()` should include `appId` in the `where` clause directly.
- [ ] **Audit log asymmetry** (carried from 2026-06-02) — `assignRole()` logs roleId; `setUserRoles()` logs only count.
- [ ] **Hardcoded `take: 50` in detail views** (carried from 2026-06-01) — `getPermission` and `getRole` silently truncate.
- [ ] **Redundant count queries** (carried from 2026-06-01).

## FastAPI resource server follow-ups

- [ ] **No CORS configuration** — No explicit CORS middleware; API could be called from any origin.
- [ ] **No security headers** — Missing `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Content-Security-Policy`.
- [ ] **No HTTPS enforcement** — No middleware to enforce HTTPS in production. AUTH_SERVER_URL defaults to `http://localhost:3000`.
- [ ] **JWKS client module-level init** — Initialized before settings are fully available; errors deferred to first request.
- [ ] **`/auth/login` is GET, not POST** — Initiating an auth flow via GET makes CSRF easier. Consider POST or add Origin/Referer validation.
- [ ] **httpx timeout hardcoded** — 5-second timeout on token exchange not configurable.
