# bug-0248: Triplicate login password-toggle PRs + PR #306 bundles unrelated changes (scope creep)

**Severity:** Minor (process / PR hygiene — leads to conflicts and wasted review)
**Status:** Open
**Fixed:** false
**Observed in:** open Jules-bot PRs #294, #296, #306 (all still open against `master` @ `a78d4a7`).

## Description

Three separate open Jules-bot "Palette" PRs implement the **same feature** — a show/hide
password toggle on the admin login form:

| PR   | Opened     | Title |
|------|------------|-------|
| #294 | 2026-07-24 | 🎨 Palette: Add delightful show/hide password eye-toggle on Login |
| #296 | 2026-07-27 | 🎨 Palette: Login Password Show/Hide Toggle |
| #306 | 2026-08-05 | 🎨 Palette: Interactive Show/Hide Password Toggle for LoginForm |

All three target the same file (`apps/admin/app/login/login-form.tsx`) and add an
`Eye`/`EyeOff` toggle over the password input. They are mutually redundant: at most one can
merge cleanly; the other two will conflict and must be closed. This is the same
**redundant-Jules-PR** pattern already captured for a different feature in bug-0245.

Separately, PR #306 exhibits **scope creep** — under a "password toggle" title it also bundles
three unrelated changes:

1. **A production auth-security change** — an unfenced `SEEDING=1` session-gate bypass in
   `apps/auth-server/src/auth/auth.config.ts` + `seed/seed.ts` (filed as
   [bug-0247](./bug-0247.md)).
2. **The bug-0243 fix** — `apps/admin/components/__tests__/app-create-drawer.test.tsx` gains
   `requireTwoFactor: false` and `twoFactorTrustDays: null` in the expected create payload.
   Fixing the long-red admin Jest suite is *good*, but burying it inside an unrelated UI PR
   means the fix rides or dies with the toggle feature and is invisible to anyone triaging
   bug-0243 / PR #287.
3. **An unrelated `apps/admin/messages/fr.json` reformat** — whitespace-only reflow of two
   `filter` blocks, adding diff noise.

## Why this is a bug

- **Guaranteed merge conflicts.** #294/#296/#306 edit the same lines of the same component; the
  second and third to merge will not apply.
- **Wasted review + CI cycles.** Three reviews, three CI runs, for one feature.
- **Security change hidden behind a cosmetic title.** The most consequential edit in #306
  (the session-gate bypass) is the least discoverable — the exact conditions under which
  bug-0247 could slip onto `master` unreviewed.
- **Coupling unrelated fixes.** The bug-0243 test fix should stand alone (or land on `master`
  directly) so it isn't blocked by the toggle feature's fate.

## Files / PRs

- `apps/admin/app/login/login-form.tsx` — feature implemented three times (PRs #294, #296, #306)
- `apps/admin/components/__tests__/app-create-drawer.test.tsx` — bug-0243 fix bundled into #306
- `apps/admin/messages/fr.json` — unrelated reformat in #306
- `apps/auth-server/src/auth/auth.config.ts`, `apps/auth-server/src/seed/seed.ts` — auth bypass in #306 (see bug-0247)

## Suggested fix

1. **Pick one password-toggle PR** (newest / cleanest — #306 has the most complete test but
   also the worst scope creep; #296 or a de-scoped #306 is preferable) and **close #294 and the
   other duplicate** with a note pointing at the survivor.
2. **Split PR #306**: keep only the login-form + i18n toggle changes; drop the `fr.json`
   reformat; and extract the `auth.config.ts`/`seed.ts` bypass into its own PR where it can be
   fenced and reviewed (per bug-0247). Land the bug-0243 test fix on its own (or via PR #287).
3. **Add a Jules guardrail / de-dup check** so the bot stops regenerating a feature that already
   has an open PR, and so UI-labeled PRs don't touch `apps/auth-server`.
