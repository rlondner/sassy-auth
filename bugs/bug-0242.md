# bug-0242: Dead i18n key `login.otp.resend`; no "resend code" control is wired in the OTP form

**Severity:** Minor
**Area:** auth / email-OTP UI
**Files:**
- `apps/admin/messages/en.json:472` and `apps/admin/messages/fr.json:472` (`login.otp.resend`)
- `apps/admin/app/login/login-otp-form.tsx:92-98` (renders only "change email", no resend)

Both message catalogs define `login.otp.resend` ("Resend code" / "Renvoyer le code"), but
`login-otp-form.tsx` never references it — the code step offers only a "Use a different
email" button. A user whose emailed code never arrives (spam, delivery delay, or the silent
`skipped_*` paths in `otp-sender.ts`) has **no resend path** short of navigating back and
re-entering their email. The translation key is dead weight that implies a feature the UI
does not provide.

**Fix:** Either wire a "Resend code" button that re-submits `requestOtp` (rate-limit aware —
BetterAuth caps OTP requests at 5/60s), or remove the `login.otp.resend` keys from both
catalogs until the control exists.

**Fixed:** false
