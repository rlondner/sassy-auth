# bug-0237: Raw email logged on every OTP request, contrary to the no-PII-in-logs convention

**Severity:** Minor
**Status:** Open
**Fixed:** false

## Description

`sendSignInOtp` logs the requester's plaintext email on every sign-in-code request,
including for unknown and inactive accounts:

```typescript
logger.info('Sign-in code requested', {
  context: 'auth-otp',
  email,                       // <-- plaintext PII in a shared log stream
  outcome: saUser ? 'skipped_inactive' : 'skipped_unknown',
});
// ...and again on the 'sent' path
logger.info('Sign-in code requested', { context: 'auth-otp', email, outcome: 'sent' });
```

This is inconsistent with the codebase's own established stance on not putting user PII
into shared log/telemetry streams:
- `apps/admin/app/login/actions.ts` deliberately avoids Sentry email breadcrumbs
  ("Do not pass plaintext email to Sentry; the admin layout will identify the user by id").
- The session-create gate (`auth.config.ts`) logs `betterAuthUserId`, **not** the email,
  for exactly this reason.
- bug-0163 established that credentials/identifiers landing in `docker logs` / Sentry /
  Datadog are readable by operators and any log-forwarding pipeline.

Because the log line is emitted for `skipped_unknown` too, anyone with log access can
enumerate which addresses have requested sign-in codes — the same enumeration the neutral
HTTP response was designed to prevent.

## Files

- `apps/auth-server/src/auth/otp-sender.ts:41-47`
- `apps/auth-server/src/auth/otp-sender.ts:64`

## Fix

Drop the email from the structured log, or replace it with a non-reversible identifier
(a hash, or the SaUser id when known). The `outcome` field is the actionable signal;
the raw address adds PII risk without operational value:

```typescript
logger.info('Sign-in code requested', { context: 'auth-otp', outcome });
```
