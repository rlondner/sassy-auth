## Why this was retracted

The original claim was that PR #316 renders Radix `<Tooltip>` in the 5 admin tables with **no
`TooltipProvider`** in scope, so `Tooltip.Root` would throw at render. That claim was based on
`grep -rn TooltipProvider apps/admin` returning zero matches.

That grep was **too narrow**. A `TooltipProvider` **is** in scope for every admin table — it is
supplied transitively by the shared UI package, not by `apps/admin` code:

```
AdminLayout (apps/admin/app/(admin)/layout.tsx)
  └─ AdminShell            (apps/admin/components/admin-shell.tsx)
       └─ SidebarShell     (apps/admin/components/sidebar-shell.tsx)
            └─ <SidebarProvider>                    (packages/ui …/sidebar.tsx:56)
                 └─ <TooltipProvider delayDuration={0}>   (…/sidebar.tsx:140)
                      └─ <SidebarInset>{children}</SidebarInset>   ← the table pages render here
```

`SidebarProvider` wraps its children in `<TooltipProvider>`, so the tables' `<Tooltip>` elements
resolve the provider context correctly. **No render crash occurs.**

## Lesson (do not re-file)

This is the **same false positive** already recorded on the 2026-08-04 run: *"Tooltip without
TooltipProvider crashes all tables" was a FALSE POSITIVE — `SidebarShell → SidebarProvider`
supplies a global `TooltipProvider`.* When checking for a missing React context provider, trace
the provider that shared shell/layout components inject from **other packages** — do not rely on
a text search of the app directory alone.
