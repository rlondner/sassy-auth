# bug-0249: PR #316 renders Radix `<Tooltip>` in 5 admin tables with no `TooltipProvider` — every table page crashes at render

**Severity:** Critical (runtime crash — admin console unusable)
**Status:** Open
**Fixed:** false
**Introduced by:** PR #316 (`palette/accessible-table-tooltips-6451768424245745641`, Jules bot — "🎨 Palette: Standardized Table Copy and Row Action Accessible Tooltips") — created 2026-08-13, not yet on `master`.

## Description

PR #316 wraps the Sqid copy button and the "more actions" (`more_vert`) row-action trigger of
**every** admin table in Radix `<Tooltip>` primitives from `@sassy-auth/ui`:

```tsx
// apps/admin/components/apps-table.tsx (and orgs-, roles-, permissions-, users-table.tsx)
import { /* … */ Tooltip, TooltipTrigger, TooltipContent } from '@sassy-auth/ui'
// …
<Tooltip>
  <TooltipTrigger asChild>
    <button aria-label={copied ? t('common.copied') : t('common.copy')} /* … */>…</button>
  </TooltipTrigger>
  <TooltipContent side="top">{copied ? t('common.copied') : t('common.copy')}</TooltipContent>
</Tooltip>
```

`@sassy-auth/ui`'s `Tooltip` is a direct re-export of `TooltipPrimitive.Root`
(`packages/ui/src/components/ui/tooltip.tsx:10`). In `@radix-ui/react-tooltip@1.2.8`, `Root`
calls `useTooltipProviderContext(...)` on **every render**, and that provider context is created
**without a default value**:

```js
// @radix-ui/react-tooltip/dist/index.js
var [TooltipProviderContextProvider, useTooltipProviderContext] =
  createTooltipContext(PROVIDER_NAME);   // <-- no default context argument
```

```js
// @radix-ui/react-context/dist/index.js — the consumer hook
if (context) return context;
if (defaultContext !== void 0) return defaultContext;
throw new Error(`\`${consumerName}\` must be used within \`${rootComponentName}\``);
```

Because no default is supplied, `Root` **throws** `` `Tooltip` must be used within
`TooltipProvider` `` unless a `<TooltipProvider>` is mounted as an ancestor.

**The admin app has no `TooltipProvider` anywhere, and PR #316 does not add one.**
`grep -rn "TooltipProvider" apps/admin` → **0 matches**; the PR diff adds **0** occurrences of
`TooltipProvider`. This PR is also the *first* code to render a `<Tooltip>` in `apps/admin`
(no prior `<Tooltip` / `TooltipTrigger` usage exists), so nothing else in the tree provides the
context either.

## Why this is a bug

1. **Every admin list page crashes on render.** `AppsTable`, `OrgsTable`, `RolesTable`,
   `PermissionsTable`, and `UsersTable` all render the offending column cells. The moment any of
   these tables renders a row, `Tooltip.Root` throws, taking down the Apps / Orgs / Roles /
   Permissions / Users routes (Next.js error boundary → 500 / error page). This is the core
   admin surface — the console is effectively unusable.
2. **The unit tests can never catch it — they mock the primitive away.** PR #316 updates each
   table test to `jest.mock('@sassy-auth/ui', …)` with `Tooltip: Passthrough`,
   `TooltipContent: Passthrough`, `TooltipTrigger: Trigger`. The real Radix `Root` (the piece
   that reads provider context) never executes under test, so the suite stays green while the
   production render path is broken. The PR body claims "full test coverage"; the coverage is of
   a stub, not of the integration it introduces. (This is the bug-0093 "Jest UI mock fragility"
   pattern recurring — see bug-0251.)
3. **Absent on `master`.** `master` (`a78d4a7`) renders these copy/action buttons as plain
   `<button>` elements with no Radix Tooltip, so the crash is net-new to this PR.

## Files

- `apps/admin/components/apps-table.tsx`, `orgs-table.tsx`, `roles-table.tsx`,
  `permissions-table.tsx`, `users-table.tsx` — add `<Tooltip>` with no provider in scope
- `packages/ui/src/components/ui/tooltip.tsx:8-10` — `Tooltip = TooltipPrimitive.Root`,
  `TooltipProvider = TooltipPrimitive.Provider` (the required provider is exported but unused)
- `apps/admin/app/(admin)/layout.tsx` / `apps/admin/components/admin-shell.tsx` — where a
  single app-level `<TooltipProvider>` belongs

## Suggested fix

Mount **one** `TooltipProvider` high in the admin tree so every table inherits it. The cleanest
spot is around `AdminShell` (or the root `apps/admin/app/layout.tsx`):

```tsx
import { TooltipProvider } from '@sassy-auth/ui'

// in AdminShell (client component) or app/layout.tsx
<TooltipProvider delayDuration={200}>
  {/* existing shell / children */}
</TooltipProvider>
```

Then **de-mock the primitive in at least one test** (render the real `TooltipProvider` +
`Tooltip` via `@testing-library/react`) so a missing provider fails CI instead of shipping
green. A single integration test that renders one real table inside a real `TooltipProvider` and
asserts the copy button is reachable would have caught this.

## Verification

- Confirmed by reading the installed Radix source: `createTooltipContext(PROVIDER_NAME)` (no
  default) + the react-context consumer's `throw new Error(... must be used within ...)` branch.
- Confirmed `apps/admin` contains **zero** `TooltipProvider` references and no pre-existing
  `<Tooltip>` usage; PR #316 adds none.
- **To reproduce locally:** check out the PR branch, run the admin app
  (`pnpm --filter @sassy-auth/admin dev`), and open `/apps` (or any table route). Expect the
  React error `` `Tooltip` must be used within `TooltipProvider` `` in the console / error
  overlay. (Best-case alternative outcome: if a future Radix patch tolerates a missing provider,
  it renders with default delays — but shadcn/Radix both document the provider as required, and
  the fix above is correct either way.)
