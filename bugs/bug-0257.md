So PR #328 is a **superset of #316's admin-UI half and of #324 entirely**, plus new riders. All
three PRs edit the identical `<button aria-label=…>` lines in `apps-table.tsx`, `orgs-table.tsx`,
`permissions-table.tsx`, `roles-table.tsx`, `users-table.tsx` and the same two message files →
**any two merging will conflict on every one of those hunks.** [bug-0254](./bug-0254.md) already
flagged the #324↔#316 collision; #328 makes it a **three-way** collision and drags in more.

### The bundled riders are not cosmetic

- **`apps/admin/app/login/actions.ts`** is rewritten so `forwardSessionCookie` returns
  `{ ok, sessionToken }` and the freshly-minted session token is threaded explicitly into the
  `get-session` / `two-factor-status` fetches (instead of re-reading the Next.js cookie store).
  This is a plausible robustness improvement to the **admin login server action**, but it ships
  with **no new test** for the changed cookie-forwarding path, under a PR titled "row action
  tooltips."
- **`apps/auth-server/src/auth/auth.config.ts`** — `autoSignIn: false` (see
  [bug-0256](./bug-0256.md)).
- **`apps/admin-e2e/auth-state.setup.ts`** now waits for `/login/two-factor-prompt` and clicks
  "Skip for now" — a behavioral admission that seeded admins hit the 2FA prompt (the *correct*
  direction, opposite to [bug-0250](./bug-0250.md)'s seed suppression), but again unrelated to the
  PR's stated scope.

## Why this is a bug (and not just noise)

1. **Three mutually-conflicting open PRs** (#316/#324/#328) now cover the same 5-table +
   2-message-file surface.
2. **Reviewer confusion / wasted review** — three PRs claim to "localize/accessible-ify table row
   actions"; #328 is the largest and hardest to review because it also changes auth config, the
   admin login action, e2e setup, and the global test harness.
3. **A real login-flow change with no test**, hidden under a UI title (same class as
   [bug-0251](./bug-0251.md)).

## Suggested fix

- **Pick one carrier for the row-action a11y/i18n work** — prefer the smallest clean one (#324 has
  no auth/seed payload; see [bug-0254](./bug-0254.md)) and **close #328's duplicate UI half**.
- **Split #328's genuine non-UI improvements** (the `login/actions.ts` cookie-threading fix; the
  e2e 2FA-prompt handling) into their **own PRs with tests**, off `master`.
- **Strip `apps/auth-server/**` from #328** ([bug-0256](./bug-0256.md)).
- **Add the Jules guardrail**: skip generating a PR whose file+line set is already covered by an
  open `palette/*` PR (cf. [bug-0248](./bug-0248.md), [bug-0254](./bug-0254.md)).
