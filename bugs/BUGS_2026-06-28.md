### bug-0117 :large_blue_circle: Minor — user-create-drawer hardcoded English validation messages

**File:** `apps/admin/components/user-create-drawer.tsx:86-92`

**Description:** The `validate()` function uses hardcoded English strings `'Required'` (lines 88-92) and `'Invalid email'` (line 91) for client-side validation errors. All 4 other create drawers (`app-create-drawer.tsx`, `org-create-drawer.tsx`, `permission-create-drawer.tsx`, `role-create-drawer.tsx`) use i18n translation keys via `setErrorKey()` or translated error messages. Additionally, the org picker at line 199 uses `placeholder="Select org"` — another hardcoded English string instead of an i18n key.

**Impact:** Validation error messages and the org selector placeholder display in English regardless of the user's locale setting (e.g. French users see "Required" and "Select org" instead of translated strings). Breaks the i18n contract established by all other drawers.

**Fix:** Replace hardcoded strings with i18n keys: `e.firstName = t('users.errors.firstNameRequired')`, etc. Replace `placeholder="Select org"` with `placeholder={t('users.fields.selectOrg')}`. Add corresponding keys to `messages/en.json` and `messages/fr.json`.

### bug-0120 :yellow_circle: Warning — `DeleteAlertDialog` error div missing `role="alert"` (E2E blind spot)

**File:** `apps/admin/components/delete-alert-dialog.tsx:50`

**Description:** The error `<div>` at line 50 renders without `role="alert"`. All 10 other CRUD drawers (app-create, app-edit, org-create, org-edit, permission-create, permission-edit, role-create, role-edit, user-create, user-view) use `<p role="alert">` for inline error messages. The E2E `raceSuccessOrError` helper scopes error detection to `errorScope.getByRole('alert')` inside `[role="alertdialog"]`. Because the delete dialog's error container lacks this role, server-side delete failures (e.g. foreign-key constraint violations) are invisible to E2E tests — both the success and error promises time out to `null`, and the test silently passes.

**Impact:** All 5 delete E2E flows (`deleteApp`, `deleteOrg`, `deletePermission`, `deleteRole`, `deleteUser`) cannot detect server-side errors. A broken delete API produces false-passing tests.

**Fix:** Add `role="alert"` to the error `<div>` at line 50: `<div role="alert" className="...">`.

**Fixed:** false

### bug-0121 :yellow_circle: Warning — `OrgsService.listOrgs`/`getOrg` cross-tenant org listing via `org.users.manage`

**File:** `apps/auth-server/src/orgs/orgs.service.ts:49-53` (listOrgs) and `76-80` (getOrg)

**Description:** Both `listOrgs` and `getOrg` call `checkPermission(callerBaId, ['platform.orgs.manage', 'platform.users.manage', 'org.users.manage'])` without passing `targetOrgId`. The `checkPermission` helper unconditionally grants access when `options.targetOrgId` is undefined for non-platform permissions. A user holding only `org.users.manage` in Org A can list and view all orgs across all tenants. This is the same class of bug as bug-0076 (which covers roles/permissions) but applied to the orgs service.

**Impact:** A tenant-scoped org admin can enumerate every organization name and user count across the entire platform, violating tenant isolation for org metadata.

**Fix:** Either pass `targetOrgId: -1` when called without an org filter (forcing platform-level permission for cross-tenant listing), or remove `org.users.manage` from the orgs read gates since the admin page only needs to populate its own org dropdown (which `platform.users.manage` already covers).

**Fixed:** false

### bug-0122 :yellow_circle: Warning — Double `stripTrailingSlash` causes JWT `iss` / discovery `issuer` divergence

**File:** `apps/auth-server/src/token/oauth-metadata.ts:33-36` and `55-58`

**Description:** `resolveIssuer()` (line 35) applies `stripTrailingSlash` once. `buildOAuthAuthorizationServerMetadata()` (line 58) applies `stripTrailingSlash` a second time on the issuer parameter. `TokenService.issueJwt()` uses `resolveIssuer()` directly (one strip). When `BETTER_AUTH_URL` ends with multiple slashes (e.g. `https://auth.example.com//`), `resolveIssuer()` returns `https://auth.example.com/` (one slash stripped), JWT `iss` = `https://auth.example.com/`, but the discovery `issuer` = `https://auth.example.com` (second strip). RFC 8414 Section 3 requires exact string comparison between JWT `iss` and discovery `issuer`.

**Impact:** OAuth clients performing issuer verification reject JWTs when `BETTER_AUTH_URL` has multiple trailing slashes, silently breaking all token-based authentication.

**Fix:** Make `stripTrailingSlash` strip all trailing slashes: `s.replace(/\/+$/, '')`, or remove the redundant `stripTrailingSlash` call inside `buildOAuthAuthorizationServerMetadata`.

**Fixed:** false

### bug-0123 :yellow_circle: Warning — `role-view-drawer.tsx` shows Edit/Delete buttons to read-only users

**File:** `apps/admin/components/role-view-drawer.tsx:58-69`

**Description:** `RoleViewDrawer` always renders Edit and Delete buttons regardless of user permissions. All other entity view drawers gate their action buttons behind an immutability check (apps/orgs check `isPlatform`, permissions check `isImmutable`). The parent `RolesTable` uses a `canWrite` prop to hide dropdown actions but does NOT forward it to `RoleViewDrawer`. A read-only user who clicks a role row sees Edit/Delete buttons that will error when used.

**Impact:** Read-only org-scoped admins see Edit/Delete buttons in the role view drawer that produce confusing errors when clicked.

**Fix:** Add a `canWrite` prop to `RoleViewDrawer` and wrap the Edit/Delete `ButtonGroup` in `{canWrite && (...)}`.

### bug-0125 :large_blue_circle: Minor — `deleteRole` P2003 error user count can be stale

**File:** `apps/auth-server/src/roles/roles.service.ts:231-234`

**Description:** When `deleteRole` catches a P2003 (foreign-key constraint from `saUserRole`), it counts users outside the failed transaction: `const userCount = await prisma.saUserRole.count(...)`. Between the transaction failure and the count query, concurrent requests could remove user-role assignments, causing the error message to report an inaccurate count (e.g. "Role is assigned to 0 users" despite the deletion being blocked).

**Impact:** Misleading error message in a race condition scenario. No data corruption — the deletion correctly fails.

**Fix:** Report the constraint violation without a count: `throw new ConflictException('Role is still assigned to users')`.

**Fixed:** false

## Scan details

The uncommitted working tree was re-scanned with deeper multi-agent analysis across auth-server, admin UI, and E2E tests.

1. **Auth-server token/discovery** -- `resolveIssuer()` DRY refactor centralizes issuer resolution between DiscoveryController and TokenService. Double `stripTrailingSlash` bug found (bug-0122): JWT `iss` and discovery `issuer` can diverge when `BETTER_AUTH_URL` has multiple trailing slashes. bug-0115 (missing URL validation) remains open.

2. **Auth-server orgs service** -- `checkPermission` call in `listOrgs`/`getOrg` includes `org.users.manage` without `targetOrgId`, allowing cross-tenant org enumeration (bug-0121). Same class as bug-0076 (roles/permissions) but newly identified for the orgs service.

3. **Auth-server roles service** -- `platform.users.manage` added to `listRoles`/`getRole` permission gates. Tests and permissions matrix updated consistently. `deleteRole` P2003 error message user count can be stale in a race (bug-0125).

4. **Admin UI create drawers** -- `user-create-drawer.tsx` deviates from the pattern established by all 4 other create drawers: hardcoded English validation strings and "Select org" placeholder (bug-0117) and missing `<form>` wrapper (bug-0118).

5. **Admin UI view drawers** -- `role-view-drawer.tsx` shows Edit/Delete buttons to read-only users with no `canWrite` guard (bug-0123). `user-view-drawer.tsx` has hardcoded "Loading…" English string (bug-0124).

6. **Admin UI table action buttons** -- `users-table.tsx` is the only table missing `aria-label` on the dropdown trigger button (bug-0119).

7. **Admin UI shared components** -- `DeleteAlertDialog` error `<div>` missing `role="alert"`, making E2E delete error detection blind across all 5 delete flows (bug-0120).

8. **E2E page objects** -- `raceSuccessOrError` scoping fix applied identically across all 5 page objects. OAuth route stub correctly narrowed. The scoping fix works correctly but is blind to `DeleteAlertDialog` errors due to bug-0120.
