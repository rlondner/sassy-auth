# bug-0240: `TWO_FACTOR_TRUST_DAYS` is an operative config var but is undocumented in `.env.example`

**Severity:** Minor
**Area:** 2FA / config docs
**Files:**
- `apps/admin/lib/two-factor-prompt.ts:23-28` (`getSystemTrustDaysClient` reads `process.env['TWO_FACTOR_TRUST_DAYS']`)
- `.env.example` (missing the key; only `PLATFORM_REQUIRE_2FA` is listed under "2FA / Security")

The 2FA "don't re-prompt for N days" window is configurable via `TWO_FACTOR_TRUST_DAYS`
(consumed at `apps/admin/app/login/actions.ts:213,330` and
`apps/admin/app/login/two-factor/page.tsx:14`). The value materially changes how often
users are asked to set up / re-confirm 2FA, yet it is **absent from `.env.example`** and
from the README Environment-Variables tables — only the sibling `PLATFORM_REQUIRE_2FA` was
added when the 2FA feature landed. The code silently falls back to `14` for any
missing/invalid value, so a misconfigured deployment looks healthy while ignoring intent.

**Fix:** Add `TWO_FACTOR_TRUST_DAYS` (with the "default 14" note) to `.env.example` under
the existing "2FA / Security" block, and to the README Environment-Variables section.

**Fixed:** false
