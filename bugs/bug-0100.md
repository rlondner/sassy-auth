# bug-0100: Migration new permissions left with placeholder publicId until next seed

**Severity:** Warning
**File:** `packages/db/prisma/migrations/20260618220100_.../migration.sql` (lines 14-24)

The two newly inserted permissions (`platform.roles.manage` and `org.roles.manage`) are created with placeholder `publicId` values (`'pending-roles-manage'` and `'pending-org-roles-manage'`). These are left as-is unless a subsequent seed run is performed.

**Fix:** Add an UPDATE statement in the migration that computes the real sqid from the generated `id`, or document the seed-after-migrate requirement.

**Tests needed:** After running the migration without seed, call `GET /api/permissions` and verify no placeholder `publicId` values are returned.
