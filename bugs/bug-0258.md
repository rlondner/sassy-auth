# bug-0258: PR #328 globally stubs `@sassy-auth/ui` Tooltip primitives in `jest.setup.ts` → the entire admin Jest suite is blind to real tooltip behavior

**Severity:** Low (test-quality / coverage erosion)
**Status:** Open
**Fixed:** false
**Introduced by:** PR **#328** (`jules-16680163062728024582-5c7c94b2`, Jules bot) — opened
2026-08-16 07:40 UTC.

## Description

PR #328 adds a **global** module mock to `apps/admin/jest.setup.ts` that replaces the real
`@sassy-auth/ui` tooltip primitives with passthrough stubs for **every** admin test:

```ts
jest.mock('@sassy-auth/ui', () => {
  const React = require('react')
  const actual = jest.requireActual('@sassy-auth/ui')
  return {
    ...actual,
    TooltipProvider: ({ children }) => <>{children}</>,
    Tooltip: ({ children }) => <>{children}</>,
    TooltipTrigger: React.forwardRef(({ children, asChild, ...props }, ref) =>
      asChild && React.isValidElement(children)
        ? React.cloneElement(children, { ...props, ref })
        : <button {...props} ref={ref}>{children}</button>),
    TooltipContent: ({ children }) => <div role="tooltip">{children}</div>,
  }
})
```

Because `jest.setup.ts` is loaded for the whole `apps/admin` Jest project, **no admin unit test
ever renders the real Radix Tooltip**. The suite therefore cannot catch:

- A **missing `TooltipProvider`** in the component tree (the real `Tooltip` throws without one).
- **`asChild` ref-forwarding / composition** defects on the trigger — the exact class of issue
  filed as [bug-0252](./bug-0252.md) (nested double-`asChild` on the row-action trigger). The stub's
  hand-rolled `cloneElement` masks whatever the real Slot stack would do.
- Any regression in the shared `Tooltip*` primitives from `packages/ui`.

This is the escalation of [bug-0251](./bug-0251.md), which flagged #316 mocking the Tooltip
primitive to passthroughs **per test file**. #328 promotes that same blind spot to a **global,
always-on** stub, so it silently applies to table tests that don't even use tooltips.

## Why this is a bug (and not just noise)

- A component test that stubs out the very primitive whose accessibility behavior it purports to
  verify proves nothing about the shipped UI. The added row-action-tooltip assertions in the 5
  table suites pass against the stub, not against Radix.
- The mask specifically hides the **double-`asChild`** concern (bug-0252) and the historical
  **missing-provider** false-alarm class (bug-0249) — i.e. exactly the failure modes reviewers keep
  hand-tracing because the tests can't.

## Files

- `apps/admin/jest.setup.ts` — global `jest.mock('@sassy-auth/ui', …)` Tooltip stubs.

## Suggested fix

- **Do not globally stub the design-system tooltip.** Prefer wrapping the component-under-test in
  the **real** `TooltipProvider` inside each render helper (or a shared `renderWithProviders`), so
  tests exercise the actual primitive and would fail on a missing provider.
- If a stub is unavoidable for unrelated suites, **scope it to the specific test files** that need
  it rather than `jest.setup.ts`, and add at least one test that renders the real `Tooltip` +
  `TooltipTrigger asChild` to guard the composition (covers bug-0252).

## Verification
