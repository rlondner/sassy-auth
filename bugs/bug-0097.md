# bug-0097: removeRole has no escalation guard, asymmetric with assignRole

**Severity:** Warning
**File:** `apps/auth-server/src/users/users.service.ts` (lines 369-386)

`assignRole` applies `assertCallerCanGrantSystemPerms` to prevent privilege escalation. `removeRole` does not. An `org.users.manage` caller who cannot grant a system permission can still remove it via `removeRole`.

**Fix:** Add the same `assertCallerCanGrantSystemPerms` check to `removeRole`, passing the role's permissions.

**Tests needed:** Unit test: org admin attempts to remove a role containing a system permission they don't hold — should throw.
