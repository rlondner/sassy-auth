# bug-0241: OTP request-step error renders an untranslated raw key ("invalidCredentials")

**Severity:** Minor
**Area:** auth / email-OTP UI
**Files:**
- `apps/admin/app/login/actions.ts:180` (`requestOtp` returns `{ error: 'invalidCredentials' }`)
- `apps/admin/app/login/login-otp-form.tsx:38-39` (`errKey` allowlist)

`requestOtp` returns `{ error: 'invalidCredentials' }` when the email field is empty, but
the OTP form's `errKey` helper only maps `invalidCode | inactive | serverUnavailable`
through `t()`. Any other value — including `invalidCredentials` — is rendered **verbatim**,
so the user would see the literal string `invalidCredentials` instead of a localized
message. Separately, `"Invalid email or password."` is the wrong copy for a **passwordless**
flow (there is no password on this screen).

The browser-level `required` attribute usually prevents the empty-email trigger, but a
server action can still be invoked directly, and the `errKey` fall-through is a latent
defect for any future error value `requestOtp` might return.

**Fix:** Introduce a passwordless-appropriate key (e.g. `error.emailRequired`) and include
it — plus any other value `requestOtp` can return — in the `errKey` allowlist so no raw key
reaches the DOM.

**Fixed:** false
