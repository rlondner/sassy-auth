## New bugs (3)

### bug-0236 :yellow_circle: Warning — OTP active-user gate uses case-sensitive email lookup while the store lowercases

**Files:**
- `apps/auth-server/src/auth/otp-sender.ts:36-47`
- `apps/auth-server/src/auth/otp-test-store.ts:10-16`

**Description:** `sendSignInOtp` gates code delivery on a SaUser lookup that uses the raw,
un-normalized `email` (`where: { betterAuthUser: { email } }`). PostgreSQL equality is
case-sensitive, so `User@Example.com` does not match a stored `user@example.com`. The same
function's test-store write *does* normalize (`otpTestStore.set` → `email.toLowerCase()`),
so the two paths disagree. For a mixed-case entry belonging to an active user, the gate
returns `null`, the request is logged `skipped_unknown`, and **no sign-in code is sent** —
a silent, hard-to-diagnose failure (the UI stays neutral by design).

**Impact:** Active users whose client sends a differently-cased email cannot complete
passwordless sign-in; failure is invisible to the user and to support.

**Fix:** Normalize once (`email.trim().toLowerCase()`) and use it for both the DB gate and
the store write; add a mixed-case regression test (current spec only uses lowercase).

**Fixed:** false

### bug-0237 :large_blue_circle: Minor — Raw email logged on every OTP request, contrary to the no-PII-in-logs convention

**Files:**
- `apps/auth-server/src/auth/otp-sender.ts:41-47`
- `apps/auth-server/src/auth/otp-sender.ts:64`

**Description:** `sendSignInOtp` logs the plaintext `email` on every request, including the
`skipped_unknown` path. This contradicts the codebase's own stance elsewhere: the admin
login action avoids Sentry email breadcrumbs ("Do not pass plaintext email to Sentry"),
the session-create gate logs `betterAuthUserId` not the email, and bug-0163 established
that identifiers in shared log streams (docker/Sentry/Datadog) are a leak vector. Logging
the address for `skipped_unknown` also re-introduces the enumeration the neutral HTTP
response was meant to prevent — for anyone with log access.

**Impact:** PII in logs; log-based enumeration of who requested sign-in codes.

**Fix:** Remove `email` from the structured log (keep `outcome`), or substitute a hash /
the SaUser id when known.

**Fixed:** false

### bug-0238 :large_blue_circle: Minor — `_to_delete/` accumulates tracked files in git history with no policy

**Files:**
- `_to_delete/CR_2026-07-09.md` (tracked)
- `.gitignore` (missing `_to_delete/` entry)

**Description:** `_to_delete/` holds files staged for eventual removal, but they are
committed and tracked (`git ls-files _to_delete/` → `_to_delete/CR_2026-07-09.md`), and
the directory is not gitignored. Every file dropped there is recorded permanently, growing
the repo and muddying history. Flagged as an open follow-up in both `CR_2026-07-09.md` and
`CR_2026-07-12.md`.

**Impact:** Repo hygiene / history noise; unbounded growth of throwaway content.

**Fix:** Either add `_to_delete/` to `.gitignore` + `git rm --cached -r _to_delete/`, or
`git rm -r _to_delete/` outright. Document the chosen policy.

**Fixed:** false
