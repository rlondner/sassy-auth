## 🟡 bug-0022 — `decodeURIComponent` in `parseSessionCookie` can throw `URIError`

**Fixed:** false
**Severity:** Warning
**File:** `apps/admin/app/login/actions.ts:42`

**Description.** Commit `30de696` fixed the double-encoding logout bug by adding `decodeURIComponent(namePair.slice(eq + 1))` to decode the session cookie value. However, `decodeURIComponent` throws a `URIError` if the input contains a `%` not followed by two hex digits (e.g., `%ZZ`, `%`, `%G1`). Since there is no try-catch around this call, a malformed cookie value from the auth server would crash the entire `signIn` Server Action with an unhandled exception (500 error), instead of returning a graceful error to the login form.

While BetterAuth session tokens are typically well-formed base64 (where only `=`, `+`, `/` are percent-encoded as `%3D`, `%2B`, `%2F`), this is a defensive coding gap: any upstream change to the token format, or a buggy reverse proxy rewriting `Set-Cookie` headers, could trigger it.

**Fix sketch.** Wrap in try-catch:
```ts
let value: string
try {
  value = decodeURIComponent(namePair.slice(eq + 1))
} catch {
  value = namePair.slice(eq + 1)
}
```
This falls back to the raw (un-decoded) value on malformed input, which is the pre-fix behavior and still allows the session to work if the value happens to not need decoding.

**Tests needed.** Unit test for `parseSessionCookie` with a malformed percent-encoded value (e.g., `better-auth.session_token=abc%ZZdef; Path=/`) asserting it returns a result (not throws).
