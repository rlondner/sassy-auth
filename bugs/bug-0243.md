# bug-0243: `app-create-drawer` "creates app" unit test is stale vs the 2FA per-app create payload — fails on `master`

**Severity:** Warning
**Area:** admin / tests (2FA per-app)
**Files:**
- `apps/admin/components/__tests__/app-create-drawer.test.tsx:33-39` (assertion)
- `apps/admin/components/app-create-drawer.tsx:57-61` (submit payload)

When per-app 2FA enforcement (feature "2b") landed on `master` (merge `a78d4a7`, 2026-07-15),
`AppCreateDrawer` began submitting two new fields on create:

```ts
await createAppAction({
  name: name.trim(),
  url: url.trim(),
  callbackUrl: callbackUrl.trim() || null,
  twoFactorTrustDays,   // null by default
  requireTwoFactor,     // false by default
})
```

but the "creates app" unit test was **not** updated and still asserts:

```ts
expect(actions.createAppAction).toHaveBeenCalledWith({
  name: 'X',
  url: 'https://x.example',
  callbackUrl: null,
})
```

`toHaveBeenCalledWith` is an **exact** match, so the actual call
(`{…, twoFactorTrustDays: null, requireTwoFactor: false}`) no longer matches and the test
**fails on `master`**. This is confirmed independently by two Jules PRs — #285 (`c55d026`)
and #286 (`7c4e605`) — both of which had to add the missing `requireTwoFactor: false` /
`twoFactorTrustDays: null` lines to get their suites green (see bug-0245).

**Impact:** The admin unit suite is red on `master`; the 2b feature merged without its
component test being updated, indicating the pre-merge test gate did not run (or was not
green) for this file. Masks future regressions in the create-app payload.

**Fix:** Update the assertion to include `twoFactorTrustDays: null` and
`requireTwoFactor: false` (the create-drawer defaults). Then investigate why a merge to
`master` was allowed with a failing unit test — add/repair the CI gate for
`apps/admin` Jest suites.

**Tests needed:** The fix *is* the test; additionally ensure the admin Jest suite runs in
CI on every PR targeting `master`.

**Fixed:** false
