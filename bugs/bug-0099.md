# bug-0099: Migration literal publicId strings violate unique constraint on re-run

**Severity:** Critical
**File:** `packages/db/prisma/migrations/20260618220100_.../migration.sql` (lines 14-24)

The migration INSERTs two new `SaPermission` rows using literal `publicId` values. The `NOT EXISTS` guard checks by `name`, not by `publicId`. A partial first run followed by re-application hits the `SaPermission_publicId_key` unique constraint.

**Fix:** Add `ON CONFLICT ("name") DO NOTHING` or `ON CONFLICT ("publicId") DO NOTHING` to the INSERT statements.

**Tests needed:** Run the migration twice against a database where the first run partially completed.
