### bug-0246 — `SEED_RUNNING` env var bypasses the production session-activation gate

- **Severity:** Warning (security hardening / defense-in-depth)
- **Fixed:** false
- **File:** `apps/auth-server/src/auth/auth.config.ts` (session `create.before` hook), set by
  `apps/auth-server/src/seed/seed.ts:1`
- **What:** PR #303 adds `if (process.env.SEED_RUNNING === "true") return;` to the BetterAuth
  session-create gate, skipping `evaluateSessionGate` whenever that variable is `"true"`. There
  is no `NODE_ENV` fence, so any environment that exports it silently disables the account-status
  enforcement hardened in **bug-0074** (inactive/pending/suspended users could mint sessions).
  No log, no test, absent from `.env.example`/README.
- **Detail + fix:** [bug-0246.md](./bug-0246.md). Filed on branch `bugs/bug-0246`, **PR #304**.

## Verified false positive (not filed)

- **Radix `<Tooltip>` without a `TooltipProvider`.** PR #303 introduces the first Radix
  `<Tooltip>` usages in the five admin tables (master used the native `title=` attribute).
  `@radix-ui/react-tooltip@1.2.8` `Tooltip.Root` throws `` `Tooltip` must be used within
  `TooltipProvider` `` when no provider ancestor exists, and the PR adds `TooltipProvider` only
  as a **test-mock passthrough** — never to a real component. This *looked* like a guaranteed
  runtime crash of every admin table. It is **not**: `SidebarShell → SidebarProvider` wraps
  `{children}` in `<TooltipProvider delayDuration={0}>` (`packages/ui/src/components/ui/sidebar.tsx:91`),
  and the tables render inside `SidebarInset`, so a global provider is present. No bug. (The
  test mocks do hide this dependency, though — see TODO_2026-08-04, test-coverage item.)
