# bug-0251: PR #316 scope creep — a cosmetic "table tooltips" PR silently bundles auth-config + seed changes, and mocks away the primitive it introduces

**Severity:** Warning (process / review integrity)
**Status:** Open
**Fixed:** false
**Introduced by:** PR #316 (`palette/accessible-table-tooltips-6451768424245745641`, Jules bot — "🎨 Palette: Standardized Table Copy and Row Action Accessible Tooltips") — created 2026-08-13.

## Description

PR #316 is titled and framed as a **table tooltip / accessibility** change. Its actual diff
(18 files, +163 / −79) reaches well outside that scope:

- `apps/auth-server/src/auth/auth.config.ts` — `+ autoSignIn: false` on the BetterAuth
  `emailAndPassword` block (a change to production auth/registration behavior).
- `apps/auth-server/src/seed/seed.ts`, `demo-multitenant.ts`, `demo-resource-server.ts` —
  `+ twoFactorPromptedAt: new Date()` in each (the **Critical** 2FA-prompt-suppression
  regression filed as [bug-0250](./bug-0250.md)).
- The five table components + their tests carry the actual tooltip work.

None of the four `apps/auth-server` edits is mentioned in the PR title, and only the tooltip work
is described in the body. A reviewer scanning "table tooltips" has no cue that the PR mutates the
auth config and every seed script.

## Why this is a bug

1. **A UI-labeled PR must not silently carry auth-server and seed changes.** This is the exact
   anti-pattern already filed as [bug-0247](./bug-0247.md) / [bug-0248](./bug-0248.md) (PR #306
   bundling an unfenced session-gate bypass under a "password toggle" title). Bundling
   security-relevant edits under a cosmetic heading defeats focused review — it is precisely how
   [bug-0250](./bug-0250.md) slipped in unremarked.
2. **The tests mock away the very primitive the PR introduces.** Each updated table test does
   `jest.mock('@sassy-auth/ui', …)` with `Tooltip: Passthrough`, `TooltipContent: Passthrough`,
   `TooltipTrigger: Trigger`. The real Radix `Tooltip.Root` never runs under test, so the suite
   passes green while the production render path throws for lack of a `TooltipProvider`
   ([bug-0249](./bug-0249.md)). "Table Unit Tests Updated … full test coverage" (PR body) is
   coverage of a stub, not of the integration. This is the bug-0093 "Jest UI mock fragility"
   pattern recurring.
3. **Duplicate / conflicting changes across open PRs.** `autoSignIn: false` and the
   `twoFactorPromptedAt` seed writes are *also* present in PR #315, and the FormField/validation
   work overlaps PR #314. Three open Jules PRs (#314/#315/#316) touch the same
   `auth.config.ts` + seed + admin-drawer/table surface; whichever merges second will conflict,
   and the duplicated auth/seed edits will need manual de-duplication.

## Files

- `apps/auth-server/src/auth/auth.config.ts` (bundled `autoSignIn: false`)
- `apps/auth-server/src/seed/{seed,demo-multitenant,demo-resource-server}.ts` (bundled 2FA
  suppression — bug-0250)
- `apps/admin/components/__tests__/{apps,orgs,roles,permissions,users}-table.test.tsx`
  (`Tooltip: Passthrough` mocks)

## Suggested fix

- **Split PR #316** into (a) the table tooltip/a11y change (with a real `TooltipProvider` and a
  de-mocked integration test — see bug-0249) and (b) any intentional auth/seed change, reviewed
  on its own merits. Drop the `twoFactorPromptedAt` seed writes entirely (bug-0250).
- **De-duplicate against #315/#314** before anything merges: pick one PR to carry
  `autoSignIn: false`, and resolve the overlapping validation/drawer work so the others rebase
  cleanly or close.
- **Add a Jules guardrail:** forbid `palette/*` (UI-labeled) PRs from modifying
  `apps/auth-server/**`, and require at least one test that renders the real UI primitive a PR
  introduces (no full-mock-only coverage for newly added `@sassy-auth/ui` components).

## Notes

- Related: bug-0249 (the Tooltip provider crash this scope creep + mocking hid), bug-0250 (the
  bundled seed regression), bug-0247 / bug-0248 (same scope-creep pattern in PR #306), bug-0093
  (prior Jest UI mock fragility).
- `autoSignIn: false` itself is defensible hardening (prevents implicit session creation on
  registration) — the issue is that it, and the seed regression, ride in under a tooltip title
  rather than being reviewed as auth changes.
