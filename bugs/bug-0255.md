# bug-0255: PR #324 localizes the row-action `aria-label` in all 5 admin tables but adds a test assertion for only 1 (apps-table); the other 4 table suites are left unverified

**Severity:** Low (test-coverage asymmetry)
**Status:** Open
**Fixed:** false
**Introduced by:** PR **#324** (`palette/localize-table-row-actions-aria-label-14231760063474182685`, Jules bot), 2026-08-15.

## Description

PR #324 replaces `aria-label="more actions"` → `aria-label={t('common.moreActions')}` in **five**
components — `apps-table.tsx`, `orgs-table.tsx`, `permissions-table.tsx`, `roles-table.tsx`,
`users-table.tsx` — but the only test change is in `apps/admin/components/__tests__/apps-table.test.tsx`:

```tsx
it('renders rows from initial data with localized more actions ARIA label', () => {
  render(withIntl(<AppsTable initial={initial} />))
  ...
  const moreActionsButtons = screen.getAllByRole('button', { name: en.common.moreActions })
  expect(moreActionsButtons).toHaveLength(2)
})
```

The sibling suites `orgs-table.test.tsx`, `permissions-table.test.tsx`, `roles-table.test.tsx`, and
`users-table.test.tsx` all exist in the same directory and were **not** updated. Four of the five
changed components therefore have no assertion that the row-action button exposes the localized
accessible name.

## Why this is a bug

1. **Coverage asymmetry.** A regression that reverted the label (or mis-keyed it to a missing
   translation, rendering the raw `common.moreActions` key) in any of the four un-asserted tables
   would pass CI. The change was applied uniformly to five files; the verification was not.
2. **The one test that exists proves the pattern is cheap.** The apps-table assertion is three
   lines and reuses the shared `withIntl`/`en` fixtures already present in every sibling suite, so
   parity is low-effort.
3. **Consistency with the codebase's own convention** — each table has a dedicated `*-table.test.tsx`;
   leaving four of them silent on a change that touched all five is an inconsistency, not a
   deliberate scoping decision.

## Files

- `apps/admin/components/__tests__/apps-table.test.tsx` — the sole updated suite (has the assertion)
- `apps/admin/components/__tests__/orgs-table.test.tsx`,
  `permissions-table.test.tsx`, `roles-table.test.tsx`, `users-table.test.tsx` — changed component,
  **no** `common.moreActions` assertion added

## Suggested fix

Add the same `getAllByRole('button', { name: en.common.moreActions })` assertion to the four sibling
suites (matching each table's expected row count from its `initial`/`users` fixture). Alternatively,
if the row-action button is the shared surface, factor a single parametrized test over the five
tables.

## Verification

- `gh pr view 324 --json files` lists five `*-table.tsx` component edits but only
  `__tests__/apps-table.test.tsx` among the test files.
- The four sibling test files exist on the tree (`ls apps/admin/components/__tests__/`) and were not
  in the PR's file set.
