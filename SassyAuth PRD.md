# SassyAuth Product Requirements Document

SassyAuth is a multitenant authentication/authorization server and user/role management app for modern SaaS applications  
Is is based on BetterAuth for easy integration  
It has the following concepts:

- Users: defines the users who can manage SassyAuth artifacts (such as or authenticate on resource servers through SassyAuth  
- Permissions: Granular permissions that control the rights each user has on the system.  
- Roles: Defines roles that are a combination of Permissions  
- Orgs: defines organizations that can directly manage their own users and roles  
- Apps: defines resource servers that uses SassyAuth as its authentication server

SassyAuth Platform and Org admins can authenticate directly on SassuAuth for administration purposes.

When authentication comes from a resource server, SassyAuth generates a JWT token that includes the permissions the user inherits

## Users

Users can authenticate with a password using a username, email or phone number as the main identifier. Each app defines at least one main identifier the user can authenticate with. Email or phone number are required (username is fully optional)

Users can optionally authenticate with passwordless authentication with magic links or 6-digit authentication code sent to email address or phone number

Users can also authenticate with social providers: Google, Microsoft, Apple, GitHub

There are 2 sets of users:

- Platform admins: can perform platform-level administrative tasks (manage orgs, manage permissions, manage users)  
- App users: typically authenticates through a resource server. If they authenticate directly on SassyAuth Management UI, they may only manage their user profile. If they belong to multiple organizations, they are first prompted to choose which org they want to use to manage their profile

### User Properties

- ID (autogenerated number increment)  
- Public ID (computed Sqid)   
- First Name  
- Last Name  
- Email Address  
- Permissions  
- Phone Number (optional)  
- Username (optional)  
- Social Provider (optional)  
- Social ID (optional)

## Organizations (or orgs)

An org represents a tenant (as in “multi-tenant architecture”) through which standard users are managed  
A user can only belong to one organization  
If a user must belong to multiple organizations, duplicates of the same user, each belonging to different orgs.

The first organization is the “platform” organization

### Org Properties

- ID (autogenerated number increment)  
- Public ID (computed Sqid)  
- Org Name  
- App ID : the ID of the app the organization is associated with

## Apps

### App Properties

- ID (autogenerated number increment)  
- Public ID (computed Sqid)  
- App Name  
- App Url

The App Url determines how to authenticate/authorize a user, i.e. only the user that belongs to an org associated with the app 

## Permissions

Defines the permissions the user has on the resource server or the SassyAuth platform

There are 2 sets of permissions:

- Platform permissions: the list of permissions the user has on SassyAuth  
- App permissions: the list of permissions the user has on a resource server that uses SassyAuth 

### Platform permissions

- platform.orgs.manage: permissions to CRUD organizations  
- platform.apps.manage: permissions to CRUD apps (resource servers)  
- platform.users.manage: permissions to CRUD users and assign them to any org (  
- platform.permissions.manage: permissions to CRUD platform permissions  
- org.users.manage: permissions to CRUD users only on the organization the current user is authenticated with  
- org.permissions.manage: permissions to CRUD app permissions only for the organization the current user is authenticated with

Platform permissions are immutable and cannot be edited through the SassyAuth Management UI

### App permissions

These permissions are custom (such as “invoices.create” or “sales\_manager”)  and created by a platform admin with platform.permissions.manage permissions or an org admin with org.permissions.manage

### Permission Properties

- ID (autogenerated number increment)  
- Public ID (computed Sqid)  
- Permission Name (such as “platform.orgs.manage” or “sales\_manager”)  
- App ID
