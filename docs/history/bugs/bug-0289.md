# bug-0289: `User` mock literals missing `createdAt`/`lastLoginAt` in 2 admin test files

**Fixed:** false

## Summary

`apps/admin/lib/types.ts`'s `User` interface requires `createdAt: string` and
`lastLoginAt: string | null` (bug-0186 made these real, non-optional fields).
`user-view-drawer.test.tsx` and `users-table.test.tsx` (last touched
2026-09-04, commit `bd24b46`) still build `User`-typed literals without
either field. Verified against current `dev` (`origin/dev` HEAD `ccf2cea`):

```
components/__tests__/user-view-drawer.test.tsx(25,7): error TS2739: ... missing ... createdAt, lastLoginAt
components/__tests__/users-table.test.tsx(60,3): error TS2739: ...
components/__tests__/users-table.test.tsx(61,3): error TS2739: ...
components/__tests__/users-table.test.tsx(143,7): error TS2739: ...
```

## Impact

Same class of failure as bug-0288 (unrelated fields added to a shared type,
test fixtures never updated) but against `User` instead of `App`, and older —
this one predates the password-policy work by a day. Contributes to the same
"`typecheck` has been red on `dev` regardless of PR content" problem
documented in `TODO_2026-09-14.md`.

## Fix

Add `createdAt: '2026-01-01T00:00:00.000Z', lastLoginAt: null` to each of the
four affected `User` literals. Values are arbitrary fixed timestamps — no
assertion in either suite reads them, so any well-formed ISO string is safe.

## Verification

- `grep`-audited every `User`-typed literal in both files after the edit;
  all four now carry both fields.
- Not run through `pnpm typecheck` in this worktree (no `node_modules`
  installed); mechanical, low-risk change matching the field types exactly.
