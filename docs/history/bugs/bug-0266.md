# bug-0266: AI Semantic Security Review workflow references a nonexistent action tag

**Severity:** Warning
**Status:** Open
**Fixed:** false

## Description

`.github/workflows/ai-security-review.yml` (added 2026-08-23, commit
`8d86e15`) pins `uses: anthropics/claude-code-security-review@v1`. That
repository has **no tags and no releases at all**
(`gh api repos/anthropics/claude-code-security-review/tags` and `/releases`
both return empty arrays), so `@v1` can never resolve. Every run fails
immediately:

```
##[error]Unable to resolve action `anthropics/claude-code-security-review@v1`,
unable to find version `v1`
```

Confirmed on PR #348's run (`gh run view 32702748032 --log`). The review
step never gets far enough to execute, so no PR has ever actually received
an AI security review from this workflow since it was added.

Separately, `gh secret list` shows no `ANTHROPIC_API_KEY` secret configured
on this repo, which the action also requires
(`anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}`). Fixing the version
pin alone will surface that as the next failure. Setting the actual secret
value is an operator action outside what a code fix can do — noted in
today's TODO.

## Impact

The AI semantic security review — the newest of this repo's two added
security gates — has never run successfully on a single PR.

## Files

- `.github/workflows/ai-security-review.yml:45`

## Fix

Pin to a specific commit SHA on the action's `main` branch
(`0c6a49f1fa56a1d472575da86a94dbc1edb78eda`, the HEAD at time of this fix)
rather than a tag that doesn't exist. A SHA pin is also better supply-chain
practice than floating on `@main` for an action with PR-write access and a
secret API key, consistent with this same workflow's own hardening comments.
Applied in this PR. `ANTHROPIC_API_KEY` still needs to be added to the repo
secrets by an operator before the workflow can complete a run — see
docs/history/todo/TODO_2026-08-24.md.
