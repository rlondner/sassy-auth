# bug-0266: AI Semantic Security Review workflow references a nonexistent action tag

**Severity:** Warning
**Status:** Open
**Fixed:** false

## Description

`.github/workflows/ai-security-review.yml` (added 2026-08-23, commit
`8d86e15`) pins `uses: anthropics/claude-code-security-review@v1`. That
repository has **no tags and no releases at all**
(`gh api repos/anthropics/claude-code-security-review/tags` and `/releases`
both return empty arrays), so `@v1` can never resolve. Every run fails
immediately:

```
##[error]Unable to resolve action `anthropics/claude-code-security-review@v1`,
unable to find version `v1`
```

Confirmed on PR #348's run (`gh run view 32702748032 --log`). The review
step never gets far enough to execute, so no PR has ever actually received
an AI security review from this workflow since it was added.

Separately, `gh secret list` shows no `ANTHROPIC_API_KEY` secret configured
on this repo, which the action also requires. Fixing the version pin alone
will surface that as the next failure. Setting the actual secret value is
an operator action outside what a code fix can do — noted in today's TODO.

**Every other key in the `with:` block was also wrong**, discovered while
fixing the version pin and cross-checking against the action's actual
`action.yml` (`gh api repos/anthropics/claude-code-security-review/contents/action.yml`):

- `github_token` isn't a real input on this action at all — it reads
  `${{ github.token }}` internally for PR comments.
- `anthropic_api_key`, `model`, and `exclude_paths` are the right idea with
  the wrong spelling — the real inputs are `claude-api-key`, `claude-model`,
  `exclude-directories`.
- `severity_threshold` has no equivalent input anywhere on this action.
- The inline `system_prompt:` text has no equivalent input either — the
  closest real input, `custom-security-scan-instructions`, takes a **file
  path**, not inline text.
- `exclude-directories` matches by directory-path substring (see
  `claudecode/github_action_audit.py`'s `_is_excluded`), not glob patterns —
  the original `"tests/**, **/*.lock, **/*.md, package-lock.json"` value
  could never have matched anything even with the right key name.

GitHub Actions silently drops unrecognised keys under a `with:` block rather
than erroring, so none of the workflow's six numbered "HARDENING" comments
were ever actually wired to a real setting, independent of the version-pin
failure.

## Impact

The AI semantic security review — the newest of this repo's two added
security gates — has never run successfully on a single PR, and even once
it can run, none of its configured hardening (model choice, prompt-injection
instructions, path exclusions) was ever actually being applied.

## Files

- `.github/workflows/ai-security-review.yml`
- `.github/claude-security-scan-instructions.md` (new)

## Fix

Pin to a specific commit SHA on the action's `main` branch
(`0c6a49f1fa56a1d472575da86a94dbc1edb78eda`, the HEAD at time of this fix)
rather than a tag that doesn't exist. Rewrote the `with:` block to use the
action's real input names (`claude-api-key`, `claude-model`,
`custom-security-scan-instructions`, `exclude-directories`), moved the
prompt-injection-defense instructions to a real file since that input only
accepts a path, corrected `exclude-directories` to plain directory names
matched by substring rather than the glob patterns that were never going to
work, dropped `severity_threshold` (no equivalent input exists), and bumped
the model pin off a ~2-year-old snapshot. Also widened the separate
"Pre-scan Context Sanitization" step's delete glob from `*.env` (never
matched `.env.local`/`.env.example`/any other `.env.*`) to `.env*`, and
added the Apple `.p8` key format this repo actually uses. Applied in this
PR. `ANTHROPIC_API_KEY` still needs to be added to the repo secrets by an
operator before the workflow can complete a run — see
docs/history/todo/TODO_2026-08-24.md.

Note: `exclude-directories` can only exclude whole directories, not file
extensions — this repo's colocated `*.spec.ts` files (sitting next to their
source file rather than in a `__tests__/` subdirectory) can't be excluded
via this mechanism at all. Not fixable within this action's current input
surface; left as a known gap.
