## Fixed (2 bugs)

- **bug-0285** (High) — `isAppUrlAllowed()`
  (`apps/auth-server/src/common/config/app-url-policy.ts`), the shared
  validator behind `@IsAppUrl()` used on `SaApp.url` and other app/callback
  URL fields, only rejected `http://`, `localhost`/`*.localhost`, and the
  two literal loopback addresses `127.0.0.1`/`::1` — any other dotted
  hostname passed, including RFC 1918 private ranges, RFC 3927 link-local
  space, and the `169.254.169.254` cloud-metadata address. A tenant-scoped
  app admin could set an app's `url` (or, once PR #378 lands, its new
  `webhookUrl`) to an internal-only address; any future server-side request
  to that stored URL becomes an SSRF vector. Added IPv4/IPv6
  private-literal range checks alongside the existing loopback/localhost
  guards. PR #383.
- **bug-0286** (Medium) — `apps/admin/messages/fr.json` was missing 10 keys
  present in `en.json` (`login.error.unverified`,
  `users.status.unverified`, `apps.fields.defaultOrg*`,
  `apps.fields.defaultRole*`, `signup.errors.captcha*`), causing
  next-intl's fallback rendering instead of translated text for
  French-locale users on the login-error, users-table, app-config, and
  signup-captcha screens. Second time this bug class has shipped in the
  last few days (see `fddd82f` for the first). Added the missing keys and
  a `messages-parity.test.ts` regression test asserting `en.json`/`fr.json`
  expose identical key sets going forward. PR #384.
