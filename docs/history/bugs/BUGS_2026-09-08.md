### bug-0282 🟠 High — `app/signup/page.tsx` exports a non-page symbol, breaking `next build`

**Fixed:** false

**Files:**
- `apps/admin/app/signup/page.tsx`
- `apps/admin/app/signup/fetch-app-info.ts` (new)
- `apps/admin/app/signup/__tests__/page.test.tsx`

**Description:** `page.tsx` exported `fetchAppInfo` as a named export
alongside the default `SignupPage` component. Next.js's App Router
validates that a `page.tsx` file only exports its recognized allow-list
(default component, `dynamic`, `generateMetadata`, etc.); any other export
fails that validation:

```
app/signup/page.tsx
Type error: Page "app/signup/page.tsx" does not match the required types of a Next.js Page.
```

**Impact:** `next build` — and therefore `admin-e2e` CI, which builds
before running Playwright — has been broken since the function landed
(`bf8924f`, 2026-09-05). Any deploy of `apps/admin` from `dev` would fail
the same way. Invisible for 3 days: see bug-0284.

**Fix:** moved `fetchAppInfo` into `fetch-app-info.ts`, a plain module
imported by both `page.tsx` and its test. `page.tsx` now only exports
`dynamic` and the default component.

**Verification:** `npx jest app/signup/__tests__/page.test.tsx` — 4/4
passing. `next build` now compiles past this file (next failure is the
independent bug-0283).

**PR:** #379 (`bugs/bug-0282-signup-page-invalid-export`)

### bug-0283 🟠 High — `roles/page.tsx`'s app-picker mock missing required `App` fields

**Fixed:** false

**Files:**
- `apps/admin/app/(admin)/roles/page.tsx`

**Description:** The non-platform branch of `RolesPage` hand-builds a
single-item `App[]` for the app picker. It was never updated after
`passwordPolicyOverride`/`effectivePasswordPolicy` became required `App`
fields (`430f870`, 2026-09-05, per-app password policy feature):

```
app/(admin)/roles/page.tsx(40,7): error TS2322: Type '{ ... }[]' is not assignable to type 'App[]'.
  Type '{ ... }' is missing the following properties from type 'App': passwordPolicyOverride, effectivePasswordPolicy
```

**Impact:** breaks `typecheck` CI, and `next build`'s own type-check step
(so `admin-e2e` too) — present on `dev` since before 2026-09-01 (earliest
visible `typecheck` Actions run), invisible for the same reason as
bug-0282: see bug-0284.

**Fix:** filled in the two fields using the existing
`FALLBACK_PASSWORD_POLICY` constant (`apps/admin/lib/types.ts`, already
built for exactly this "no live policy resolved" case). This mock entry is
only used to label/select the viewer's own app in a picker — it never
renders or enforces the policy — so the fallback default is safe.

**Verification:** `tsc --noEmit -p tsconfig.ci.json` (the exact command
`pnpm typecheck:ci` runs) — 0 errors. `npx jest
components/__tests__/roles-table.test.tsx` — 9/9 passing.

**PR:** #380 (`bugs/bug-0283-roles-page-app-mock-missing-fields`)

### bug-0284 🟡 Medium — `typecheck`/`unit-tests`/`e2e` never run on push to `dev`

**Fixed:** false

**Files:**
- `.github/workflows/e2e.yml`
- `.github/workflows/typecheck.yml`
- `.github/workflows/unit-tests.yml`

**Description:** All three workflows trigger on `pull_request` against
`[master, dev]` but on `push` only to `[master]`. A direct push or merge
to `dev` — its normal role as the integration branch in this repo's
`feat/*` → `dev` → `master` flow — gets zero CI signal unless a PR happens
to be open against it at the same time.

**Impact:** this is the concrete mechanism that hid both bug-0282 (3 days)
and bug-0283 (over a week) — the same failure shape already documented
repeatedly for `master` before it had this same gap fixed (the 34-day e2e
freeze and the 2-day silent `unit-tests` red, both noted in prior daily
reviews). `dev` had the identical exposure and nobody had closed it yet;
in fact the 2026-09-04 TODO already flagged this exact gap as worth a
decision and it went unaddressed for 4 days.

**Fix:** added `dev` to `push.branches` in all three workflows, matching
their existing `pull_request` scope.

**Verification:** diff reviewed — only the `push.branches` array changed
in each file. Effect will be directly observable on the next push to `dev`
triggering real `typecheck`/`unit-tests`/`e2e` runs.

**PR:** #381 (`bugs/bug-0284-ci-missing-dev-push-trigger`)
