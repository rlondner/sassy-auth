# Bug Catalog

Bugs surfaced by the **2026-08-24 daily code review**. The reviewed window
(since the 2026-08-21 review) saw 30 commits landing a complete invite-only
social-authentication feature (Google, Microsoft, Apple) directly on
`master`, plus a Docker quickstart and two new CI security workflows. This
is a post-feature security/correctness scan, not a regression scan against
a frozen tree — the prior 34-day `master` freeze broke on 2026-08-19 and has
stayed broken. 6 new bugs found (0 critical, 4 warning, 1 warning-scoped-to-
test-infra, 1 minor). Full detail for each bug is in its own
`bug-NNNN.md` file; this catalog is the index. Every bug below has a fix
already applied in its linked PR.

Severity legend:
- 🔴 **Critical** — blocks shipping; tenant isolation, credential leakage, or auth bypass.
- 🟡 **Warning** — fix soon; correctness, integrity, or availability gap.
- 🔵 **Minor** — small correctness / doc-accuracy hygiene.

## New bugs (6)

### bug-0265 🟡 Warning — Trivy SARIF upload failure silently skips the CVE-blocking gate

**Files:** `.github/workflows/trivy.yml`

This private repo has no GitHub Advanced Security, so the SARIF-upload step
always fails ("Code scanning is not enabled"). Without `continue-on-error`,
that failure stopped the next step — the actual "Enforce PR Block on
Critical CVEs" gate — from ever running. Also pinned both
`aquasecurity/trivy-action@master` calls to a version+SHA instead of the
mutable branch (one of them runs with `security-events: write` and gates
every PR merge).

**Fix:** PR #349. **Fixed:** false

### bug-0268 🟡 Warning — federated sign-in audit trail recorded rejections only

**Files:** `apps/auth-server/src/auth/auth.config.ts`, `apps/auth-server/src/social/sign-in-method.ts`

`recordFederationEvent` declares `'social.link.created'`,
`'social.signin.ok'`, `'social.signin.rejected'`, `'social.link.removed'`
but was only ever called once, for the rejection path. Every successful
federated sign-in produced zero audit-trail rows, despite the feature's own
docs describing `SaAuditEvent` as the durable "who linked this account and
when" record.

**Fix:** PR #354 (wires `social.signin.ok`; `social.link.created`/`removed`
remain unemitted — see TODO_2026-08-24.md). **Fixed:** false

### bug-0269 🟡 Warning — `Account` has no DB-level uniqueness on (providerId, accountId)

**Files:** `packages/db/schema.prisma`, `packages/db/migrations/20260824070000_account_provider_unique/`

BetterAuth's account-linking table had no unique constraint at all. The
social-login feature's invite-only linking guarantee rested entirely on
BetterAuth's own (third-party) find-or-create logic never racing or having
a bug, with nothing in the database backing it up.

**Fix:** PR #353 (new migration adding `@@unique([providerId, accountId])`). **Fixed:** false

### bug-0270 🟡 Warning (test-infrastructure only, not reachable in production) — stub-idp's concurrent-write guard has a check-then-act race

**Files:** `apps/admin-e2e/fixtures/stub-idp/server.mjs`

The e2e stub IdP's `POST /__set-identity` guard checked `isPending()` before
its only `await`, then claimed the pending slot after — a real async
yield point that let two concurrent writes both pass the check, exactly the
silent-interleaving failure mode the guard exists to turn into a loud 409.
Not reachable today (`playwright.config.ts` pins `workers: 1`), but the
guard was untested in the one scenario it exists for.

**Fix:** PR #352. **Fixed:** false
