### bug-0271 🟡 Warning — apps/admin declares React 18 while every login form requires React 19

**Files:**
- `apps/admin/package.json`
- `packages/ui/package.json`
- `apps/admin/app/login/__tests__/login-forms.test.tsx`

**Description:** `LoginForm`/`LoginOtpForm`/`TwoFactorForm` all depend on React
19-only APIs (`useActionState`, function-valued `<form action>`), but `apps/admin`
declared `react ^18.3.0`. The app worked only because Next 15 vendors and aliases its
own React 19 at bundle time; nothing in the normal dev loop (`next dev`, `tsc
--noEmit`) exercises the declared version. Today's new 22-case `login-forms.test.tsx`
— which resolves `react` via plain Jest module resolution, not Next's alias — landed
already `describe.skip`'d rather than red, because the author probed the mismatch
directly. Full detail in `bug-0271.md`.

**Fix:** PR #357. Bumps `apps/admin` and `packages/ui` (which had the identical stale
devDependency pin despite already accepting React 19 as a peer) to `react@^19.0.0`,
dedupes the workspace install, un-skips the suite. Also fixes two of the newly-run
cases that had the `TwoFactorForm` trust-device checkbox's default backwards — never
executed before today, so never caught. **Verified:** 47/47 admin suites (409/409
tests) pass; 4/4 ui suites pass; `tsc --noEmit` shows the same 5 pre-existing,
unrelated errors with and without this change.

**Fixed:** false

### bug-0272 🟡 Warning — AI review's sanitization pre-scan misses this repo's actual dotenv convention

**Files:**
- `.github/workflows/ai-security-review.yml:38-42`

**Description:** The AI security review workflow's "Pre-scan Context Sanitization"
step exists to delete secret-bearing files before the AI model reads the checkout,
but `find -name "*.env"` only matches names *ending* in `.env` (`foo.env`). It misses
`.env.local`, `.env.production`, and `.env.local.bak-<timestamp>` — this repo's real
dotenv convention, documented in `.gitignore`'s own comment as the exact pattern that
has already been accidentally committed here once. Full detail in `bug-0272.md`.

**Fix:** PR #358. Adds `find . -name ".env*" -type f -delete` alongside the existing
suffix-form pattern. Verified by reproducing both glob behaviors against a scratch
directory containing all four file-name shapes.

**Fixed:** false

## Verified — not filed

- **`ai-security-review.yml`'s stray trailing `)` in the `claude_args` string**
  (introduced in `16e6055`, line 50, right before the closing YAML quote): traced
  through `anthropics/claude-code-action`'s `base-action/src/parse-sdk-options.ts`,
  which pre-escapes `()|&;<>` to private-use codepoints before handing the string to
  `shell-quote`'s parser specifically to stop bare parens from being treated as shell
  control operators. The stray `)` does **not** break argument parsing — it ends up as
  a literal trailing character appended to the injected prompt text. Cosmetic only;
  noted in today's TODO as a one-line cleanup, not filed as a bug.

  `docs/history/code-reviews/CR_2026-08-25.md`): doesn't apply here — `.env.example`
