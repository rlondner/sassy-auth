### bug-0126 :yellow_circle: Warning — `raceSuccessOrError` silently passes when both promises timeout

**Files:**
- `apps/admin-e2e/pages/apps.page.ts:69-90`
- `apps/admin-e2e/pages/orgs.page.ts:65-86`
- `apps/admin-e2e/pages/permissions.page.ts:64-85`
- `apps/admin-e2e/pages/roles.page.ts:64-85`
- `apps/admin-e2e/pages/users.page.ts:84-105`

**Description:** The `raceSuccessOrError` helper in all 5 page objects uses `Promise.race()` where both the success and error promises swallow timeouts via `.catch(() => null)`. When **neither** the success toast nor the error toast appears within 10 seconds, both promises resolve to `null`. `Promise.race` returns the first `null` to settle, and the subsequent `if (outcome === 'error')` check is false — so the function returns silently as if the operation succeeded.

**Impact:** Tests produce false positives. If an operation completes without rendering any toast (e.g., the toast component fails to mount, a network error returns silently, or the page navigates away before the toast appears), the E2E test passes when it should fail. This is distinct from bug-0120 (error div missing `role="alert"` — which prevents error detection specifically); this bug affects the case where *no outcome at all* is detected.

**Fix:** Add a `null` check after the race:
```typescript
const outcome = await Promise.race([success, error])
if (outcome === null) {
  throw new Error(`Expected success toast "${successText}" or error toast, but neither appeared within 10 seconds`)
}
if (outcome === 'error') {
  const text = (await errorScope.getByRole('alert').textContent())?.trim() ?? '<unknown>'
  throw new Error(`UI rendered error toast: "${text}"`)
}
```

**Fixed:** false

### bug-0127 :yellow_circle: Warning — UsersTable has 4 non-functional dropdown menu items

**File:** `apps/admin/components/users-table.tsx:107-118`

**Description:** The UsersTable dropdown menu renders four action items — "Reset Password" (line 108), "Resend Invitation" (line 111), "Deactivate" (line 115), and "Activate" (line 117) — with no `onClick` handlers. Clicking any of these items does nothing. By contrast, "Edit" (line 104) and "Delete" (line 119-122) have working handlers. The other table components (apps, orgs, permissions, roles) have fully functional action menus.

**Impact:** Users see clickable menu items that do nothing, creating a broken UX. Critical user management workflows (password reset, invitation resend, status changes) appear available but are not functional. This is misleading — either the items should be implemented or removed/disabled until ready.

**Fix:** Either:
1. Add `onClick` handlers that call the corresponding API endpoints (`POST /api/users/:id/resend-invitation`, etc.) with toast feedback, or
2. Remove the menu items until the backend endpoints are ready, or
3. Add `disabled` prop with a tooltip explaining "Coming soon".

**Fixed:** false

### bug-0128 :large_blue_circle: Minor — `getRole` test suite missing ForbiddenException coverage

**File:** `apps/auth-server/src/roles/roles.service.spec.ts:160-193`

**Description:** The `getRole` test suite has only 2 tests: the happy path (line 161) and "throws NotFound when the role does not exist" (line 189). There is no test verifying that `getRole` throws `ForbiddenException` when the caller (`saUser`) is not found in the database. The implementation handles this case at `roles.service.ts:114` (`if (!caller) throw new ForbiddenException()`), but this path is untested.

**Impact:** Missing test coverage for the authorization failure path. If the `ForbiddenException` logic is accidentally removed or changed, no test will catch the regression.

**Fix:** Add a test case:
```typescript
it('throws ForbiddenException when caller is not found', async () => {
  mocks.saRole.findUnique.mockResolvedValue({
    id: 7, appId: 5, publicId: 'sq_r7', name: 'Editor',
    app: { publicId: 'sq_app1', name: 'Portal' },
    permissions: [],
  });
  mocks.saUser.findUnique.mockResolvedValue(null);
  await expect(makeService().getRole('ba-caller', 'sq_r7')).rejects.toBeInstanceOf(ForbiddenException);
});
```

### bug-0129 :large_blue_circle: Minor — `.env.example` missing `SEED_DEMO_MULTITENANT` variable

**File:** `.env.example`

**Description:** The `SEED_DEMO_MULTITENANT` environment variable is documented in the README (line 177, 234) and used in the seed script (`apps/auth-server/src/seed/seed.ts`), E2E tests (`apps/admin-e2e/lib/admins.ts`, `apps/admin-e2e/tests/multitenant-tenant-admin.spec.ts`), and test factories (`apps/auth-server/test/scenarios/factories.ts`). However, it is absent from `.env.example`, which only includes `SEED_DEMO=`. Developers copying `.env.example` to `.env.local` will not know about the multi-tenant demo data option.

**Impact:** Discoverability gap. Developers who rely on `.env.example` as the source of truth (as stated in README line 129) will miss this variable. Multi-tenant E2E tests that depend on `SEED_DEMO_MULTITENANT=1` may fail without an obvious explanation.

**Fix:** Add the following line to `.env.example` after `SEED_DEMO=`:
```env
# Set to 1 to seed multi-tenant demo data (app01 + Acme/Globex orgs) during db:seed
SEED_DEMO_MULTITENANT=
```

**Fixed:** false
