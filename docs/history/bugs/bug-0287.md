# bug-0287 — Auth-server local dev URLs point at `https://` but the server only serves plain HTTP

**Fixed:** true

**Files:**
- `.env.example`
- `.flox/env/manifest.toml`
- `.flox/env/manifest.lock`
- `.github/workflows/e2e.yml`
- `docker-compose.yml`
- `docker/entrypoint.sh`
- `apps/admin-e2e/playwright.config.ts`
- `apps/admin-e2e/lib/app-fixtures.ts`
- `apps/admin-e2e/lib/oauth-fixtures.ts`
- `apps/admin-e2e/pages/login.page.ts`
- `README.md`
- `BEGINNER_README.md`

**Description:** `ccf2cea` ("dev(ports): updated auth-server port from
3000 to 3010") mechanically replaced every `http://localhost:3000`
default with `https://localhost:3010` across the repo — not just the
port, but the scheme too. `apps/auth-server/src/main.ts` was part of the
same commit but only changed the port number passed to `app.listen()`
(`process.env.PORT ?? 3010`); it never gained an `httpsOptions` /
`createServer` call or any TLS certificate wiring, so the auth-server
still binds and serves plain HTTP on 3010.

Every default that a fresh clone, `docker compose up`, `flox activate`,
or the `e2e` CI workflow relies on now points those consumers at
`https://localhost:3010` — a TLS handshake against a socket that only
speaks HTTP. `docker/entrypoint.sh`'s own startup banner prints
`https://localhost:3010` as the URL to open. The e2e Playwright suite's
fallback defaults (`playwright.config.ts`, `app-fixtures.ts`,
`oauth-fixtures.ts`, `login.page.ts`) inherited the same wrong scheme,
so any CI or local run that doesn't have `AUTH_SERVER_URL` overridden in
its actual environment would fail every request to the auth-server with
a TLS/connection error rather than a clean HTTP response.

**Impact:** Default `docker-compose up`, a fresh `flox activate`, and
the `e2e.yml` workflow's own hard-coded `BETTER_AUTH_URL`/
`AUTH_SERVER_URL` env values all break — any `fetch`/`curl`/Playwright
request against `https://localhost:3010` fails at the TLS layer before
reaching the NestJS app, since nothing terminates TLS there. This is a
regression in the same commit's own stated goal (renumber the port) —
the scheme change was very likely an unintended side effect of a
blanket find/replace rather than a deliberate move to local HTTPS
(DEPLOYMENT.md documents HTTPS as a production-only concern, requiring
either the Render-provisioned certs or a manual `mkcert + Caddy` local
TLS setup that this commit did not add).

**Fix:** Reverted the scheme back to `http://` everywhere it was
touched by `ccf2cea` and is used as the real local-dev/CI default,
keeping the intended port-3010 change. Historical/point-in-time docs
under `docs/history/**` and `docs/superpowers/**`, and test files that
use the URL only as an arbitrary string value rather than dialing it,
were left untouched — out of scope for this fix.
