## New bugs (1)

### :large_blue_circle: bug-0116 — `users-table.tsx` delete handler does not close view drawer

**File:** `apps/admin/components/users-table.tsx`, lines 194–203

**Description:** The inline `onConfirm` callback for the `DeleteAlertDialog` in `users-table.tsx` calls `setDeleteOpen(false)` and `refresh()` after successful deletion but never calls `setViewOpen(false)`. In contrast, all four other tables (`apps-table.tsx:150`, `orgs-table.tsx:170`, `permissions-table.tsx:179`, `roles-table.tsx:175`) explicitly call `setViewOpen(false)` in their `handleDelete` functions.

**Impact:** If a user opens the view drawer (by clicking a row), then triggers delete from the row's dropdown menu, successful deletion closes the delete dialog but leaves the view drawer open. After `router.refresh()` re-renders the page, the view drawer may show stale data or a broken state for the now-deleted user.

**Fix:** Add `setViewOpen(false)` to the `onConfirm` callback, after `setDeleteOpen(false)` on line 201.
