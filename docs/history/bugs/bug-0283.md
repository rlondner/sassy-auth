# bug-0283: `roles/page.tsx` app mock missing `App`'s password-policy fields

**Fixed:** false

## Summary

`apps/admin/lib/types.ts`'s `App` interface has required
`passwordPolicyOverride: PasswordPolicy | null` and
`effectivePasswordPolicy: PasswordPolicy` fields (added by the per-app
password-policy feature merged 2026-09-05, commit `430f870`). The non-platform
branch of `app/(admin)/roles/page.tsx` builds a single-item `App[]` array by
hand for the app picker and never picked up the new fields, so `typecheck`
(and `next build`'s own type-check step) fails:

```
app/(admin)/roles/page.tsx(40,7): error TS2322: Type '{ publicId: string; ... }[]' is not assignable to type 'App[]'.
  Type '{ ... }' is missing the following properties from type 'App': passwordPolicyOverride, effectivePasswordPolicy
```

## Impact

- `typecheck` CI has been red on `dev` since before 2026-09-01 (the earliest
  run visible in Actions history) — every commit since predates that job even
  running, because `.github/workflows/typecheck.yml` only triggers on `push`
  to `master` and on pull requests. `dev` had no open PRs between then and PR
  #378 (2026-09-08), so nothing surfaced it.
- Blocks `next build`, and therefore `admin-e2e` CI, the same way bug-0282
  does (independently — fixing one does not fix the other).

## Fix

Fill in the two missing fields on the synthesized app-picker entry:
`passwordPolicyOverride: null` and `effectivePasswordPolicy:
FALLBACK_PASSWORD_POLICY` (the existing constant `apps/admin/lib/types.ts`
already exports for exactly this "no live policy resolved yet" case). This
entry is only used to label/select the viewer's own app in a picker — it
never renders or enforces the policy — so the fallback default is safe.

## Verification

- `tsc --noEmit -p tsconfig.ci.json` (matches `pnpm typecheck:ci`, the exact
  command CI runs) — clean, 0 errors.
- `npx jest components/__tests__/roles-table.test.tsx` — 9/9 passing.
- `next build` now compiles past `app/(admin)/roles/page.tsx`; the remaining
  failure in this branch is the unrelated, independently-fixed bug-0282
  (`app/signup/page.tsx`, PR #379).
