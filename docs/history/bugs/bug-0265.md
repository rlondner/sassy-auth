# bug-0265: Trivy SARIF upload failure silently skips the CVE-blocking gate

**Severity:** Warning
**Status:** Open
**Fixed:** false

## Description

`.github/workflows/trivy.yml` (added 2026-08-23, commit `8d86e15`) runs three
steps in sequence: generate a SARIF report, upload it to the GitHub Security
tab, then a separate `Enforce PR Block on Critical CVEs` step that hard-fails
the build (`exit-code: '1'`) on any CRITICAL, unfixed vulnerability.

This repository is private and does not have GitHub Advanced Security /
code scanning enabled, so the `github/codeql-action/upload-sarif@v3` step
always fails: `Please verify that the necessary features are enabled: Code
scanning is not enabled for this repository.` (confirmed via
`gh run view 32679294758 --log`, and reproduced again on PR #348's run
`32702747969`).

GitHub Actions skips subsequent steps once one fails (no `continue-on-error`
was set), so the actual point of the workflow — the "Enforce PR Block on
Critical CVEs" step — never runs. The job shows red on every PR and every
scheduled run, but not because of real CVEs; the real gate is silently
skipped underneath that red status, which is worse than not having the
workflow at all (a real critical CVE would currently merge unblocked, and
the constant unrelated red trains reviewers to ignore the check).

## Impact

The intended CVE-blocking gate for this repo has never actually executed
since the workflow was added. Confirmed on the scheduled run
(`2026-08-24T01:17`), a PR run (`2026-08-24T07:42:47` on PR #348), and the
`ci: add Claude security review and Trivy CVE scan workflows` commit itself.

## Files

- `.github/workflows/trivy.yml:41-46`

## Fix

Add `continue-on-error: true` to the SARIF-upload step so a GHAS-unavailable
failure there can't prevent the CRITICAL-CVE gate from running. Applied in
this PR. Once GitHub Advanced Security is enabled for this repo (or it goes
public), the upload will start succeeding on its own and `continue-on-error`
can be removed — it does not mask an actual SARIF-format or scan failure,
only the code-scanning-tab availability check.
