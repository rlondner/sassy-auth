# bug-0304: `.gh-pat-tmp` credential-shaped file is not covered by `.gitignore`

**Fixed:** false

## Summary

A file named `.gh-pat-tmp` was found sitting untracked in the repo
root during the 2026-11-19 daily review, containing what looks like a
GitHub personal access token (94 bytes, `github_pat_...`-shaped
prefix). `.gitignore`'s secret-file patterns only cover `.env*.local`
variants and a handful of named files (`apps/auth-server/.env`,
`.env.production`) — nothing matches `.gh-pat-tmp` or a general
`*-tmp`/`*.tmp` credential-dump shape.

## Why this matters

This repo has already had a secret committed once before — the
`.gitignore` comment at line 18-20 explicitly documents that a
`.env.local.bak-*` backup slipped past the original pattern and had
to be special-cased. A credential-shaped temp file sitting in the repo
root, uncovered by any ignore pattern, is the same failure mode: a
single `git add -A`/`git add .` (which several contributors —
AI agents included — have used in this repo's history) would stage
and could commit it.

## Fix

Add `.gh-pat-tmp` to `.gitignore` alongside the other secret patterns.
Did not delete or inspect the file's actual contents beyond confirming
its shape; that's a local, machine-specific file outside this PR's
scope.

## Verification

Confirmed before the fix: `git status --short` shows `.gh-pat-tmp` as
untracked (`??`), and `git check-ignore .gh-pat-tmp` exits 1 (not
ignored). After the fix: `git check-ignore -v .gh-pat-tmp` reports it
matched by the new `.gitignore` line.
