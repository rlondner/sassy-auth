### bug-0300 🔴 Critical — PR #468 (the bug-0299 CVE fix) breaks the build and has been red on CI since it was opened, contradicting yesterday's "closed out" note

**Fixed:** false (partially — one of two root causes fixed and pushed to
PR #468 in this run; see below)

See [bug-0300.md](./bug-0300.md) for the full writeup. Summary: the
`better-auth 1.6.11 → 1.7.7` bump in PR #468 has two independent root
causes, both failing CI since the PR's creation commit
(`gh pr checks 468`: `admin-e2e fail` / `unit-tests fail` on every run —
it has never been green, contradicting yesterday's "closed out" note):

1. `unit-tests` failed to even load `verify-user-totp.spec.ts`, because
   the bumped `@better-auth/utils@0.5.1` pulls in `@noble/hashes@2.2.0`,
   which is ESM-only and the auth-server's Jest config has no
   `transformIgnorePatterns` override to transform it. **Fixed and
   pushed to the `bug-0299` branch in this run** (commit `ec223c6`): a
   `pnpm.overrides` pin to `@noble/hashes@^1.8.0` (same pattern PR #468
   already used for `dompurify`). Verified locally — the previously
   crashing spec now passes, and the auth-server suite drops from 5
   failing test suites to 3.
2. `nest build` itself fails with 9 TypeScript errors because
   `auth.api.createVerificationOTP` / `checkVerificationOTP` /
   `verifyEmailOTP` / `generateOpenAPISchema` no longer exist on the
   inferred API type, and two `databaseHooks` `after` handler signatures
   no longer match the library's stricter `GenericEndpointContext` type.
   **Not fixed in this run** — the correct replacement calls need to be
   checked against the actually installed `better-auth@1.7.7` type
   definitions rather than guessed, since this sits directly in the
   registration / email-verification flow. This is the remaining
   blocker on PR #468.

**Note on where the fix belongs:** this bug lives entirely inside
still-open PR #468 (`bug-0299`), not on `dev` — `dev` never received the
dependency bump, so there is no equivalent code on `dev` to patch. Per
this run's instructions to open a PR against `dev` for each new bug, the
docs for bug-0300 are included in this `dev`-targeted bundle, but the
actual code fix must land as a follow-up push to the `bug-0299` branch /
PR #468, not as a separate `dev` PR duplicating unmerged code.
