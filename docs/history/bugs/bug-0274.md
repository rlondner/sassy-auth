# bug-0274: unit-tests CI workflow was left on Node 20, missed by the Node 24 migration

**Severity:** Low
**Status:** Open
**Fixed:** false

## Description

`5e21bfe` ("chore: migrate to Node 24", 2026-08-25) bumped `.github/workflows/e2e.yml`
and `.github/workflows/typecheck.yml` from `node-version: 20` to `24`, plus the
`Dockerfile` and root `package.json#engines` (`>=24.0.0`), stating it "Bumps CI,
Docker, and engines to Node 24." It did not touch
`.github/workflows/unit-tests.yml`, which still pinned `node-version: 20`.

Every `unit-tests` run since has logged, per step:

```
WARN Unsupported engine: wanted: {"node":">=24.0.0"} (current: {"node":"v20.20.2"...})
```

plus GitHub's own end-of-run warning that `actions/checkout@v4`,
`actions/setup-node@v4`, and `pnpm/action-setup@v4` are being force-run on a
deprecated Node — the same EOL/deprecation problem the migration commit's own message
says it was fixing for Trivy.

## Impact

Cosmetic today (pnpm treats the engines mismatch as a warning, not a hard failure),
but leaves the one CI job most likely to catch a genuine Node-24-only regression
(`unit-tests`, which runs `auth-server`/`admin`/`ui`/`db` test suites directly,
unlike `typecheck` or `e2e`) running on the wrong runtime. GitHub has already
signaled Node 20 support on Actions runners is going away.

## Files

- `.github/workflows/unit-tests.yml:26`

## Fix

`node-version: 20` → `24`, matching `e2e.yml`, `typecheck.yml`, the `Dockerfile`, and
`package.json#engines`. Verified by re-running the full local suite this workflow
runs (`auth-server`, `admin`, `ui`, `db` — all green, see bug-0273) under the local
Node 24.14.1 toolchain with no new failures attributable to the version bump.
