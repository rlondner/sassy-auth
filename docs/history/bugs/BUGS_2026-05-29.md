## 🟡 bug-0016 — Hardcoded test credentials in E2E source files

**Fixed:** false
**Severity:** Warning
**Files:** `apps/admin-e2e/tests/login.spec.ts:4-5`, `apps/admin-e2e/auth-state.setup.ts:5-6`

**Description.** The super-admin email (`s@sa.io`) and password (`Pass@word1234`) are hardcoded as string constants in two test files. These credentials are visible in git history, CI logs, and Playwright reports. While the e2e workflow comment says values are "non-sensitive test-only," these are seeded credentials that authenticate against a real (ephemeral) database and can sign in to the admin console.

**Fix sketch.** Read from environment variables with fallback:
```ts
const SUPER_ADMIN_EMAIL = process.env.E2E_ADMIN_EMAIL ?? 's@sa.io'
const SUPER_ADMIN_PASSWORD = process.env.E2E_ADMIN_PASSWORD ?? 'Pass@word1234'
```
Add `E2E_ADMIN_EMAIL` and `E2E_ADMIN_PASSWORD` to the GitHub Actions workflow `env:` block and to `.env.example`.

**Tests needed.** Verify the e2e suite still passes with env-var–sourced credentials.

## 🟡 bug-0017 — Silent cookie-setting failure when parseSessionCookie returns null

**Fixed:** false
**Severity:** Warning
**File:** `apps/admin/app/login/actions.ts:127-141`

**Description.** After a successful `200 OK` from the auth server, the `signIn` action parses the `Set-Cookie` header with `parseSessionCookie()`. If that function returns `null` (malformed header, unexpected cookie name, BetterAuth response format change), the session cookie is **silently never set**. The action then `redirect('/users')`, landing the user on the users page without a valid session. The middleware will immediately bounce them back to `/login` with no error message — a confusing UX.

**Fix sketch.** Log a Sentry warning and return an error when parsing fails:
```ts
if (!parsed) {
  Sentry.captureMessage('Failed to parse session cookie from auth server', { level: 'error' })
  return { error: 'invalidCredentials' }
}
```

**Tests needed.** Unit test for `signIn` with a malformed `Set-Cookie` header asserting it returns an error.

## 🟡 bug-0018 — TRUSTED_ORIGINS env var missing URL format validation

**Fixed:** false
**Severity:** Warning
**File:** `apps/auth-server/src/auth/auth.config.ts:12-15`

**Description.** The `TRUSTED_ORIGINS` env var is split by comma and trimmed, but no validation ensures each entry is a valid origin URL. Typos (missing protocol, trailing slash, extra spaces inside a URL) are silently accepted. If the operator sets `TRUSTED_ORIGINS=localhost:3001` (missing `http://`), BetterAuth's origin check will never match, and all admin logins will fail with 403 — with no startup error.

**Fix sketch.** Validate each origin at config-load time:
```ts
const TRUSTED_ORIGINS = (process.env.TRUSTED_ORIGINS
  ?.split(',')
  .map((s) => s.trim())
  .filter(Boolean) ?? ['http://localhost:3001'])
  .map((origin) => {
    try { new URL(origin); return origin }
    catch { throw new Error(`Invalid origin in TRUSTED_ORIGINS: "${origin}"`) }
  })
```

**Tests needed.** Unit test for auth config initialization with invalid origins.

## 🔵 bug-0020 — parseSessionCookie regex fragile on Expires dates with commas

**Fixed:** false
**Severity:** Minor
**File:** `apps/admin/app/login/actions.ts:27`

**Description.** The cookie-splitting regex `/,(?=\s*[A-Za-z0-9!#$%&'*+\-.^_`|~]+=)/` uses a lookahead to avoid splitting on commas inside `Expires=Wed, 21 Oct ...` dates. However, the regex matches any token-char followed by `=`, which could match day-of-week abbreviations like `Thu=...` in edge cases where multiple Set-Cookie headers are combined differently than expected by `node-fetch`.

In practice, Node 20's `undici` concatenates multiple `Set-Cookie` headers with `, ` (comma-space). If BetterAuth ever issues additional cookies (e.g., CSRF token), the regex might incorrectly split mid-Expires.

**Fix sketch.** Consider using the `set-cookie-parser` npm package (7 kB, zero deps) which handles all edge cases:
```ts
import { parse as parseCookie } from 'set-cookie-parser'
```
Or add explicit test cases for multi-cookie + Expires scenarios.

**Tests needed.** Unit tests for `parseSessionCookie` with edge-case inputs.
