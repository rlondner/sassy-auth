## New bugs filed this run

### bug-0296 — GCP VibeCast activation branding drifted from Render

**Fixed:** false

`gcp/env.auth-server.yaml` (new in `4151407`) sets
`VIBECAST_ACTIVATION_EMAIL_FROM_ADDRESS` and
`VIBECAST_ACTIVATION_EMAIL_MESSAGE` to values that don't match
`render.yaml`'s `sassy-auth-server` service, despite
`docs/gcp-deployment.md` stating in two places ("Values are identical to
Render so the cutover is a pure DNS switch") that the two configs are
kept in sync:

- `VIBECAST_ACTIVATION_EMAIL_FROM_ADDRESS`: GCP had `rl@getvibecast.com`;
  Render has `hello@getvibecast.com`. If the `rl@` domain/address isn't
  verified with Resend, a send using it would fail outright — see
  `render.yaml`'s own comment: "fromAddress's domain must be verified
  with the email provider (Resend) or sends will fail."
- `VIBECAST_ACTIVATION_EMAIL_MESSAGE`: GCP's copy read "Click on the
  button (or the link) below to activate your VibeCast account" —
  describing a button/link flow. `render.yaml`'s copy ("Enter the
  6-digit code below...") is correct:
  `apps/auth-server/src/email/templates/verify-email-code.template.ts`
  renders a fixed, non-customizable 6-digit OTP box, not a button or
  link, by design ("the mechanism of verification must never be
  something an admin's custom `message` text can spoof or omit"). GCP's
  message text didn't match the actual product behavior at all.

**Why this hasn't broken anything yet:** per
`apps/auth-server/src/seed/vibecast-migration.ts`'s own comment, these
four `VIBECAST_ACTIVATION_EMAIL_*` vars are read only the *first* time
the VibeCast `SaApp` row is created; afterward the fields are owned by
the `SaApp` record (editable via the admin console) and the env vars are
ignored. Both Render and GCP point at the same Neon database, and
Render already created that row, so a GCP deploy today would not
actually re-apply the wrong values. The bug is real and worth fixing
regardless: it contradicts the deployment doc's explicit parity claim,
and it would silently apply on any future fresh database (a new
environment, a disaster-recovery restore, or if the VibeCast `SaApp` is
ever deleted and recreated).

**Fix:** PR #459 (`bug-0296`) — brings `gcp/env.auth-server.yaml`'s two
values back in sync with `render.yaml`.
