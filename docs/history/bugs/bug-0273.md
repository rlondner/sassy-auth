# bug-0273: master's unit-tests CI has been red for 2+ days — packages/ui's branch-coverage floor is unmet

**Severity:** Critical
**Status:** Open
**Fixed:** false

## Description

Every `unit-tests` run on `master` since PR #347 merged (2026-08-25 04:33 UTC) has
failed: `pnpm --filter @sassy-auth/ui test -- --coverage` exits 1 because branch
coverage is 48.83%, below the 51% floor declared in `packages/ui/package.json`'s
`coverageThreshold.global.branches`. That floor was only added the day before
(`2c888ba`, 2026-08-24) and its commit message claimed the baseline was verified
against the full first-party tree — but the verification was incomplete.

Reproduced locally (`pnpm --filter @sassy-auth/ui test -- --coverage --coverageReporters=text`):

```
File                 | % Stmts | % Branch | % Funcs | % Lines
confirm-dialog.tsx   |     100 |    76.92 |     100 |     100
data-table.tsx       |     100 |    69.23 |     100 |     100
form-field.tsx       |       0 |        0 |       0 |       0
sheet-body.tsx       |       0 |      100 |       0 |       0
status-chip.tsx      |     100 |      100 |     100 |     100
user-avatar.tsx      |     100 |      100 |     100 |     100
hooks/use-mobile.tsx |       0 |      100 |       0 |       0
```

Two entirely first-party, entirely untested files — `components/form-field.tsx`
(0% across every metric) and `hooks/use-mobile.tsx` (0% statements/functions/lines,
counted as 100% branches only because it has none uncovered relative to itself) —
are what pull the package-wide branch figure under the floor. `use-mobile.tsx` was
explicitly named as a known gap in the `2c888ba` baseline commit message. But
`form-field.tsx` was not: it has existed since 2026-05-27 (`23e9fe4`), unchanged
since, and was already untested at baseline time — the "only untested first-party
file left in the package" claim in `2c888ba` was wrong when it was written, not a
later regression. `FormField` is used in production
(`apps/admin/components/user-create-drawer.tsx`) and exercised indirectly by
`apps/admin`'s own test suite, but `packages/ui`'s coverage run only measures
`packages/ui`'s own specs, so that indirect exercise counts for nothing here.

## Impact

Every PR against `master` and every push to `master` gets a failing `unit-tests`
check. There is no branch protection on this repo (confirmed 2026-08-19), so this
doesn't block merges outright, but it does mean the CI status badge and PR checks
have been silently lying for 2+ days — a genuine new test failure in this job would
be invisible against the existing red baseline, exactly the failure mode called out
in the 2026-08-19 CI-health finding (bug-0259) for the e2e workflow.

## Files

- `packages/ui/src/components/form-field.tsx` — untested first-party component
- `packages/ui/package.json` — `coverageThreshold.global.branches: 51`

## Fix

Add a direct unit spec for `FormField`
(`packages/ui/src/__tests__/form-field.test.tsx`) covering its real conditional
branches: generated vs. supplied `id`, required-marker presence, hint shown only
when there's no error, error takes precedence over hint and flips
`aria-invalid`/`aria-describedby`. No source or threshold changes — the floor is
correct, the package was just missing coverage for code that already ships.

Verified: `pnpm --filter @sassy-auth/ui test -- --coverage` — 5/5 suites, 21/21
tests pass, `form-field.tsx` now 100% across all four metrics, package-wide
branches 83.72% (was 48.83%), comfortably above the 51% floor. `pnpm --filter
@sassy-auth/admin test`, `pnpm --filter @sassy-auth/auth-server test`, and `pnpm
--filter @sassy-auth/db test` re-run clean and unaffected.

`hooks/use-mobile.tsx` remaining at 0% first-party coverage is a known, pre-existing
gap (called out in `2c888ba`) — left as-is here since it isn't what's failing the
floor; tracked in today's TODO.
