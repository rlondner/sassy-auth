# bug-0263: GitHub Actions artifact storage quota exhausted — every recent e2e run fails to upload its report/traces

**Severity:** Warning (degrades CI debuggability; does not itself fail builds)
**Status:** Open — fix proposed in this PR, unverified until it merges and the quota clears
**Fixed:** false
**Found by:** 2026-08-20 daily review, while re-checking the [bug-0262](./bug-0262.md) hypothesis via existing CI logs.

## Description

Every `admin-e2e` workflow run sampled from the last 48 hours (6/6 checked —
`32342791624`, `32267803869`, `32267492632`, `32265990053`, `32265148980`,
`32186112882`) ends with:

```
##[error]Failed to CreateArtifact: Artifact storage quota has been hit. Unable to
upload any new artifacts. Usage is recalculated every 6-12 hours.
```

`.github/workflows/e2e.yml` uploads two artifacts per run:

- `playwright-report` — unconditionally, on every run (`if: ${{ !cancelled() }}`), `retention-days: 14`
- `playwright-test-results` (traces/videos/screenshots) — on failure, `retention-days: 14`

`admin-e2e` has been red on `master` for 34+ days (bug-0259), so `test:e2e` fails
on nearly every push and PR. Combined with `trace: 'retain-on-failure'` and
`video: 'retain-on-failure'` in `apps/admin-e2e/playwright.config.ts`, that means
the failure-path upload (traces + videos, the larger of the two artifacts) has
been firing on nearly every single run, and 14 days of accumulated report+trace
uploads outpaced GitHub's Actions artifact storage quota for this account.

**Consequence:** since the quota is exhausted, no run — pass or fail — can
currently upload its Playwright HTML report or its failure traces/videos/
screenshots. This is actively hampering the bug-0262 investigation: the one CI
run that reached the real test suite (`32265048205`, on `bugs/bug-0259`) is the
last one whose artifacts are still viewable; every run since has produced logs
only, no traces to inspect.

## Fix

Reduce `retention-days` from 14 to 3 for both artifact uploads in
`.github/workflows/e2e.yml`. A shorter retention window bounds accumulated
storage independent of the current failure rate, without changing what gets
captured (trace/video/screenshot capture settings in `playwright.config.ts` are
left untouched, since bug-0262 triage still needs them).

This does not by itself clear artifacts already counted against the quota —
GitHub's usage figure is recalculated on its own 6-12 hour cycle. If uploads are
still failing after this lands, the remaining lever is deleting old artifacts
manually (Settings → Actions → Caches, or `gh api` against
`/repos/{owner}/{repo}/actions/artifacts`) rather than waiting out the natural
14-day expiry.

## Verification

Re-checked after this fix merges: the next few `admin-e2e` runs should no longer
log `Failed to CreateArtifact` once the shorter-retention artifacts from this
change start displacing the 14-day backlog. Not verifiable synchronously in this
PR since GitHub's quota recalculation lags real time.
