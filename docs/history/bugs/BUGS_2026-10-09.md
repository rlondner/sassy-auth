### `use-section-persistence.ts` — SSR/hydration mismatch hypothesis (checked, not a bug)

`useSectionPersistence` (`apps/admin/lib/use-section-persistence.ts:39-41`)
uses a lazy `useState` initializer that reads `window.localStorage`
directly during render, which could in principle produce a hydration
mismatch if its result ever reaches the DOM on the server pass:

```ts
const [stored, setStored] = React.useState<SectionMap>(() =>
  typeof window === 'undefined' ? {} : readStored(drawerType),
)
```

`AppCreateDrawer`/`AppEditDrawer`/`AppViewDrawer` are indeed always
mounted in `apps-table.tsx` (not conditionally rendered on `open`), so
the hook does run on every render regardless of whether the drawer is
visible. **Traced further and confirmed this is not a bug**: all three
drawers wrap their content in `@sassy-auth/ui`'s `Sheet`
(`packages/ui/src/components/ui/sheet.tsx`), built on Radix's
`Dialog.Primitive`. Radix's `Dialog.Content` renders nothing into the DOM
at all while `open={false}` (no `forceMount`) — so the `isOpen()` values
the hook computes never reach the server-rendered or first-hydrated DOM
in either case; both passes render nothing for the closed drawer. No
visible mismatch, no React hydration warning. Verified rather than filed.
