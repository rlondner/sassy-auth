**Files:**

**Branch / PR:** `bug-0299` / [PR #468](https://github.com/rlondner/sassy-auth/pull/468) — not `dev`. The breakage does not exist on `dev` itself (which is still pinned to the vulnerable pre-bump versions); it is entirely contained in the still-open fix PR, so no new PR against `dev` was opened for this — fixing it means pushing to the existing `bug-0299` branch, not duplicating a parallel PR for code that doesn't exist on `dev` yet.

**Description:** PR #468 bumps `better-auth` `1.6.11 → 1.7.7` (and
`@better-auth/utils` `0.4.0 → 0.5.1`) to patch CVE-2026-114607 (OAuth
state reusable as a Magic Link). That bump has two independent breaking
effects, both currently failing the PR's own CI:

1. **`nest build` fails to compile (`admin-e2e` and implicitly any
   consumer of the build output).** Nine TypeScript errors:
   - `auth.config.ts` lines 232, 266, 372, 427: the `after` hook
     signatures for `databaseHooks.user.create` and
     `databaseHooks.session.create` now receive a `GenericEndpointContext
     | null` second argument instead of the old
     `{ path?: string; params?: Record<string,string> } | null` shape —
     the existing handler signatures no longer satisfy better-auth
     1.7.7's stricter inferred types.
   - `auth.config.ts:629`, `registration.service.ts:449`,
     `registration.service.ts:475`, `registration.service.ts:526`,
     `main.ts:258`: `auth.api.createVerificationOTP`,
     `checkVerificationOTP`, `verifyEmailOTP`, and
     `generateOpenAPISchema` no longer exist on the inferred `auth.api`
     type. TypeScript's suggestion for `verifyEmailOTP` ("Did you mean
     `verifyEmail`?") implies the email-OTP plugin's exposed endpoint
     names changed shape in 1.7.x, not just signatures — this needs to be
     checked against the plugin actually configured in `auth.config.ts`,
     not pattern-matched blindly, because these calls sit directly in
     the registration/email-verification flow.

2. **`unit-tests` can't even load `verify-user-totp.spec.ts`.**
   `@better-auth/utils@0.5.1`'s `otp`/`hmac`/`hex` CJS wrappers
   transitively `require()` `@noble/hashes@2.2.0`, which ships
   ESM-only (`"exports"` has no `require` condition, source uses bare
   `export function ...`). `apps/auth-server/package.json`'s `jest`
   config has no `transformIgnorePatterns` override, so Jest's default
   (`/node_modules/`) leaves that file untransformed and the CJS
   `require()` call chokes with `SyntaxError: Unexpected token 'export'`.
   5 of 110 test suites fail this way; 47 of 1118 tests fail overall
   (`gh run view 42875751005 --log-failed`, job on PR #468 @
   2026-11-10T18:30, unchanged as of this review's re-check).

**Why this matters beyond "a PR is red":** TODO_2026-11-10.md's "Closed
out this run" section stated bug-0299 was "Fixed in PR #468 ... Verified
via lint/build/test on admin and auth-server." That claim is contradicted
by the PR's own `gh pr checks 468` output, which has shown `admin-e2e
fail` / `unit-tests fail` since the PR's creation commit — there is no
run where it was ever green. The CVE fix is real and necessary, but it
has not actually been verified, and is not mergeable as-is. Until it
merges, the four CRITICAL CVEs documented in bug-0299 remain live on
`dev`, now for a second day past when they were first "closed out."

**Failure scenario:** none on `dev` today — `dev` never received this
bump. The risk is process, not runtime: if PR #468 were merged as-is (or
force-merged past red CI), `nest build` would fail outright in
production deploys, and the auth-server would not boot.

**Fix:**
1. **Applied in this run**, pushed directly to the `bug-0299` branch
   (commit `ec223c6`, PR #468): added a `pnpm.overrides` entry pinning
   `@noble/hashes` to `^1.8.0` (the same mechanism PR #468 already uses
   for `dompurify`), so `@better-auth/utils@0.5.1` resolves against a
   `require()`-compatible hash implementation instead of the ESM-only
   `2.2.0`. Verified locally: `jest auth/verify-user-totp.spec.ts` goes
   from "Test suite failed to run" to `PASS`, and the full
   `auth-server` suite goes from 5 failing suites to 3 — the remaining
   3 (`auth.config.spec.ts`, `registration.service.spec.ts`,
   `registration.controller.spec.ts`) are exactly the API-surface break
   below, left untouched.
2. **Still open — the OTP/OpenAPI API-surface break.** Open
   `node_modules/.pnpm/better-auth@1.7.7*/node_modules/better-auth`'s
   shipped `.d.ts` (after installing the bump) to find the current
   email-OTP plugin's actual exposed endpoint names, and update the four
   call sites in `auth.config.ts`, `registration.service.ts`, and
   `main.ts` accordingly — including re-checking whether
   `generateOpenAPISchema` moved to a different plugin export rather
   than being removed outright.
3. Update the hook signatures at `auth.config.ts:232`/`266` to accept
   `GenericEndpointContext | null` and adjust any internal use of
   `ctx.path`/`ctx.params` to whatever `GenericEndpointContext` exposes
   for the same data.
4. Re-run `pnpm --filter auth-server build` and
   `pnpm --filter auth-server test` locally before re-pushing — not just
   trusting a PR description. (Step 1's fix above *was* verified this
   way; step 2 still needs the same discipline before it's called done.)
