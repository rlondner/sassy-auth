## bug-0308: `trust proxy` hop count is hardcoded, silently wrong for any topology other than Render's

**Fixed:** false

See [bug-0308.md](./bug-0308.md) for the full writeup (filed and fixed together in PR #485).

Summary: `apps/auth-server/src/main.ts` hardcoded Express's `trust proxy` setting to `1` hop,
correct only for Render. GCP's optional external HTTPS Load Balancer (`gcp/setup-lb.sh`) would
add a second hop if ever put in front of Cloud Run instead of using domain mappings directly —
silently collapsing every client's rate-limit bucket onto the load balancer's own address (the
same symptom class as `CR_2026-09-02.md`'s finding). No live impact today since neither
deployment uses a second hop yet; this is a latent configuration bug. Fixed by making the hop
count configurable via a new `TRUST_PROXY_HOPS` env var.
