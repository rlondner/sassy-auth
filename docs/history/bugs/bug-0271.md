# bug-0271: apps/admin declares React 18 while every login form requires React 19

**Severity:** Warning
**Status:** Open
**Fixed:** false

## Description

`apps/admin/package.json` declared `"react": "^18.3.0"`, `"react-dom": "^18.3.0"`,
`"@types/react": "^18.3.0"` — but `LoginForm`, `LoginOtpForm`, and `TwoFactorForm`
(`apps/admin/app/login/**`) all call `useActionState`, a React 19-only hook, and wire
submission through a function-valued `<form action={fn}>`, a React 19-only DOM
integration. React 18.3.1 exports neither.

The app never crashed because Next 15 vendors its own internal copy of React 19 at
`next/dist/compiled/react` and aliases the `react` import to it at build/dev time —
the declared workspace dependency is never actually what runs in the browser or on the
server. Typecheck passed too, because `@types/react@18.3.29` back-ports `useActionState`
into its ambient `canary.d.ts`. Nothing in the normal dev loop (`next dev`, `next build`,
`tsc --noEmit`) exercises the *declared* React version — only something that resolves
`react` via plain Node module resolution (Jest) does.

That is exactly what happened: `apps/admin/app/login/__tests__/login-forms.test.tsx`
(22 cases covering all three login forms) was added today already wrapped in
`describe.skip`, with a comment explaining Jest resolves the declared 18.3.1 and the
components silently no-op under it — confirmed by the test author with a direct probe
(0 calls to the form's `action` function, DOM `action` attribute rendered `null`). The
gap has been live since these forms were built; today is only the first time anything
tried to render them outside Next's bundler and surfaced it.

## Impact

The three components a user actually authenticates through had **zero automated test
coverage** for credential submission, OTP request/verify, TOTP/backup-code paths, or the
2FA redirect — masked by a green typecheck and a working dev server. It is also a latent
packaging risk: anything that resolves `react` through normal module resolution instead
of Next's webpack alias (a different test runner, a Storybook config, an SSR tool, a
future Next major that stops vendoring React) inherits a React major-version mismatch
with no compile-time signal.

`packages/ui`'s own `devDependencies` had the identical pin (`react@^18.3.0`) despite its
`peerDependencies` already declaring `"react": "^18 || ^19"` — so simply bumping
`apps/admin` alone reproduces the "React Element from an older version of React was
rendered" duplicate-copy error at test time, because pnpm materializes two separate
React installs for the two packages. Both had to move together.

## Files

- `apps/admin/package.json` — `react`/`react-dom`/`@types/react`/`@types/react-dom`
- `packages/ui/package.json` — same four, in `devDependencies`
- `apps/admin/app/login/__tests__/login-forms.test.tsx` — the blocked suite

## Fix

Bump `apps/admin` and `packages/ui`'s React packages to `^19.0.0` (matching what
actually runs) and reinstall so pnpm dedupes to a single React copy across the
workspace. Un-skip the three `describe` blocks.

Doing so also surfaced a second, pre-existing defect the skip had hidden: two of the
`TwoFactorForm` cases asserted the trust-device checkbox defaults to *unchecked*, but
`TwoFactorForm.tsx:14` initializes `useState(true)` — the checkbox is pre-checked by
design. The cases were rewritten to assert the actual (evidently intentional) default
and to exercise the untick path instead of a stale assumption never previously run.

Verified: `pnpm --filter @sassy-auth/admin test` — 47 suites / 409 tests pass (was 46
suites / 387 tests with this one skipped). `pnpm --filter @sassy-auth/ui test` — 4/4
suites pass. `tsc --noEmit` in `apps/admin` shows the same 5 pre-existing errors before
and after this change (missing `createdAt`/`lastLoginAt` on two unrelated test fixtures,
and `@jest/globals` resolution in two other specs) — confirmed by diffing `tsc` output
with and without this fix stashed; none are introduced by the React bump.
