# bug-0284: `typecheck`/`unit-tests`/`e2e` CI never runs on push to `dev`

**Fixed:** false

## Summary

`.github/workflows/{typecheck,unit-tests,e2e}.yml` all trigger on
`pull_request` against `[master, dev]`, but on `push` only to `[master]`.
Direct pushes/merges to `dev` (its normal integration branch, per this repo's
own convention of `feat/*` → `dev` → `master`) never run these checks unless a
PR happens to also be open against `dev` at the same time.

## Impact — this is not hypothetical, it already caused real damage

This exact gap is why bug-0282 and bug-0283 sat on `dev` undetected:

- bug-0282 (`app/signup/page.tsx` invalid export, breaks `next build`) landed
  2026-09-05 and was invisible until PR #378 opened against `dev` on
  2026-09-08 — 3 days of a broken build with zero CI signal.
- bug-0283 (`roles/page.tsx` missing `App` fields) has been present since
  before 2026-09-01 (earliest visible `typecheck` run on `dev` in Actions
  history) with the same invisibility.

Both bugs independently block `next build`, so `admin-e2e` and `typecheck`
were both silently broken on `dev` this entire time. This is the same failure
shape documented repeatedly for `master` (e.g. the 34-day e2e freeze noted in
the 2026-08-19 daily review, and the 2026-08-27 `unit-tests` 2-day silent red)
— `dev` has the identical exposure and no one had fixed it there yet.

## Fix

Add `dev` to the `push.branches` list in `e2e.yml`, `typecheck.yml`, and
`unit-tests.yml`, matching their existing `pull_request` scope. `dev` now
gets the same CI signal on every push that `master` already has.

## Verification

- YAML diff reviewed — only the `push.branches` array changed, no other
  workflow behavior affected.
- Not runnable locally (GitHub Actions triggers), but the change is
  minimal and mechanical; correctness will be visible on the next push to
  `dev` (this PR's own merge, or the next one).
