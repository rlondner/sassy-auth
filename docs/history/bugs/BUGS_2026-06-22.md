## :yellow_circle: bug-0112 -- French toast i18n strings are untranslated English

**Fixed:** false
**Severity:** Warning
**File:** `apps/admin/messages/fr.json` (lines 83-87, 163-167, 224-228, 305-309, 398-403)

**Description.** All 15 toast strings in `fr.json` are identical to their `en.json` counterparts: "App created", "App updated", "App deleted", "Org created", etc. A French-locale user triggering any CRUD operation sees English-only toast messages. The toast keys were added in a prior commit but the French translations were never filled in. This affects: `apps.toast.*` (3), `orgs.toast.*` (3), `permissions.toast.*` (3), `roles.toast.*` (3), `users.toast.*` (4 — created/updated/deleted/resent).

**Fix sketch.** Translate the 15 strings:
- `apps.toast.created` → "Application créée"
- `apps.toast.updated` → "Application mise à jour"
- `apps.toast.deleted` → "Application supprimée"
- `orgs.toast.created` → "Organisation créée"
- `orgs.toast.updated` → "Organisation mise à jour"
- `orgs.toast.deleted` → "Organisation supprimée"
- `permissions.toast.created` → "Permission créée"
- `permissions.toast.updated` → "Permission mise à jour"
- `permissions.toast.deleted` → "Permission supprimée"
- `roles.toast.created` → "Rôle créé"
- `roles.toast.updated` → "Rôle mis à jour"
- `roles.toast.deleted` → "Rôle supprimé"
- `users.toast.created` → "Utilisateur créé"
- `users.toast.updated` → "Utilisateur mis à jour"
- `users.toast.deleted` → "Utilisateur supprimé"
- `users.toast.resent` → "Invitation renvoyée"

**Tests needed.** Render any create/edit/delete drawer in French locale and verify the toast text is in French.

## :large_blue_circle: bug-0114 -- Unhandled refresh errors after successful mutations in admin tables

**Fixed:** false
**Severity:** Minor
**File:** `apps/admin/components/apps-table.tsx`, `orgs-table.tsx`, `permissions-table.tsx`, `roles-table.tsx` — uncommitted working tree changes

**Description.** After a successful create/update/delete, each table calls `await refresh()` to re-fetch list data from the server. If the `refresh()` call fails (server action throws, network error, auth session expired), the error is unhandled — the success toast has already been shown but the table displays stale data with the old item still visible (or the newly created item missing). The user may attempt the same mutation again, hitting a "not found" or "already exists" error.

The `UsersTable` uses `router.refresh()` which is fire-and-forget and does not throw, so it is not affected by this pattern.

**Fix sketch.** Wrap `refresh()` calls in try/catch and show a `toast.error(t('common.refreshFailed'))` or similar on failure, so the user knows to manually reload the page.

**Tests needed.** Unit test: mock `listAppsAction` to throw after a successful `deleteAppAction` — verify an error toast appears (or the page doesn't silently show stale data).
