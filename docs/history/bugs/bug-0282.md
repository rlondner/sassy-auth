# bug-0282: `app/signup/page.tsx` exports a non-page symbol, breaking `next build` on `dev`

**Fixed:** false

## Summary

`apps/admin/app/signup/page.tsx` exports `fetchAppInfo` as a named export
alongside the default page component. Next.js's App Router validates that a
`page.tsx` file only exports the small allow-list of symbols it recognizes
(the default component, `dynamic`, `generateMetadata`, etc.) — an arbitrary
extra export fails that validation with:

```
app/signup/page.tsx
Type error: Page "app/signup/page.tsx" does not match the required types of a Next.js Page.
```

This is a hard build failure (`next build` exits 1), not a lint warning.

## Impact

- `admin-e2e` CI (which runs `next build` before starting Playwright) has been
  red on every run since the function was introduced.
- Any production deploy of `apps/admin` from `dev` would fail the same way.
- The failure was invisible because `.github/workflows/e2e.yml` only triggers
  on `push` to `master` and on pull requests — `dev` had no open PRs between
  2026-09-05 (when the function landed) and 2026-09-08 (when PR #378 opened
  against `dev` and surfaced it in CI for the first time).

## Root cause

Introduced in `bf8924f` (`feat(admin): add /signup page`, 2026-09-05) and kept
through `63c5e31` (`test(admin): cover companyName-omission payload shape and
fetchAppInfo's fallback behavior`), which added a unit test importing
`fetchAppInfo` directly from `../page`. That import made it convenient to keep
the function inside `page.tsx`, but Next's page-export contract doesn't allow
it.

## Fix

Move `fetchAppInfo` into a plain module, `apps/admin/app/signup/fetch-app-info.ts`,
imported by both `page.tsx` and its test. `page.tsx` now only exports
`dynamic` and the default `SignupPage` component, matching every other page
in the app (`oauth-error`, `reset-password`, `login`, etc.).

## Verification

- `next build` (matching the `admin-e2e` CI step) now compiles past
  `app/signup/page.tsx`. It still fails on `app/(admin)/roles/page.tsx`,
  a separate, pre-existing issue — see bug-0283.
- `npx jest app/signup/__tests__/page.test.tsx` — 4/4 passing against the new
  module path.
