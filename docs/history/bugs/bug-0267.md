# bug-0267: README/env templates advertise GitHub as a social provider that isn't wired up

**Severity:** Minor
**Status:** Open
**Fixed:** false

## Description

Yesterday's social-authentication feature (`ab909c2`, "invite-only social
authentication with Google, Microsoft and Apple") implements exactly three
providers: `apps/auth-server/src/social/build-social-providers.ts` only ever
registers `google`, `microsoft`, and `apple` (`GOOGLE_KEYS`/`MICROSOFT_KEYS`/
`APPLE_KEYS`), and `docs/social-auth-setup.md` (the setup guide added in the
same commit range) documents exactly those three and no others.

But `README.md` still claims GitHub is a fourth supported provider in two
places ("Social login is limited to the providers BetterAuth supports
(Google, Microsoft, Apple, GitHub)" and the OAuth-flow description), the
README's env var table lists `GITHUB_CLIENT_ID`/`GITHUB_CLIENT_SECRET` as
real config, `.env.example` has the same two vars sitting inside the social
providers block with no comment marking them as unimplemented, and
`turbo.json`/`.flox/env/manifest.toml` both carry the same two vars in their
env passthrough lists. An operator who sets `GITHUB_CLIENT_ID`/
`GITHUB_CLIENT_SECRET` expecting a working GitHub sign-in button gets
silence — `hasAll(env, GITHUB_KEYS)` doesn't exist, there is no `GITHUB_KEYS`
constant, nothing reads these vars anywhere in application code.

## Impact

Low — no functional break, but the docs actively promise a capability that
does not exist, which is worse than omitting it: an operator following
`.env.example` has no signal that these two vars are dead.

## Files

- `README.md:176` ("What SassyAuth is not")
- `README.md:507` (OAuth flow description)

- `.env.example:39-40` (removed)
- `turbo.json:41-42` (removed)
- `.flox/env/manifest.toml:93-94` (removed)

## Fix

Remove the two dead `GITHUB_CLIENT_ID`/`GITHUB_CLIENT_SECRET` entries from
`.env.example`, `turbo.json`'s env passthrough list, and
`.flox/env/manifest.toml`; correct the two README lines that named GitHub as
a supported provider. Applied in this PR.
(`.flox/env/manifest.lock` is Flox-generated from `manifest.toml` and left
untouched — it resyncs on the next `flox` activation/edit rather than being
hand-patched.)
