## :yellow_circle: bug-0115 -- `resolveIssuer()` accepts any string without URL validation

**Fixed:** false
**Severity:** Warning
**File:** `apps/auth-server/src/token/oauth-metadata.ts` (lines 30-35)

**Description.** The new `resolveIssuer()` function strips trailing slashes from `BETTER_AUTH_URL` but does not validate that the result is a syntactically valid absolute URL. This means:

- `BETTER_AUTH_URL=""` (empty string) → issuer becomes `""`, producing malformed discovery docs and JWT `iss` claims
- `BETTER_AUTH_URL="   "` (whitespace) → issuer becomes `"   "` (untrimmed whitespace)
- `BETTER_AUTH_URL="not-a-url"` → issuer becomes `"not-a-url"`, a non-routable value
- `BETTER_AUTH_URL="ftp://wrong-protocol.example.com"` → accepted without warning

The `DiscoveryController` constructor warns when `BETTER_AUTH_URL` is **unset** (line 15), but does not warn or validate when it is **set to an invalid value**. This is the more dangerous case — an operator who sets the variable may assume it was validated.

The issuer value appears in two critical outputs:
1. The `/.well-known/oauth-authorization-server` discovery document (`issuer` field)
2. Every issued JWT (`iss` claim)

RFC 8414 §2 requires the issuer to be a URL using the `https` scheme (or `http` for localhost). OAuth clients perform exact string comparison on the issuer, so a malformed value will silently break all token verification.

**Fix sketch.** Add URL validation in `resolveIssuer()`:

```typescript
export function resolveIssuer(): string {
  const raw = process.env.BETTER_AUTH_URL ?? ISSUER_PLACEHOLDER;
  const normalized = stripTrailingSlash(raw.trim());
  try {
    const url = new URL(normalized);
    if (!['http:', 'https:'].includes(url.protocol)) {
      throw new Error(`unsupported protocol: ${url.protocol}`);
    }
    return normalized;
  } catch (e) {
    throw new Error(
      `BETTER_AUTH_URL is not a valid HTTP(S) URL: "${raw}" — ${(e as Error).message}`,
    );
  }
}
```

This provides a clear startup error when the value is misconfigured, rather than silently propagating invalid issuer values to all OAuth clients.

**Tests needed.** Unit tests in `oauth-metadata.spec.ts`:
- `resolveIssuer()` throws when `BETTER_AUTH_URL` is an empty string
- `resolveIssuer()` throws when `BETTER_AUTH_URL` is whitespace
- `resolveIssuer()` throws when `BETTER_AUTH_URL` is a non-URL string
- `resolveIssuer()` throws when `BETTER_AUTH_URL` uses an unsupported protocol
- `resolveIssuer()` trims surrounding whitespace before validation
