## Observed, not filed as a bug

- **🟢 LOW — `TWO_FACTOR_PROMPT_ENABLED` fail-open parsing accepts any
  non-`"false"`/`"0"` string, including typos** (e.g. `flase`, `off`,
  `no` are silently treated as "enabled"). `apps/auth-server/src/auth/resolve-trust-days.ts:63-67`.
  This is the documented fail-open design, not a logic error, so not
  filed as a bug — but a misconfigured deploy that intends to disable
  the prompt fleet-wide could silently fail to do so. Worth a
  startup-time warning log when the raw value is neither empty/undefined
