# bug-0286 🟡 Medium — `fr.json` missing 10 translation keys present in `en.json`

**Files:**
- `apps/admin/messages/fr.json`
- `apps/admin/messages/__tests__/messages-parity.test.ts`

**Description:** Diffing every flattened key between `apps/admin/messages/en.json`
and `apps/admin/messages/fr.json` found 10 keys present in `en.json` with no
French counterpart:

- `login.error.unverified`
- `users.status.unverified`
- `apps.fields.defaultOrg`, `defaultOrgHint`, `defaultOrgNone`
- `apps.fields.defaultRole`, `defaultRoleHint`, `defaultRoleNone`
- `signup.errors.captchaRequired`, `captchaFailed`

This is the second time this exact bug class has shipped in the last few
commits — `fddd82f fix(admin): add missing signup.verified French
translations` fixed the same class of gap days ago, and it recurred because
nothing in CI or the test suite catches a key added to `en.json` without
its `fr.json` counterpart (or vice versa).

**Failure scenario:**
1. A French-locale user tries to sign in before verifying their email.
   `login-form.tsx` calls `t('error.unverified')` against the missing
   `login.error.unverified` key — with next-intl, a missing key renders a
   fallback/raw-path string instead of a translated sentence, so the user
   sees broken text instead of "please verify your email."
2. Any French-locale admin opens the Users table or a user's detail
   drawer for a user whose status is `unverified` — `users.status.unverified`
   is missing, same broken-fallback rendering, in a page admins view
   routinely.
3. A French-locale operator configuring an app's default-org / default-role
   self-serve-signup fields, or a French-locale user hitting the signup
   captcha, sees the same class of broken fallback text.

**Fix:** PR TBD. Added all 10 missing keys to `fr.json`, matching
`en.json`'s key ordering within each object. Also added
`apps/admin/messages/__tests__/messages-parity.test.ts`, a small Jest test
that flattens both locale files and asserts the key sets are identical —
this is the automated check the TODO from `BUGS_2026-09-08.md`/prior runs
recommended, so the bug class can't silently recur a third time.

**Verified:** A one-off Node script flattening both JSON files confirmed
zero remaining key differences in either direction. `npx jest
messages-parity` — 1/1 pass. (Full `apps/admin` typecheck was not run as
part of verifying this change since it currently fails on pre-existing,
unrelated issues in this checkout — missing `@marsidev/react-turnstile`
and `@jest/globals` type declarations, and `App`/`User` test-mock shape
drift predating this fix — none of which touch `messages/*.json`.)

**Fixed:** false
