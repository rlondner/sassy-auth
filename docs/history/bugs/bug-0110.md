# bug-0110: roles.service updateRole missing null check after findUnique in transaction

**Severity:** Minor
**File:** `apps/auth-server/src/roles/roles.service.ts` (lines 196-199)

Inside the `updateRole` transaction, `tx.saRole.findUnique(...)` can return `null` if the role was deleted by a concurrent request. The result is used without a null check.

**Fix:** Add `if (!updated) throw new NotFoundException('Role not found after update')`.

**Tests needed:** Unit test: mock `findUnique` returning `null` after `update` — should throw `NotFoundException`.
