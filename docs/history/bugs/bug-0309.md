# bug-0309: staging deploy dispatches on every push to `dev`, even when no app version was bumped

**Fixed:** false

## Where

`.github/workflows/version-bump.yml`, the `Dispatch staging deploy` step (added in
`b44b12a`, 2026-11-25, as part of the version-bump feature).

## What's wrong

The `bump` job's `Commit and push bump` step is correctly guarded with
`if: steps.bump.outputs.message != ''` — it only commits and pushes a version bump
when `scripts/bump-versions.mjs` actually bumped a deployed package
(`@sassy-auth/admin`, `@sassy-auth/admin-e2e`, `@sassy-auth/auth-server`).

The very next step, `Dispatch staging deploy`, has no such guard:

```yaml
- name: Dispatch staging deploy
  env:
    GH_TOKEN: ${{ github.token }}
  run: gh workflow run deploy-render-staging.yml --ref dev
```

It runs unconditionally on every push to `dev`, including pushes that touch
nothing in `BUMPABLE` — docs-only commits (this review's own daily-review PRs,
once merged), changes to `scripts/`, `.github/workflows/`, database migrations,
or any other workspace package. Each of those still triggers a full
`deploy-render-staging.yml` run that redeploys the exact same code with no
version change.

## Impact

- Wastes CI minutes and Render deploy time on every no-op push to `dev` (docs,
  CI config, non-deployed packages).
- Causes an unnecessary service restart/redeploy on staging for changes that
  have nothing to do with the deployed apps, which is the kind of surprise
  redeploy this feature was explicitly built to make *auto-bumped and
  predictable* for (see `6414f33`'s plan) — the dispatch step undercuts that by
  firing even when nothing was bumped.
- Today's own daily-review PR, once merged, would trigger exactly this: a
  docs-only push to `dev` that re-deploys staging for no reason.

## Fix

Gate the dispatch step the same way the commit/push step already is:

```yaml
- name: Dispatch staging deploy
  if: steps.bump.outputs.message != ''
  env:
    GH_TOKEN: ${{ github.token }}
  run: gh workflow run deploy-render-staging.yml --ref dev
```

Fixed in PR for `bug-0309`.
