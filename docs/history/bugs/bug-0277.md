# bug-0277 🟡 Medium — OIDC discovery doc advertises a logout endpoint that doesn't exist

**Files:**
- `apps/auth-server/src/token/oauth-metadata.ts`
- `apps/auth-server/src/token/oauth-metadata.spec.ts`

**Description:** The new `/.well-known/openid-configuration` document
(added `a220f2b`, `feat(oidc): serve /.well-known/openid-configuration`)
advertised `end_session_endpoint` pointing at
`/api/token/oauth/logout` (`OAUTH_LOGOUT_ROUTE`). No controller ever
registered that route — `TokenController` has `oauth/authorize`,
`oauth/token`, `oauth/userinfo`, `direct/login`, `jwks`, and
`app-trust-days`, but nothing for `oauth/logout`.

This isn't an oversight in this review's diff alone: the original design
doc (`docs/superpowers/plans/2026-08-21-oidc-compatibility.md`) specced a
full RP-Initiated Logout controller as its own task, including the
`assertPostLogoutRedirectUriAllowed` helper (which *did* ship, unused, in
`redirect-uri.ts`) and a `SaAppRedirectUri` `'post_logout'` kind (which
also shipped). Only the discovery advertisement and the unused helper
landed — the controller task itself never did.

**Failure scenario:** A conformant OIDC relying party reads
`/.well-known/openid-configuration`, sees `end_session_endpoint`, and
either (a) calls it during a "log out everywhere" flow and gets a 404, or
(b) advertises RP-Initiated Logout support to its own users based on this
server's discovery doc, promising a capability that silently fails at
runtime. This is exactly the "don't advertise a capability that isn't
real" class of bug the discovery doc is supposed to guard against —
`response_types_supported`, `grant_types_supported`, and
`claims_supported` were all cross-checked against the real implementation
during this review and are accurate; `end_session_endpoint` was the one
field that wasn't.

**Fix:** PR #370. Removed `end_session_endpoint` from
`OpenIdConfiguration` / `buildOpenIdConfiguration()` and the now-unused
`OAUTH_LOGOUT_ROUTE` constant, with a comment pointing at this bug so the
field is re-added deliberately (not by accident) once the logout endpoint
actually ships. `assertPostLogoutRedirectUriAllowed` and the
`'post_logout'` redirect-URI kind are left in place since they're the
groundwork for that future endpoint, not dead code in the same sense.

**Verified:** `npx tsc --noEmit` in `apps/auth-server` — no errors;
`npx jest --testPathPattern=oauth-metadata` — 14/14 pass, including a new
assertion that `end_session_endpoint` is absent from the doc;
`npx jest --testPathPattern="discovery.controller|token.controller"` —
46/46 pass (unaffected).

**Fixed:** false
