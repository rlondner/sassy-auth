## Activation webhook design (PR #378) — worth a security-minded look before merge

Skimmed but not deeply audited (out of today's scope, which focused on the
CI-red investigation): `SaApp.webhookUrl`/`webhookSecret` plus
`notifyActivation` delivery on email-verify/invite-accept/re-activation.
Two things worth someone's explicit attention on that PR specifically:
- Whether `webhookUrl` is validated the same way app `url`/`callbackUrl`
  already are (`SASSY_AUTH_ALLOW_INSECURE_APP_URLS`-gated https/public-host
  requirement) — an admin-configurable outbound webhook URL is a classic
  SSRF surface if it accepts arbitrary internal hosts.
- Whether the webhook delivery has a timeout/retry/backoff bound, so a
  slow or hanging endpoint on one app can't block the request path
  (email-verify, invite-accept) that triggers it.
Not verified either way — flagging for whoever reviews #378's own diff,
since this run's fixes (#379-#381) are scoped to the pre-existing CI
breakage, not the new feature itself.
