## Risky patterns (architectural)

- [ ] **TOCTOU in `resolveAppScopedIds`** — `resolvePermissionIdsForApp()` and `resolveRoleIdsForApp()` fetch permissions/roles by publicId then validate they belong to the target app. The `where` clause should include `appId` directly to combine lookup and validation in one query, preventing information leakage via timing and eliminating the theoretical race window.
- [ ] **Audit log asymmetry** — `assignRole()` logs the specific roleId; `setUserRoles()` logs only the count. Direct-permission set-replace doesn't log the permission IDs either. Audit logs should be consistent across all mutation paths.
- [ ] **Hardcoded `take: 50` in permission/role detail views** (carried from 2026-06-01) — `getPermission` and `getRole` silently truncate associated roles/users at 50.
- [ ] **Redundant count queries** (carried from 2026-06-01) — `getPermission` and `getRole` issue separate `count()` queries after fetching relations.
- [ ] **Agent worktree submodule artifacts** (carried from 2026-05-31, bug-0023) — still unfixed.
