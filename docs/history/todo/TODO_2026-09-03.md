**Review verdict: close to mergeable, not quite there.**

Found and fixed directly on the branch (pushed to `origin/feature/admin-signup`):
- **bug-0279** (Medium) — `GET /api/register/app` had no rate limiting and
  is a distinguishable-response enumeration oracle for `appPublicId`,
  contradicting its own docstring's claimed parity with
  `GET /api/social-providers`. Fixed: reused `RateLimitGuard`.
- **bug-0280** (High) — `RegisterDto.password` only required 8 characters
  with no complexity check, regressing the 12-char + upper/lower/digit
  policy `bug-0007` established elsewhere in this codebase and already
  displayed in `SignupForm`'s own client-side validation. Fixed: applied
  the same `MinLength(12)` + `Matches()` pattern used on
  `AcceptInvitationDto`.

Both fixes have new specs and pass `tsc --noEmit` — see
BUGS_2026-09-03.md for full writeups.

**Test coverage on the branch itself:** good, not perfect.
- `apps/admin/app/signup/__tests__/actions.test.ts` and
  `signup-form.test.tsx` cover the client action's error-status mapping and
  the form's client-side password validation/submit/success states.
- `apps/admin/app/login/__tests__/login-forms.test.tsx` covers the new

- `registration.controller.spec.ts` / `registration.service.spec.ts` cover
  the new `getAppName` service+controller and the firstName/lastName wiring
  into BetterAuth's `signUpEmail` `name` field and the `SaUser` row.
- **Gap, not filed as a bug:** no test asserts what happens when
  `POST /api/register` is called with `appPublicId` pointing at an app that
  has `disableSignUp`/invite-only social config, or any org-limit /
  multi-tenant constraint that might exist elsewhere in `SaApp`/`SaOrg`
  creation paths (e.g. is there a cap on orgs-per-app, or is uncapped
  self-serve org creation the intended design here?). Worth a design
  sanity-check before merge, not necessarily a bug — self-serve signup
  creating an org per signup is presumably the intended model, but it's
  worth someone with product context confirming there's no "invite-only
  app" flag this bypasses. Not verified against the actual `SaApp` schema
  in this run due to time; flagging as the one open question before merge
  rather than guessing.
- **No e2e coverage** for the `/signup` page itself (Playwright specs exist
  for `/login` and other admin flows per repo convention, but none were
  added for `/signup` on this branch). Given this is a new,
  publicly-reachable, unauthenticated form that creates real accounts and
  orgs, an e2e smoke test (happy path + the `appNotFound`/`emailTaken`
  error paths) would be worth adding before merge.
- **i18n**: `en.json`/`fr.json` additions are complete and parallel — no
  gap found there.

**Recommendation:** merge-ready from a correctness standpoint once the
above two bugs are picked up (now fixed on the branch); the org-creation
design question and e2e coverage are the two things worth resolving before
merge, not blockers to keep reviewing further.
