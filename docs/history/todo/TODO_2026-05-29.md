## Risky patterns (architectural)

- [ ] **Origin forwarding via Referer fallback** — `auth-origin.ts:10` falls back to `Referer` when `Origin` is absent. Referer is user-controlled in browsers and may leak path info. The current `.origin` extraction mitigates injection, but consider removing the Referer fallback or documenting why it's needed.
- [ ] **Session validation on every middleware request** — `middleware.ts` calls `GET /api/auth/get-session` on every non-public request. This adds a network round-trip to every page load. Should investigate:
  - Short-lived JWT validation at the edge (no round-trip)
  - Session cache with TTL (e.g., 30s in-memory or cookie-based)
  - At minimum: measure P50/P99 latency impact of this pattern
- [ ] **No rate limiting on e2e-targeted endpoints** — The `/api/auth/sign-in/email` endpoint has no rate limiting. An attacker can brute-force credentials. This was noted in the auth-server previously but is now more visible because the e2e suite exercises it.
- [ ] **`webServer` in Playwright config uses `dev` mode** — The CI e2e workflow starts both servers with `pnpm dev`, which means Next.js and NestJS run in development mode. This differs from production behavior (no `next build` / `next start`). Consider a `test` or `production` mode for CI.

## Configuration / ops follow-ups

- [ ] **`.env.example` missing e2e vars** — `E2E_ADMIN_EMAIL`, `E2E_ADMIN_PASSWORD`, `CI_TESTS`, `TRUSTED_ORIGINS` are not in `.env.example`. Operators and CI must discover these from workflow/config files.
- [ ] **`.auth/` not gitignored in admin-e2e** — `apps/admin-e2e/.auth/super-admin.json` (Playwright storage state) is not gitignored. If a developer runs the auth-state setup locally, the session state file could be committed.
- [ ] **Turbo `test:e2e` env passthrough** — `turbo.json` passes through `RSA_PRIVATE_KEY` and `RSA_PUBLIC_KEY` in the env list, which is correct for CI. Ensure these are never logged by Turbo's output.
- [ ] **ADMIN_URL env var defaulting** — `apps/admin-e2e/playwright.config.ts:6` defaults to `http://localhost:3001`, same as the admin `package.json` dev port. If someone runs admin on a different port, e2e tests fail silently.
