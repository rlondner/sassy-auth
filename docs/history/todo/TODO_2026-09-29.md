## `render.staging.yaml`'s COOKIE_DOMAIN comment documented a real bug as an accepted quirk

See [BUGS_2026-09-29.md#bug-0293](../bugs/BUGS_2026-09-29.md#bug-0293--medium--staging-and-production-session-cookies-collide-in-the-same-browsers-cookie-jar)
for the full writeup and fix (PR #436). Worth calling out the process gap
on its own: the commit that introduced the collision (`5329d1e`) *also*
wrote a code comment correctly describing the exact failure mode ("A
browser that has an active session cookie from BOTH environments will only
keep whichever one it set/received most recently") and then shipped it
anyway as a "UX quirk, not a security issue." That's a fair call on
severity, but the fix (a distinct `COOKIE_PREFIX`) is small enough that it
should have been in scope for the same PR rather than deferred to the next
day's review. No action needed beyond the fix already opened — just a
pattern worth naming: a self-diagnosed bug in a code comment should either
get fixed in the same PR or get filed as a tracked bug immediately, not
left as an inline comment for the next reviewer to rediscover.
