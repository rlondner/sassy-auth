## `packages/db/index.ts`'s eager `DATABASE_URL` throw — local dev ergonomics

See BUGS_2026-09-04.md "Verified — not filed". Not a bug, but worth
documenting: a developer running `pnpm --filter @sassy-auth/auth-server
test` (or any suite that transitively imports `@sassy-auth/db`) without
`DATABASE_URL` exported in their shell will now get a hard failure at
import time, even though nothing in the unit suites touches a real
database. The root README's "Configure environment variables" step
already tells developers to populate `.env.local`, but Jest doesn't load
it automatically for unit specs (only the e2e-spec suite does, via
explicit `dotenv` config). A one-line README callout ("unit tests need
`DATABASE_URL` set in your shell, not just `.env.local`") or a Jest
`setupFiles` entry that loads `.env.local` would close this gap.
