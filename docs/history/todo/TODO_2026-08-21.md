## Minor hardening, not worth their own bug entries

Surfaced by [CR_2026-08-21](../code-reviews/CR_2026-08-21.md), an earlier
same-day review pass recovered and merged into this run (see the
"Housekeeping" item below):

- **`b5ad862`'s three new `429 → tooManyRequests` branches
  (`apps/admin/app/login/actions.ts`) have no unit test coverage.** The fix
  itself is correct and already on `master`; a follow-up test stubbing
  `fetch` to return 429 on each of the three credential paths would lock
  the behavior in.
- **`e253d81` interpolates the trust-device cookie value into a raw
  `Cookie:` header** (`` `better-auth.trust_device=${trustCookie.value}` ``)
  without validating it first. The value is BetterAuth-written and
  `undici`'s fetch already rejects CRLF in header values, so this isn't
  currently exploitable — but validating/encoding the value before
  interpolation would be a cheap defense-in-depth improvement if anyone
  touches this code again.
