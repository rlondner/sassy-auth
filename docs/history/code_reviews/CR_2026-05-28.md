### feat/apps-admin-ui (worktree) — proxy for an open PR
- **Author:** Raphael Londner (with `Co-Authored-By: Claude`)
- **Files changed:** 43 — **+1977 / -59**
- **Scope:** New `apps` REST module (NestJS), `/me/permissions` endpoint, admin UI for App CRUD (Next.js server actions + table + drawers), shared `ConfirmDialog` UI primitive, `SaApp.name` unique migration, FR/EN i18n.
- **Findings:**

  🔴 **Critical — none.**

  🟡 **Warning**
  1. **`AppsService.createApp` writes a literal `"placeholder"` then re-encodes via Sqids inside a `$transaction`.**
     `apps/auth-server/src/apps/apps.service.ts:40-46`
     Same anti-pattern as bug-0005 — there is no unique constraint on `SaApp.publicId`'s placeholder, but the new `@unique` constraint on `SaApp.name` plus an interrupted transaction would leave a `publicId='placeholder'` row only if the txn commits before the update, which it cannot. Still fragile: if two `createApp` calls hit the same Postgres connection and the `update` step fails for any reason (e.g. Sqids throws), the row was never seen outside the tx — fine. But the helper would silently collide if you ever lower the isolation level or extract the create outside the tx. Consider deriving the id deterministically (insert with `DEFAULT` then `RETURNING id`) and passing `{ publicId: this.sqids.encode(id) }` to a single `create` with `id` pre-allocated via a sequence read, or wrap the placeholder in a UUID-like sentinel to avoid any possibility of a duplicate `"placeholder"` row appearing under non-default isolation.
  2. **Error → i18n key mapping in `actions.ts` parses error strings (`message.includes('403')`, `.includes('own')`).**
     `apps/admin/app/(admin)/apps/actions.ts:11-22`, `apps/admin/app/(admin)/users/actions.ts:33-39`
     Substring matching on a server-formatted error message is brittle — i18n on the auth server, a thrown `Error` whose `.message` changes shape, or an upstream HTTP framework that wraps the status code differently will silently degrade to `generic`. Prefer surfacing a typed error code (e.g. `apiFetch` throws a `class ApiError { status: number; code?: string }`) and switch on `status`/`code`.
  3. **`copyToClipboard` swallows errors and returns `false` silently.**
     `apps/admin/lib/clipboard.ts`
     No telemetry breadcrumb, no user feedback when the Permissions API denies write — the UI will show the "copied" check anyway because the call sites assume success and run `onCopied?.()` only when the promise resolves, but a denied permission rejects so the user gets no feedback at all. Add a Sentry breadcrumb and surface a transient error toast on `false`.
  4. **`AppsTable` re-fetches via a `setTimeout(300)` debounce but does not cancel an in-flight `listAppsAction` when inputs change again.**
     `apps/admin/components/apps-table.tsx:39-49`
     Stale-response race: rapid typing can land an older response after a newer one, showing wrong data. Track a request id (ref counter) and ignore responses whose id is not the latest, or use `AbortController` through the server action.
  5. **`AppCreateDrawer` / `AppEditDrawer` trim only on submit, not on `IsUrl` client-side validation.**
     `apps/admin/components/app-create-drawer.tsx:36-44`
     A user pasting `"  https://x.com  "` will pass the HTML `type="url"` check, then the server `IsUrl` validator rejects, returning a `400` mapped to `apps.errors.urlInvalid`. Low-severity UX bug; trim onChange or on blur.
  6. **`AppEditDrawer` allows submitting empty-but-trimmed name (`name.trim() === ''`) without client-side guard.**
     `apps/admin/components/app-edit-drawer.tsx:31-41`
     Server `MinLength(1)` catches it, but the drawer should mirror the `AppCreateDrawer.nameRequired` check for consistent UX.
  7. **`callerBaId(req)` casts `req` via `Record<string, { id: string }>` and dereferences `betterAuthUser.id` without null check.**
     `apps/auth-server/src/apps/apps.controller.ts:9-11`, `apps/auth-server/src/me/me.controller.ts:6-8`
     If `BetterAuthGuard` is ever bypassed (misconfigured `@UseGuards` on a new method) the call throws an unstructured `TypeError` and Sentry gets noise instead of a 401. Centralize into a `@CurrentBaUser()` decorator that throws `UnauthorizedException` when the property is missing.
  8. **`MeService.getMyPermissions` fans out 4 nested includes for every call.**
     `apps/auth-server/src/me/me.service.ts:12-19`
     For a user with many roles this is `roles × permissions` rows + `directPermissions` rows. Acceptable today, but `/me/permissions` is hit on every page navigation in the admin app — add a short-lived cache (e.g. `Cache-Control: private, max-age=30` on the controller, or in-memory LRU keyed on `betterAuthUserId`). Also: the function throws `ForbiddenException` when the user doesn't exist; that should be `UnauthorizedException` — the caller is authenticated to BetterAuth but has no SaUser row.
  9. **`AppViewDrawer` `onDelete` resets `deleteError` only in the parent's `onDelete` callback closure, not when reopening the dialog independently.**
     `apps/admin/components/apps-table.tsx:147-150`
     If the user dismisses the dialog and reopens via the row dropdown, the previous error stays in state because `setDeleteError(null)` only runs when re-entering through the view drawer's button. Reset `deleteError` on `setDeleteOpen(true)` everywhere.
  10. **`ConfirmDialog` swallows non-Error throws as `'Action failed.'` and rethrows nothing.**
      `packages/ui/src/components/confirm-dialog.tsx:46-52`
      The `AppsTable.handleDelete` `throw new Error(msg)` pattern depends on this — fine — but the `error` prop (`errorProp`) takes precedence over `internalError`, so once `setDeleteError` runs in the parent, the dialog's internal error is masked. Document this contract or unify the two paths.

  🟢 **Clean**
  - DTOs use `class-validator`, are `whitelist: true`-safe, restrict URL protocols to `http`/`https` after the prior review pass (good fix on `0744fb0`).
  - `updateApp` correctly removed the bypassable `_atLeastOne` DTO trick and enforces server-side in service.
  - `apps/page.tsx` uses `Promise.allSettled` so a permissions API hiccup degrades to `AccessDeniedPanel` rather than a 500. Reasonable resilience choice.
  - Test files added for `AppsService` (`apps.service.spec.ts`, 177 lines), `MeService`, `ConfirmDialog`, and all four admin drawers. Coverage parity with new code is good.
  - `apps/auth-server/src/apps/dto/list-apps-query.dto.ts` clamps `pageSize ≤ 100` — prevents DoS via large page reads.
  - i18n keys are present in both `en.json` and `fr.json` (no missing-translation runtime warnings).

- **Recommendation:** **Request Changes** — address 🟡#1 (createApp placeholder pattern), #2 (typed error codes), and #4 (race-condition on debounced refetch) before merging. The rest can land as follow-ups.

### fix/bug-0005-publicid-sqids
- **Files changed:** 2 — **+59 / -7**
- **Scope:** Restores Sqid encoding for `SaUser.publicId` and `SaInvitation.publicId`, replacing the prior `baUserId.slice(0,12)` / `.slice(12,24)` hack with a two-step create-then-update inside a transaction.
- **Findings:**

  🟡 **Warning**
  1. **Two-phase publicId issuance leaks the temporary value as a unique row.**
     `apps/auth-server/src/users/users.service.ts:147-181`
     Same concern as the apps service: `publicId: tmp_${baUserId}` and `publicId: tmp_${token}` rely on `baUserId` and `token` being unique. They are (random/UUID), so a collision is statistically impossible. But the column lacks a check constraint forbidding the `tmp_` prefix, and if the encode-step fails the `tmp_…` row stays alive when the path is outside a transaction. The first block is inside `$transaction` — safe. The second block in `resendInvitation` is also wrapped in `$transaction` (good). Verify the same wrapping at every other call site that hits `publicId`.
  2. **`crypto.randomUUID().slice(0, 12)` was removed from `resendInvitation` but the test spec coverage of the new flow is the only protection against regression.** Add an integration test that asserts the `publicId` matches the Sqid alphabet (`/^[A-Za-z0-9]+$/`, length ≥ project's minLength) for `SaUser` and `SaInvitation`.

  🟢 **Clean**
  - 28 lines of new spec coverage in `users.service.spec.ts` — TDD-style, good.
  - Encoding is now consistent with the project's canonical Sqid scheme.

- **Recommendation:** **Approve with follow-up** — file a tech-debt ticket for the `tmp_` placeholder anti-pattern (replace with `id` pre-allocation or a deterministic encode-from-known-sequence).
