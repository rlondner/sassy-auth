### 🟡 Warning

**W1 — In-memory PKCE state in resource-server-fastapi will not survive restart or horizontal scale**
`apps/resource-server-fastapi/app/oauth/routes.py:17` keeps `_PENDING: dict[str, tuple[str, float]]` in process memory. The comment correctly flags "Single-instance only." For a demo this is fine; for prod or anything fronted by more than one worker (uvicorn `--workers > 1`, gunicorn, k8s replicas) the `/auth/callback` will fail because `state` is unknown on the second instance. Recommend either:
- Redis with `SETEX state {ttl} verifier` (matches PKCE_STATE_TTL_SECONDS), or
- a signed cookie carrying `(state, verifier)` set by `/auth/login` and consumed by `/auth/callback`, eliminating server-side state.

**W2 — In-memory OAuth authorization codes in auth-server have the same scale/restart limitation**
`apps/auth-server/src/token/oauth.service.ts:23` `this.codes = new Map<string, AuthCode>()`. Codes minted on pod A cannot be exchanged on pod B. TTL is 5 min so user-visible failure is bounded, but a single rolling restart during business hours will invalidate every in-flight flow. Same fix shape: Redis with `SETEX` + `GETDEL` for one-time-use semantics, or a `sa_oauth_code` table with `expires_at` and atomic delete-returning.

**W3 — JWT claim breakage: `permissions: string[]` → `scope: string`**
`packages/types/index.ts` removed `permissions` and added `scope` (space-separated). Any resource server holding a JWT issued before the deploy will continue to send `permissions` in its expectations / parsers. Mitigations:
- Access-token TTL is 1h, so churn is bounded.
- But: coordinate the deploy with any downstream consumer; document in `CHANGELOG.md` as a **breaking change** in the JWT envelope.
- Consider a 1-release transition where both claims are emitted, then drop `permissions`.

**W4 — `@IsUrl({ require_tld: false })` loosens redirect_uri DTO validation**
`apps/auth-server/src/token/dto/oauth-token-exchange.dto.ts:19`. Justification (localhost in dev/test) is sound, and the real security boundary is `assertRedirectUriMatchesApp()` against `sa_app.url`. Net OK — but make sure no `sa_app.url` row in prod is allowed to store `http://localhost` / unroutable hostnames; otherwise a non-TLD redirect_uri becomes acceptable. Add a check at app create/update time in `AppsService` that rejects non-routable origins outside of `NODE_ENV !== 'production'`.

**W5 — Bare `except Exception` in JWT verifier hides programming errors**
`apps/resource-server-fastapi/app/oauth/verifier.py:18` — the `try/except Exception` collapses every failure mode (signature mismatch, missing claim, JWKS fetch failure, `cryptography` import problem) into a 401. That is correct for clients, but for operators it makes debugging painful. Add `log.warning("jwt.verify.failed", extra={"error": type(e).__name__})` (no token, no message body) before `raise`. Same pattern as the auth-server's `oauth.pkce.verify_failed` log.

**W6 — `_purge_expired` only runs on new `/auth/login`**
`apps/resource-server-fastapi/app/oauth/routes.py:20`. Bounded leak (each entry ≈ 100 B, TTL 600 s), so not a real risk, but if `_PENDING` is replaced with Redis (W1) this concern disappears. If staying in-memory short-term, schedule a `BackgroundTasks` or APScheduler purge every 60 s.

**W7 — Module-level `_jwks_client` initialization couples to settings at import time**
`apps/resource-server-fastapi/app/oauth/verifier.py:7`. Tests work via `monkeypatch.setattr(v, "_jwks_client", _StubClient())`, which is fine, but it means: (a) settings changes after import don't propagate, (b) JWKS fetch failures at app boot crash the import chain. Move the client behind `@lru_cache` accessor `get_jwks_client()` consistent with `get_settings()`.

### 🟢 Clean

- **PKCE S256 verification is correct.** `apps/auth-server/src/token/oauth.service.ts:51` uses `crypto.timingSafeEqual` after length check; base64url encoding strips padding and replaces `+/` correctly; only `S256` is accepted, no `plain` fallback. RFC 7636 §4.6 compliant.
- **OAuth error codes aligned to RFC 6749 §5.2.** `packages/types/index.ts` now exposes `invalid_request`, `invalid_redirect_uri`, `invalid_grant`, `unauthorized_client`. Old over-specific codes (`INVALID_CODE`, `CODE_EXPIRED`) correctly collapsed into `invalid_grant`.
- **`assertRedirectUriMatchesApp` returns 400, does not redirect to attacker URI.** `apps/auth-server/src/token/redirect-uri.ts` throws `BadRequestException` rather than redirecting. RFC 6749 §3.1.2.4 conformant. Origin comparison uses `new URL(...).origin`, which normalizes path/trailing-slash differences. Tests cover host, scheme, port mismatch and malformed input.
- **One-time-use codes are deleted on every failure path** (unknown app, expired, verifier mismatch) — no replay window in `oauth.service.ts`.
- **`validateNextUrl` in admin is hardened against common bypasses.** `apps/admin/lib/safe-next.ts` rejects: protocol-relative (`//evil`), backslash (`/\\evil`), userinfo (`http://attacker@host`), origins outside allowlist, and malformed URLs. Tests exercise each. `LOGIN_NEXT_ALLOWED_ORIGINS` env extension is a clean escape hatch.
- **FastAPI verifier requires `["exp","iat","sub","iss","aud","scope"]`** and validates `aud` + `iss` with `pyjwt`. JWKS client uses `cache_keys=True, lifespan=600` — sensible. Scope check is set-membership against the required scope, not substring matching (avoids `rs.properties.create2` matching `rs.properties.create`).
- **Demo seed is idempotent.** `apps/auth-server/src/seed/demo-resource-server.ts` uses `findUnique`/`findFirst` before insert and `upsert` for join tables. Gated by `SEED_DEMO=1` so production seeds are unaffected.
- **Sidebar active-route fix is the right shape.** `apps/admin/components/sidebar-shell.tsx` now reads `usePathname()` directly in the client component, removing the `x-pathname` header indirection and its silent `'/users'` fallback in `(admin)/layout.tsx`. Simpler control flow, no SSR/CSR mismatch risk.
- **`SheetContent` flex fix has correct mechanical explanation.** `packages/ui/src/components/ui/sheet.tsx` — without `flex flex-col` on the parent, the `flex-1 + overflow-y-auto` body had no constrained-height parent, so the footer scrolled off. Fix unblocks Playwright's normal `.click()` and the test correctly drops the `dispatchEvent` workaround.
- **Observability logs in TokenController are PII-safe.** `oauth.pkce.verify_failed` and `oauth.redirect_uri.rejected` log `appId`, error code, and origin — never `code_verifier`, `code_challenge`, or the access token. Matches the spec promise.

3. **W5 + W7 — Tighten resource-server JWT verifier ergonomics.** `log.warning("jwt.verify.failed", ...)` before raising; move `_jwks_client` behind `@lru_cache` accessor for parity with `get_settings()`. Both small, ~10 lines.

**Overall repo health:** Strong — PKCE work is well-specified, well-tested, and conformant to RFC 7636 / RFC 6749; the main gap is state-store productionization, which is a known design choice, not a defect.
