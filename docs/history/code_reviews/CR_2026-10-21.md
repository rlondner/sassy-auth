### 🟢 PR #462 — fix(auth-server): pin fake clock in refresh-token rotate tests (bug-0298) — by rlondner
- **Files:** 2 · **+75 / -0**  ·  base `dev` ← `bug-0298`
- **Scope:** Adds `jest.useFakeTimers().setSystemTime(new Date('2026-10-01T00:00:00Z'))` / `useRealTimers()` wrappers to the `describe('rotate', …)` block in `apps/auth-server/src/token/refresh-token.service.spec.ts`; plus `docs/history/bugs/bug-0298.md` write-up.
- **Findings:**
  - 🟢 **Correctness:** Right fix. `RefreshTokenService.rotate()` builds `now = new Date()` and rejects when `row.expiresAt < now || row.absoluteExpiresAt < now`. The hardcoded fixtures (`expiresAt: 2026-10-17`, `absoluteExpiresAt: 2026-12-16`) became permanently expired on 2026-10-18. Pinning the clock before `existingRow` is read decouples the fixture from wall-clock drift. Timer scope is local to the `rotate` describe block (`beforeEach`/`afterEach`), so leakage into other suites is prevented.
  - 🟢 **Safety:** No production code touched; auth logic unchanged. Prisma mock in the spec means `jest.useFakeTimers()` won't deadlock a real DB client timeout.
  - 🟢 **Test coverage:** Restores 3 previously silently-red tests (`rotates a valid token`, `rolls back the whole transaction`, `concurrent replay`) → 12/12 passing per the bug write-up. These three cover the critical correctness paths of rotation (happy path, transactional rollback, race-condition single-use enforcement) — getting them back to green materially improves confidence in refresh-token security.
  - 🟡 **Follow-up (not blocking):** The TODO already proposes a lint/review rule to flag `new Date('20XX-…')` literals in test fixtures without an adjacent fake-timer scope. Worth implementing as an ESLint rule (`no-wall-clock-fixtures`) or a CI grep guard — this is the second time-bomb-shaped failure the repo has hit this quarter.
  - 🟡 **Observation:** The bug was invisible on `dev` since the 2026-10-19 push (`4151407`) because that push's own diff (GCP Cloud Run / Dockerfiles) didn't touch `token/`. Suggests the CI red/green signal is not reaching PR authors effectively — an ADR on branch protection + required status checks on `dev` would prevent recurrence.
- **Recommendation:** **Approve & merge** — fixes active red CI, unblocks all PRs targeting `dev`.
