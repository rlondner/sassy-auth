## Root cause found: the "shared `unit-tests` failure" from 2026-10-20's review

The prior two reviews (2026-10-19, 2026-10-20) both flagged `unit-tests`
failing on every open PR as a "pre-existing / infra-shared failure" but
didn't root-cause it. Investigated this run:

```
FAIL token/refresh-token.service.spec.ts
  ● rotates a valid token ... UnauthorizedException: invalid_grant
  ● rolls back the whole transaction ... Expected "db error", got "invalid_grant"
  ● concurrent replay ... updateMany never called
```

`RefreshTokenService.rotate()` rejects a token once
`row.expiresAt < new Date()`. The spec's "valid, not-yet-expired" fixture
hardcodes `expiresAt: new Date('2026-10-17T00:00:00Z')` and never installs
fake timers for the three failing tests, so it compares against the real
system clock — which passed 2026-10-17 on 2026-10-18, permanently flipping
these tests to "expired" regardless of the actual code path under test.
Filed **bug-0298** (🟠 High — masks real rotation/rollback/race-handling
regressions behind a permanent false failure, and taints every open PR's
CI status with an unrelated red job). Fixed by pinning `jest.useFakeTimers()`
for the whole `rotate` describe block; verified 12/12 passing locally.
PR against `dev` created for the fix.
