## 2. Triage of Underlying Bugs (from the PR descriptions)

These are the *real* engineering items behind the doc PRs. Prioritized by production impact.

### 🔴 Critical (fix first)

**bug-0146 — Sentry breadcrumb logs raw user email (PII)**
- **File:** `apps/admin/lib/api.ts:36`
- **Impact:** Compliance/regulatory. PII sent to a third-party observability vendor is a GDPR/CCPA hazard, especially in the insurance/healthcare/legal tenants your platform targets. This is a "fix today" item, not a backlog item.
- **Recommendation:** Ship the fix immediately (`result.user.email` → `result.user.id`). Also audit *all* Sentry `addBreadcrumb` / `captureException` call sites in `apps/admin/` and `apps/auth-server/` for other PII leaks (names, emails, org names, phone numbers). Consider a Sentry `beforeSend` scrubber as defense in depth.

**bug-0143 — `deletePermission` silently cascades role/user assignments**
- **File:** `apps/auth-server/src/permissions/permissions.service.ts:189-209`
- **Impact:** Data-integrity / RBAC governance. An admin deleting a permission unknowingly revokes it from every role and user assignment via `onDelete: Cascade`. In a regulated multi-tenant SaaS, silent bulk revocation of authorization state is a serious audit issue.
- **Recommendation:** Pre-check dependent counts and throw `ConflictException` with the count in the payload. Add an audit-log entry for permission deletions regardless. Consider whether cascade is the right schema-level policy at all — `Restrict` may be safer for authorization tables.

**bug-0140 — `listUsers` returns unbounded results**
- **File:** `apps/auth-server/src/users/users.service.ts:79`
- **Impact:** DoS / memory. Every other list endpoint paginates; this one doesn't. A tenant with 50k+ users could OOM the API pod or blow response-payload budgets.
- **Recommendation:** Fix now. Match the existing `listOrgs` / `listRoles` pattern (`page`, `pageSize`, default 25, cap at 100). Add an integration test seeding 1k+ users to verify the cap.

**bug-0139 — `resendInvitation` expire+create is non-atomic**
- **File:** `apps/auth-server/src/users/users.service.ts:536-547`
- **Impact:** Partial-failure orphans a user with zero valid invitation tokens — they can neither accept nor be reinvited without manual DB intervention.
- **Recommendation:** Wrap in `prisma.$transaction`. Add a test that injects a failure between the two operations and asserts the original token survives.

### 🟡 Warning

- **bug-0138** — `removeRole` leaks Prisma stack trace on P2025 (info disclosure + 500 vs 404). Straightforward `try/catch → NotFoundException`.
- **bug-0137 / bug-0145** — Missing request-cancellation in debounced search / drawer fetch effects. Classic React stale-response bug. Standardize on the `cancelled` flag pattern already used in `role-create-drawer.tsx`; consider extracting an `useAbortableFetch` hook to avoid future repeats.
- **bug-0142** — `UserViewDrawer` edit-mode `useEffect` has missing deps (`roles`, `directPermissions`). Stale-closure risk. Also — enable `react-hooks/exhaustive-deps` as an ESLint **error** to catch these at CI time.
- **bug-0136** — `apiFetch` throws generic error on 401 instead of redirecting. Consider a shared `useAuthGuard` or a top-level fetch interceptor rather than sprinkling `if (res.status === 401)` throughout.
- **bug-0144** — Missing `expiresAt` index on `SaInvitation`. Add `@@index([expiresAt])`, generate migration, deploy behind normal migration flow (non-blocking for small tables now, but will bite on scale).

### 🟢 Minor

- **bug-0141** — Whitespace-only name in edit drawers. Trivial. Also add a DTO-level `@IsNotEmpty` / `@Matches(/\S/)` server-side check — never rely on client validation as the sole guard.
