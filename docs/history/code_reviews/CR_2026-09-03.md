## Branch: `bugs/bug-0278-hardcoded-auth-throttle-ignores-env`

**Diff:** 5 files, +138 / −28. New file `apps/auth-server/src/common/config/rate-limit-config.ts` (+ spec).

**Change**

Per `@nestjs/throttler` semantics, a per-route `@Throttle({ auth: { limit, ttl } })`
call *overrides* the named bucket's module-level config — it doesn't merely
select the bucket. Previously `InvitationsController`, `TokenController.directLogin`
and `TokenController.oauthAuthorize` each hardcoded `{ limit: 10, ttl: 60_000 }`,
so `AUTH_RATE_LIMIT` / `AUTH_RATE_WINDOW_MS` env vars had **zero effect** on the
routes they were introduced to protect. Fix extracts a shared `AUTH_THROTTLE` /
`DEFAULT_THROTTLE` config module, imported by both `AppModule.forRoot()` and every
per-route decorator so they can never drift again.

**Findings**

| Severity | Area | Finding |
|---|---|---|
| 🟢 Security | Rate-limiting | Actual fix for a silent-misconfiguration class bug. Env-var-driven auth throttle is now genuinely tunable in prod without a redeploy. |
| 🟢 Architecture | Config surface | Single-source-of-truth pattern is right — avoids the exact drift class this bug came from. Extending later (add a `sensitive` bucket, etc.) is now additive. |
| 🟢 Testing | Coverage | `rate-limit-config.spec.ts` added (+79). Covers the env-parse + test-mode-override path. |
| 🟡 Runtime coupling | Module init | `DEFAULT_THROTTLE` / `AUTH_THROTTLE` are evaluated at **module load** (top-level `const`), which reads `process.env` once. Same behavior as before the change, so no regression — but worth documenting: changing env vars now requires a restart, not a config reload. Consider making these `getX()` factories if hot-reload is ever wanted (unlikely). |
| 🟡 Test-mode gate | Isolation | `isTest` bypasses envInt entirely. If someone in the future adds a third bucket and forgets the `isTest ?` short-circuit, e2e will flake against it. Consider a small `resolveBucket(name, fallback)` helper that centralizes the `isTest` short-circuit. Non-blocking. |

**Recommendation:** ✅ Approve.

## Branch: `feature/admin-signup`

**Diff:** 22 files, +2321 / −15. Spans `apps/admin` (Next.js) and
`apps/auth-server` (NestJS registration slice). Includes design spec (215) +
implementation plan (1293) under `docs/superpowers/`.

**Auth-server changes**

- `RegisterDto`: `password` policy raised to `MinLength(12)` + regex `^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{12,}$` — restores parity with `AcceptInvitationDto` (bug-0007) that had regressed on this newer endpoint. `firstName` / `lastName` added and are now required.
- `RegistrationService.register`: BetterAuth `signUpEmail` now uses `${firstName} ${lastName}` for `name`; the `SaUser` row gets real `firstName` / `lastName` instead of `companyName` / `''`.
- `RegistrationController`: new `GET /api/register/app?appPublicId=…` — public, unauthenticated, returns `{ name }` (200) or 404. Guarded by a new `AppLookupRateLimitGuard`.
- `AppLookupRateLimitGuard` extends `RateLimitGuard` — separate DI singleton so page-load lookups don't consume the `POST /api/register` budget; reads the same env vars.

**Admin changes**

- New `/signup` page, `SignupForm` client component, `registerAction` server action.
- `middleware.ts`: `/signup` added to `PUBLIC_PATHS`.
- i18n keys added for both `en` and `fr`.
- Tests: `actions.test.ts`, `signup-form.test.tsx`.

**Findings**

| Severity | Area | Finding |
|---|---|---|
| 🟢 Security | AuthN policy | Restoring 12-char + complexity floor on `RegisterDto` is a real fix — a direct POST to `/api/register` could otherwise register accounts weaker than any invitation flow allows. Server-side enforcement (not just admin UI) is the right layer. |
| 🟢 Security | Identity model | Fix stops using `companyName` as first name of the org admin — was a silent data-quality bug that would surface in audit logs, email templates, and RBAC UI. |
| 🟢 Architecture | Rate-limit isolation | `AppLookupRateLimitGuard` subclass pattern is exactly right: shares limit *values* via inheritance but keeps its own counter Map. The commit message + inline comment explain the reasoning; future maintainers won't accidentally collapse them. |
| 🟡 Security | Enumeration surface | `GET /api/register/app` is an unauthenticated `appPublicId` oracle by design (200 vs 404 is distinguishable — unavoidable given the endpoint's purpose). Rate limit mitigates but does not eliminate. Explicitly acknowledged in the JSDoc, which is good. **Follow-up:** consider whether `appPublicId` should be treated as low-entropy public info (like an OAuth `client_id`) going forward — if yes, this stays fine; if no, the whole design needs a rethink. Recommend adding this to `SECURITY.md`'s "not a secret" list. |
| 🟡 Error mapping | UX / observability | `apps/admin/app/signup/actions.ts` maps any non-{200,404,409,429} response to `'validationError'`. That collapses 5xx (server unavailable / DB down / auth-server bug) into a message that blames the user. Split 5xx → `'serverUnavailable'`. Cheap fix, better ops signal. |
| 🟡 Trust boundary | Origin header | `registerAction` forwards `getForwardedOrigin()` as the `Origin` header to the auth-server. Verify auth-server side does not use `Origin` for any trust decision (CORS reflection, redirect_uri validation, etc.) — this is a server-action request, not a browser request, so `Origin` is attacker-controllable via the `x-forwarded-*` headers. If any downstream code trusts it, that's a real issue; if it's purely for CORS/logging, ignore. |
| 🟡 Client validation drift | Consistency | `SignupForm` re-implements the password policy client-side (`.length < 12`, `/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).+$/`). It matches the DTO today but is a second source of truth — will drift the day the server-side pattern changes. Consider exporting the pattern from a shared `@sassy-auth/shared` package, or accepting the drift risk and adding a lint / test rule that pins them together. |
| 🟢 Testing | Coverage | New tests for both server action (77 lines) and form (143 lines). Auth-server side: `register.dto.spec.ts` (+48), `registration.controller.spec.ts` (+44), `rate-limit.guard.spec.ts` (+25), `registration.service.spec.ts` (+31). Reasonable for the surface added. |
| 🟢 i18n | Coverage | English **and** French strings added in the same commit — no half-shipped locale. |
| 🟢 Blast radius | Public routing | `/signup` added to `PUBLIC_PATHS` in middleware, list is small and easy to audit. |

**Recommendation:** 🟡 Approve with follow-ups — fold the 5xx → `serverUnavailable`
mapping and the `Origin`-header trust check into this PR (both are 5-minute
changes); the enumeration-surface docs update and the shared-pattern refactor
can be follow-up tickets.
