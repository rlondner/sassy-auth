This silently disables the Prisma transactional client type and removes IDE/CI guarantees on every `tx.saRole`/`tx.saUser`/`tx.saApp`/`tx.saOrg`/`tx.saPermission` call site. The bot most likely hit a build-order issue where `@sassy-auth/db`'s generated Prisma types weren't visible at compile time and reached for `any` rather than fixing the build. Correct fix: import `Prisma` from `@prisma/client` and type as `Prisma.TransactionClient`. Reject `any` in shared infra code per repo standards.
- 🟡 **`.github/workflows/e2e.yml` — pnpm version pin removed.** `pnpm/action-setup@v4` no longer specifies `version: 9`; CI will now derive the version from the `packageManager` field in root `package.json`. Acceptable **only if** `package.json` declares `packageManager: "pnpm@9.x.x"`. If not, CI becomes non-reproducible (auto-upgrades on every pnpm release). Verify the lockfile is still resolvable.
- 🟡 **New CI step `pnpm exec turbo build --filter=!@sassy-auth/auth-server` skips the auth-server build.** Filtering out the auth-server (the security-critical app) from the build verification step before `prisma generate` can mask compilation/type breakage that would otherwise be caught pre-deploy. Either include it (preferred) or explain in a comment why it's excluded (e.g. circular dep with Prisma generation).
- 🟢 **a11y / i18n improvements are solid.** `aria-label={t('common.moreActions')}` on the row-action button + paired `<TooltipContent>` is the right Radix pattern. fr.json now resolves the long-standing English-fallback for `save/edit/delete/confirm`.

- 🟢 **Root `<TooltipProvider>` placement is correct** — inside `NextIntlClientProvider`, outside `children`. Single instance, no double-wrap risk.

**Recommendation:** 🟥 **Request Changes** — block on (a) restoring proper `Prisma.TransactionClient` typing in `seed.ts`, (b) confirming `packageManager` pin in `package.json`, (c) justifying the `--filter=!@sassy-auth/auth-server` exclusion.
