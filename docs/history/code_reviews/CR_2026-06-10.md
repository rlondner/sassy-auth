  - 🟢 New `button.test.tsx` is well-scoped and covers the loading + asChild matrix.
- **Recommendation:** **Request Changes — block on type-safety regression.** Split into: (a) UI loading prop (keep), (b) builder swap (separate PR with `tsc --noEmit` in CI), (c) revert `tx: any` casts.

### PR #43 — feat(auth): OAuth2 PKCE + FastAPI resource server + observability
- **Author:** Raphael Londner · **Updated:** 2026-06-02T04:05Z
- **Files:** 46 · **+4800 / −64**
- **Findings (security-critical — this PR rewrites the OAuth token exchange):**
  - 🟢 **PKCE S256 properly implemented**: `OauthService.exchangeCode` recomputes `s256(verifier)` and uses `crypto.timingSafeEqual` with explicit length check before the compare. Correct order of operations.
  - 🟢 **One-time code use** preserved: code is deleted on success, expiry, client mismatch, and verifier mismatch — no leakage path.
  - 🟢 **Redirect-URI origin matching** (`assertRedirectUriMatchesApp`) is enforced on BOTH `/authorize` AND `/token`, with structured `oauth.redirect_uri.rejected` log + Sentry tag. Defends against covert redirect.
  - 🟢 `scope` claim is now space-delimited string per RFC 6749 §3.3 (`scope: permissions.join(' ')`) — replaces the non-standard array `permissions` claim. FastAPI verifier consumes it correctly.
  - 🟢 `validateNextUrl` (admin) blocks protocol-relative (`//evil`), backslash-escape (`/\evil`), userinfo-injection (`http://attacker@host`), and cross-origin destinations. Test coverage is solid.
  - 🟢 FastAPI verifier uses `PyJWKClient` with `cache_keys=True, lifespan=600` and `options.require=[exp, iat, sub, iss, aud, scope]` — good defense-in-depth.
  - 🔴 **Breaking change, undocumented**: `OauthTokenExchangeDto` removes `client_secret` and replaces it with `code_verifier`. Any existing confidential-client integration breaks silently with a validation 400. Either:
    - keep `client_secret` optional + branch by client type (public vs confidential), or
    - document the public-client-only contract and bump a breaking version of the OpenAPI spec.
  - 🔴 **In-memory authorization-code store** (`private readonly codes = new Map<string, AuthCode>()`) won't survive a restart and breaks under horizontal scaling — a code minted by node-A is unredeemable on node-B. Already tracked as bugs #39 (persist), #40 (gc), #73 (memory purge); call it out explicitly in PR description, do not ship to multi-instance prod without #39 merged first.
  - 🟡 **`@IsUrl({ require_tld: false })`** on `redirect_uri` is needed for `http://localhost:*` dev, but in prod allows weak URLs (`http://foo`). Gate on `NODE_ENV` or rely solely on `assertRedirectUriMatchesApp` (which already enforces origin-equality against the registered `app.url`).
  - 🟡 **`code_challenge_method` only accepts `'S256'`** — correct policy, but error returned is `INVALID_REQUEST` with no `error_description` per RFC 6749 §5.2. Consider `invalid_request` with description `code_challenge_method must be S256`.
  - 🟡 **No rate limit** on `/api/token/oauth/token` — code-substitution / brute-force window. Tracked as bug #46 / #80; should be a release blocker for this PR.
  - 🟡 FastAPI verifier's `except Exception:` swallows the underlying jwt failure reason — wrap as 401 but log `exc_info=True` for telemetry.
  - 🟢 Test coverage: `oauth.service.spec.ts`, `redirect-uri.spec.ts`, `safe-next.spec.ts`, `test_pkce.py`, `test_verifier.py`, `test_api_properties.py` all updated for the new contract.
- **Recommendation:** **Needs Discussion** — security implementation is correct, but (a) the `client_secret` → `code_verifier` swap is a breaking API change that must be communicated, and (b) the in-memory code store + missing rate limit make this unsafe for multi-instance deploy. Merge only with bugs #39 + #46 sequenced before the resource-server cutover.
