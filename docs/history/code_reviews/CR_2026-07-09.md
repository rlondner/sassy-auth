## 🔴 Critical findings — must fix before shipping

### 1. Timing-guard fix `880b5e6` (bug-0209) has two live side-channels

The commit adds a dummy `verifyPassword` on the *user-not-found* branch. Post-fix scan (already documented in `bugs/BUGS_2026-07-08.md` on `daily-review-2026-07-08`) found **two other branches that skip scrypt**, defeating the guard:

**bug-0214 — org/app mismatch returns 403 before scrypt**
`apps/auth-server/src/token/token.controller.ts:384-387`. Valid user in wrong tenant throws `ForbiddenException(USER_ORG_MISMATCH)` instantly, while user-not-found returns `401 INVALID_CREDENTIALS` after ~100 ms scrypt. Attacker gets a tenant-membership oracle plus enumeration.
Fix: move mismatch check *after* password verification and collapse the response into `INVALID_CREDENTIALS`.

**bug-0215 — social-only user skips scrypt**
Same file, lines `396-402`. If the user row has no credential-provider `account` row (Google/GitHub only), the code throws `INVALID_CREDENTIALS` immediately without `verifyPassword`. Reveals authentication method → targeted phishing vector.
Fix: run the dummy `verifyPassword` on this branch too, mirroring the not-found branch pattern.

Status: tracking branches `fix/bug-0214` and `fix/bug-0215` exist but contain only chore commits — **no fixes landed yet**.

## 🟡 Warnings

### 2. Post-login OAuth `next` path is broken (bug-0216)
`880b5e6` builds `nextPath = ${OAUTH_AUTHORIZE_ROUTE}?...` — no `/api/token/` prefix, no leading `/`. Admin's `validateNextUrl()` (`apps/admin/lib/safe-next.ts`) rejects it; user is dumped at `/users` after login. The intended UX of bug-0149 is non-functional in practice.
Fix: `nextPath = ` `/${NEST_GLOBAL_PREFIX}/${TOKEN_CONTROLLER_PATH}/${OAUTH_AUTHORIZE_ROUTE}?${query.toString()}`.

### 3. Helmet CSP breaks Swagger UI in dev (bug-0217)
`configure-nest-app.ts:21-25`. `helmet()` is applied unconditionally with default CSP that blocks inline scripts/styles; Swagger UI is mounted in *non*-production. Comment claims prod-only but that's wrong.
Fix: `app.use(helmet({ contentSecurityPolicy: process.env.NODE_ENV === 'production' }))`.

### 4. `updateUser` status guard is one-hop, not transitive (bug-0218)
`f9403a2` guards `pending → active` but an admin can pending → inactive → active in two calls, activating a user with no credential. Guard the destination, not the transition edge.
Fix: block *any* → `active` unless previous state was `active` (reactivation from `inactive` is the only allowed activation transition).

### 5. `updateUser` missing self-modification guard (bug-0219)
Sibling mutations (`deleteUser`, `setUserRoles`, `setUserDirectPermissions`) all check `if (user.betterAuthUserId === callerBaId) throw`. `updateUser` doesn't. An admin can deactivate themselves via `status`. Add symmetric check when `dto.status` is set.

### 6. `SaOauthCode` has no cleanup job (bug-0220)
`26f6df1a` (bug-0039) moved OAuth codes from Map to DB but shipped without a purger. Schema comment even calls it out. Unbounded growth.
Fix: NestJS `@Cron('*/15 * * * *')` calling `prisma.saOauthCode.deleteMany({ where: { expiresAt: { lt: new Date() } } })`.

### 7. `updateUserAction` swallows Next.js `NEXT_REDIRECT` sentinel (bug-0221)
Sibling actions try/catch and re-throw redirects; this one doesn't. Session expiry mid-edit shows a generic error toast instead of routing to `/login`. New surface introduced by `23e9fe4` (bug-0136).

### 8. `user-view-drawer` initial-load effect lacks cancellation (bug-0222)
Peer drawers were fixed in `f9403a2` (bug-0145); this one was missed. Rapid drawer open/close can render user A data over user B state.

### 9. Rate-limiter without proxy trust (`0b6ef0d`, follow-up already noted)
The `ThrottlerModule` keys on request IP. In prod behind a reverse proxy, all requests will bucket into the LB IP unless Express is set with `app.set('trust proxy', ...)`. Commit message explicitly parks this as a follow-up — flagging so it doesn't slip through to a deployment PR.

### 10. Session-cache TTL invalidation (`e1c06d0`, verify)
10 s cache on session validation is a reasonable trade, but confirm the invalidation path fires on password change / role revoke / logout — otherwise a revoked admin can act for up to 10 s. `0b6ef0d` sets `cookieCache: { enabled: false }` in `auth.config.ts` deliberately for the same reason; the admin-middleware cache reintroduces a shorter version of the same risk. Recommend explicit test coverage for revoke-then-request within TTL.
