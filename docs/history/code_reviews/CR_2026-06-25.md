#### Findings

🔴 **Critical — Type-safety regression on security-critical paths**
The PR description states: *"Fixed 60+ pre-existing TypeScript errors in auth-server (transactions & implicit any) to unblock the build."* The fix chosen is to retype callback parameters as `any` in code that enforces authorization, including:

| File | Callback now typed `any` |
|---|---|
| `common/permissions/check-permission.ts` | `ur`, `rp`, `up` in the perms-set construction |
| `common/permissions/check-permission-for-app.ts` | same |
| `common/permissions/assert-caller-can-grant-system-perms.ts` | `ur`, `rp`, `up` — escalation guard |
| `users/users.service.ts` | role/permission mapping, system-perm filter, escalation guard inputs (`as string[]` added to silence the result of an `any` chain) |
| `roles/roles.service.ts` | row mappers, groupBy result mappers, transaction handlers |
| `permissions/permissions.service.ts` | row/groupBy mappers, transaction handler |
| `invitations/invitations.service.ts` | transaction handler |
| `apps/apps.service.ts`, `orgs/orgs.service.ts`, `permissions.service.ts` | `type Tx = Parameters<Parameters<typeof prisma.$transaction>[0]>[0]` → `type Tx = any` |

Why this is a problem in an auth server:
- `check-permission*` and `assert-caller-can-grant-system-perms` are the chokepoints for RBAC/ABAC. Losing structural typing on the role/permission graph means a future rename (`permission.name` → `permission.code`, etc.) or a Prisma `include` change will silently produce `undefined` keys in the perms `Set`, instead of failing the build. That is a latent privilege-escalation / silent-deny vector.
- Transaction handlers retyped to `any` remove Prisma's TypeScript-level guarantee that only valid model calls are issued inside `prisma.$transaction(...)`. A typo or wrong-table write will compile and execute.
- The 60+ errors were "pre-existing," which strongly suggests an underlying Prisma client / TypeScript version drift or a missing `prisma generate` in CI — not something that should be papered over with `any`.

🟡 **Warning — CI workflow change**
- Removing `with: { version: 9 }` from `pnpm/action-setup@v4` makes the runner use whatever pnpm version is declared in `packageManager` in the root `package.json`. That is the right direction (single source of truth), but should be verified to actually be set in the manifest and pinned (e.g. `pnpm@9.x.x`), otherwise the action defaults can drift across runs.
- The new `pnpm exec turbo build --filter=!@sassy-auth/auth-server` step is sensible to materialize shared packages before Prisma generate, but it exempts the auth-server from CI build verification on this workflow path. If the e2e job is what was previously catching auth-server build errors, that signal is now lost.

🟡 **Warning — Tooltip + DropdownMenuTrigger composition (admin tables)**
- Radix `DropdownMenuTrigger asChild` wrapped inside `TooltipTrigger asChild` works in current shadcn/Radix versions, but stacks two `asChild` slot proxies on the same `<button>`. Verify keyboard behavior (Space/Enter should open the menu; the tooltip should not steal focus or trap it on mobile/long-press). Suggest at least one Playwright a11y test for "menu opens via keyboard while tooltip is mounted" before merging.
- The dropdown `<button>` has both an `aria-label="common.moreActions"` and an adjacent `<TooltipContent>` with the same text — screen readers may announce twice. Either drop the `aria-label` or set `aria-describedby` on the trigger instead.

🟡 **Warning — i18n key duplication risk**
- `common.copy` / `common.copied` / `common.moreActions` are added at the `common.*` level. The existing per-table action namespaces (`apps.actions.copy`, etc.) still exist and the table now uses `common.copy` instead of `apps.actions.copy`. Either prune the per-table copy keys to avoid drift, or keep them and have `common.copy` reference them — otherwise translators will update one and miss the other.

🟢 **Clean — French translation fix**
- `apps/admin/messages/fr.json` `common.{save,edit,delete,confirm}` were left in English in `master`. PR finally localizes them. Good catch.

🟢 **Clean — Tooltip/i18n on copy button**
- Switching the copy-feedback affordance from a hard-coded `material-symbols` swap to an i18n'd tooltip is the right pattern.

#### Recommendation
**🛑 Request changes.** Merging tooltips/i18n/CI bits in isolation is fine, but the `: any` sweep across the authorization layer should be reverted from this PR and split into a dedicated `chore(types): restore strict typing in auth-server` PR that actually fixes the Prisma type generation (likely `pnpm --filter @sassy-auth/db exec prisma generate` not being run before `tsc`, or `@prisma/client` version mismatch in the monorepo). Until then, the auth-server portion of this PR is a security maintainability regression.
