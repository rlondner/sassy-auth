### PR #107 — 🎨 Palette: Add tooltips to row actions and fix CI robustness
- **Author:** `google-labs-jules[bot]` (co-authored by `rlondner`) · **Updated:** 2026-06-16T08:31Z

- **Scope:** (a) `TooltipProvider` wired into admin root layout + per-test wrappers; (b) all 5 admin tables (`apps`, `orgs`, `permissions`, `roles`, `users`) now wrap their "more actions" trigger in `<Tooltip>` with localized `aria-label={t('common.moreActions')}`; (c) `e2e.yml`: drop explicit `pnpm version: 9` and add `pnpm exec turbo build --filter=!@sassy-auth/auth-server`; (d) `auth-server/package.json` seed switched to `ts-node --transpile-only`; (e) **6 service files have their typed callback params replaced with `: any`**.
- **Findings:**
  - 🔴 **Type-safety regression (same pattern flagged on PR #100 on 2026-06-10).** `check-permission.ts`, `permissions.service.ts`, `roles.service.ts`, `users.service.ts`, `invitations.service.ts`, and `seed.ts` now annotate 19 callback parameters (`ur`, `rp`, `up`, `g`, `r`, `row`, `tx`) as `any`. This includes 6 `prisma.$transaction(async (tx: any) => …)` sites — the same pattern the prior CR called out as eroding the Prisma typed-transaction contract. **The cast also hides real errors**: `UsersService.createWithInvitation` now declares `let saUser: any;` instead of `Prisma.SaUserGetPayload<{ include: typeof USER_INCLUDE }>`, so any future change to `USER_INCLUDE` will not be caught at compile time. Root cause is almost certainly the Prisma client typegen not being run before `tsc`. Fix the dependency order, do not silence the type.
  - 🔴 **Seed still uses `ts-node --transpile-only`** (`apps/auth-server/package.json`). This skips type-checking during seed, which runs in CI before e2e. The seed touches RBAC tables — silently shipping a broken seed is a production-data-shape risk. Add a separate `seed:typecheck` step (`tsc --noEmit -p apps/auth-server/tsconfig.json`) in CI before `seed`.
  - 🟡 **`UsersTable` row action button**: pre-change had **no `aria-label`** at all (line was `<button className="…"><span … /></button>`). PR #107 adds `aria-label={t('common.moreActions')}` — that's a positive a11y improvement and a stealth bugfix not called out in the PR description. Worth a separate line item in the changelog so it isn't lost.
  - 🟡 **`.Jules/palette.md`** is journal/learnings content written by the bot agent. It uses date `2025-05-15` (a year in the past). Either backfill the correct date or omit the timestamp — stale dates on agent journals get confusing in code archaeology.
  - 🟢 **`pnpm/action-setup@v4` without `version`** is **correct**: `package.json` has `"packageManager": "pnpm@9.0.0"`, and `pnpm/action-setup@v4` auto-detects from `packageManager`. *(Self-correction from 2026-06-10 CR, which flagged this as a drift risk — it isn't, because the pin moves to `package.json`.)*
  - 🟢 **`turbo build --filter=!@sassy-auth/auth-server`** correctly excludes the auth-server (which has known TS errors) from the pre-e2e build while still building the shared `@sassy-auth/db` and `@sassy-auth/ui` packages the admin app consumes. Pragmatic short-term fix.
  - 🟢 **Tooltip wiring** (root provider + per-table-test provider) is correct. Tooltip pattern (`<Tooltip><TooltipTrigger asChild><DropdownMenuTrigger asChild>…`) correctly composes Radix's two `asChild` Slot wrappers — the `button` becomes the single rendered child of both Slots.

Not introduced by this PR, but the diff makes it obvious — file a follow-up to backfill these or remove the French locale until it's complete.
