### Production code

**`e253d81`** `fix(admin): forward the trust-device cookie so "Trust this device" works` — Raphael
- Files: `apps/admin/app/login/actions.ts` (+14)
- Only the `better-auth.trust_device` cookie is forwarded to the auth server, explicitly *not* `cookieStore.toString()`. Good — prevents an active session cookie from bleeding into a password sign-in. Comment calls this out explicitly.
- 🟢 Header composition uses conditional spread, so the `Cookie:` key is omitted when absent (no empty header).
- 🟡 **Minor:** cookie value is interpolated into a `Cookie:` header without validation. BetterAuth writes it, so trust is high, but a `\r\n` in a spoofed cookie value would header-split. Consider `encodeURIComponent`/reject on control chars for defense-in-depth. Node's `undici` fetch does reject CRLF in header values, so exploitability is low.
- **Recommendation:** ✅ Ship. Optional hardening noted.
