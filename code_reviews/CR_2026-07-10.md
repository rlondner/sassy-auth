- **`bug-0232` — BetterAuth routes bypass `ThrottlerGuard`.** This is the tail of the `bug-0080` throttler work reviewed on 2026-07-08. The NestJS `ThrottlerGuard` only wraps the auth-server's Nest controllers; BetterAuth mounts its own Express-style handler tree that never goes through the guard. **Fix pattern to watch for in the eventual PR:** either (a) a middleware wrapper that re-enters the Nest throttler for the BetterAuth mount path, or (b) an explicit `express-rate-limit` on the BetterAuth router with matching bucket sizes (`auth` bucket = 10/min). Do **not** accept a fix that just adds `@Throttle` to a Nest controller — that would not touch the BetterAuth handler.
- **`bug-0234` — action-layer error leakage.** Look for the fix to (a) log the raw error server-side (Sentry breadcrumb + structured log) and (b) return a stable, opaque error shape to the UI (`{ ok: false, code: 'INTERNAL' | 'VALIDATION' | 'FORBIDDEN', message: <sanitized> }`). Do not accept a fix that just wraps the error in `String(e)` or `e.message` — DB constraint messages and Prisma stack traces are frequent leak vectors.
- **`bug-0233` — UsersTable stale-selection rebase.** The bug-0206 fix landed in one table component and not the other — this is a **consistency-of-fix** class of bug. When reviewing the eventual PR, grep for any other table using the same selection pattern (`RolesTable`, `PermissionsTable`, `AppsTable`, `OrgsTable`) and confirm none are still on the pre-fix pattern.
