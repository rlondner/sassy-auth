### PR #8 — `fix(bug-0005): restore Sqid scheme for SaUser/SaInvitation publicId`
**Author:** Raphael Londner · **Updated:** 2026-05-27 · **Diff:** 2 files, +59 / -7 (`apps/auth-server/src/users/users.service.{ts,spec.ts}`)

Replaces UUID-slice placeholders with a two-step create → re-encode via `this.sqids.encode(row.id)` for `SaUser.publicId` and `SaInvitation.publicId`. Wraps the new `resendInvitation` two-step in its own `prisma.$transaction`.

**Findings:**
- 🟡 **Correctness / collision risk on tmp_ placeholder.** `SaUser.publicId` and `SaInvitation.publicId` are `@unique` (confirmed in `packages/db/schema.prisma`). The temporary `tmp_${baUserId}` is unique by BetterAuth user id and `tmp_${token}` by 32-byte random — safe in practice, but if a previous transaction crashed between insert and update, an orphan `tmp_*` row could remain and the next insert with the same `baUserId` (e.g., retry path) would 23505. Mitigated by transactions wrapping both steps, but consider asserting in tests that a failed update rolls back the insert.
- 🟡 **Perf: doubled writes per create.** Each user/invite now costs 2 INSERTs + 2 UPDATEs inside the transaction. Acceptable for invite flow (low QPS), but if this pattern spreads to hot paths, prefer a DB-side sequence + `LPAD`/sqid encoding via trigger or a `RETURNING` + single UPDATE in raw SQL.
- 🟡 **Test brittleness.** `users.service.spec.ts` adds `(mockPrisma.saInvitation as unknown as { update?: jest.Mock }).update = jest.fn()...` — bypasses the typed mock map. Add `update` to the shared `mockPrisma.saInvitation` definition so it's consistent across describe blocks.
- 🟢 Atomicity preserved (both steps inside `tx`).
- 🟢 Sqids approach matches the project's "canonical encoding" convention.

**Recommendation:** Request Changes — extend the mock map cleanly, add a test for "update rolls back insert on failure," and consider a single-statement variant if this pattern spreads.

### PR #18 — `fix(bug-0018): validate TRUSTED_ORIGINS entries are valid URLs at startup`
**Author:** Raphael Londner · **Updated:** 2026-05-29 · **Diff:** 1 file, +10 / -2 (`apps/auth-server/src/auth/auth.config.ts`)

Wraps each parsed `TRUSTED_ORIGINS` entry in `new URL(origin)` and throws on invalid.

**Findings:**
- 🟢 **Fail-fast at module evaluation.** Good — bad config crashes the auth-server boot before BetterAuth misroutes anything.
- 🟡 **`new URL()` accepts `javascript:` and `data:` schemes.** A misconfigured `TRUSTED_ORIGINS=javascript:foo` would pass the URL parse but is not a meaningful origin. Tighten to: `const u = new URL(origin); if (!['http:', 'https:'].includes(u.protocol)) throw ...; if (origin.endsWith('/')) throw ...;` since BetterAuth compares origins by exact string and a trailing slash silently breaks matching.
- 🟡 **Error message exposes the bad value.** Fine for boot logs, but if `TRUSTED_ORIGINS` ever contained an accidentally pasted secret, it would land in the stack trace. Consider truncating.

**Recommendation:** Request Changes (minor) — restrict protocol + reject trailing slash.
