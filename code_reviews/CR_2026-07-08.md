### 🟡 Warnings — worth a closer look

- **`e1c06d0` — 10 s session-validation cache in admin middleware (bug-0165).** Well-documented trade-off. The stated window is "10s for a server-side-revoked-but-still-cookied session." Two things to flag:
  1. Interacts with the `04ad774` mid-flow deactivation guard — for **admin-console** navigation, an admin who is deactivated will still get 10s of validated requests. Auth-server enforcement (bug-0074) still applies on the actual OAuth/token endpoints, so the residual risk is bounded to admin UI actions issued through the admin gateway. Document this in a runbook so incident response knows the deactivation-to-lockout SLA.
  2. `Map` is instance-local — fine, but if you ever add a shared-token revocation feed (Redis pub/sub, etc.), remember to invalidate this cache too.
- **`4d26f96` — read actions catch-and-return-`[]` (bug-0190).** The empty-array fallback keeps drawers stable, but it also silences **403** responses from a user who just lost a permission. The user sees "no data" instead of "you no longer have access." Consider surfacing a structured `{ ok: false, reason: 'forbidden' }` tuple so the drawer can render an access-denied state (component `AccessDeniedPanel` is already introduced in the same commit). Otherwise Sentry sees the 403 but the user doesn't know why the drawer is empty.
- **`4a193dc` — `RoleViewDrawer` `canWrite` defaults to `true` (bug-0205).** New optional prop with `= true` default preserves back-compat, but any existing caller that forgets to pass `canWrite` continues to render Edit/Delete unconditionally. Grep for `RoleViewDrawer` callers and confirm they all pass the prop explicitly, or flip the default to `false` (fail-closed).
- **`6db55b7` — `generatePendingPublicId()` with `randomUUID()` (bug-0148).** Correct fix. Follow-up: the seed housekeeping ("prefix `pending-`") is a semantic contract now shared across 13 files. Consider hoisting the prefix into a shared constant so seed-cleanup logic and the generator can't drift.
