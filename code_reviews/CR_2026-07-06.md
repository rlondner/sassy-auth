### fix/bug-0165-middleware-session-caching · Raphael Londner
**Head:** `a183d1b` · **Commits vs master:** 1 · **Latest:** 2026-07-04 20:41 EDT
**Files:** `apps/admin/middleware.ts` (+27 / −8)

**Findings**
- 🟡 **Warning – Session revocation lag up to 60s.** Adds an `sa-session-ok` cookie stamped with `Date.now()/1000` and short-circuits `validateSession` for `SESSION_CACHE_MAX_AGE = 60` seconds. Consequence: after admin-initiated logout, `deleteUser`, session revoke, or role change, the affected browser continues to be admitted through the edge middleware for up to a minute. Downstream page loaders that call the auth-server directly will still see the revoked state, but any middleware-only gating is stale.
  - Mitigations to consider: (a) lower TTL to 10–15s for admin; (b) require the auth-server to also stamp/return an `Set-Cookie: sa-session-ok=…` on `/login` so its lifetime is bounded by the server, not client middleware; (c) on `/logout` and `/api/auth/*` mutations, have downstream handlers explicitly `response.cookies.delete('sa-session-ok')`; (d) document the trade-off in the middleware header comment.
- 🟡 **Warning – Timestamp is unauthenticated.** Cookie is `httpOnly + sameSite=lax + secure`, so XSS is largely mitigated, but the value is a self-declared client-visible integer. An attacker with any cookie-write path (browser extension, MITM downgrade in dev, subdomain-set cookie) can extend the window by forging a fresh `sa-session-ok` timestamp. Adding an HMAC over `session_token + ts` (using a middleware-side secret) would eliminate the forgery vector without a round-trip. At minimum, gate this feature behind `NODE_ENV === 'production'` and refuse missing/invalid `sa-session-ok` in dev to catch regressions.
- 🟢 The `AbortController(3000)` transport-timeout fold-in is correct (same as bug-0166) and the failure path deletes `sa-session-ok` — good hygiene.
- 🟢 Redirect path correctly clears the cache cookie.

**Recommendation:** **Needs Discussion.** Approve after (a) shortening TTL or (b) adding server-issued cache token or HMAC; also note this branch supersedes bug-0166 — close #bug-0166 or land it first as a separate hardening step.
