## Security assessment of the 2FA feature

No auth-bypass, tenant-isolation, or credential-leak defects found. Specifically verified:

- `verifyUserTotp` is **fail-closed** — no `TwoFactor` row ⇒ `false`; direct/login refuses a
  pwd-only JWT for a 2FA-enrolled user (`token.controller.ts:492-507`).
- The direct/login endpoint is throttled (`@Throttle` 10/min/IP) and the interactive verify
  endpoints have explicit `customRules` (3 per 10s).
- `isPlatformTwoFactorRequired` honors only the exact string `"true"` (no `"1"`/`"yes"`
  foot-gun).
- TOTP secret and entered code are never logged.

Hardening caveats (not bugs — see TODO items 1–3): rate-limit storage is in-memory
(per-replica); the two 2FA verification surfaces use different limits with no shared
per-account lockout; `shouldPromptTwoFactor` is duplicated server/client.
