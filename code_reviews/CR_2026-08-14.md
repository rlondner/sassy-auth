**What the revision does:** drops the Radix `<Tooltip>/<TooltipTrigger>/<TooltipContent>` wrapper
from the copy button and the `more_vert` row-action button in all 5 tables, replacing it with a
plain native **`title=`** attribute (plus the existing `aria-label`), and removes the now-unused
`Tooltip*` imports and the `Tooltip: Passthrough` / `TooltipTrigger: Trigger` test mocks.

### Findings

- 🟢 **Resolves bug-0252 (nested double-`asChild`).** With Radix Tooltip gone, the
  `TooltipTrigger asChild → DropdownMenuTrigger asChild → <button>` stack no longer exists — the
  row-action button is now a single native button under one `DropdownMenuTrigger asChild`. The
  Slot-composition fragility flagged on 2026-08-13 is moot. (Fix is in the PR head, **not** on
  `master`, so `bug-0252.md` stays `Fixed: false`.)
- 🟢 **Moots half of bug-0251.** The "mocks away its own Tooltip primitive → coverage of a stub"
  complaint no longer applies: the primitive and its mocks were removed. **The scope-creep half
  stands** — see below.
- 🔴 **bug-0250 (Critical) persists unchanged.** `git diff --stat master b3acc18 -- apps/auth-server`
  is still 4 files / +4: `seed.ts:120`, `demo-multitenant.ts:103`, `demo-resource-server.ts:163`
  set `twoFactorPromptedAt: new Date()` (suppresses the 2FA-enrollment prompt for every seeded
  user for `TWO_FACTOR_TRUST_DAYS`), and `auth.config.ts:146` sets `autoSignIn: false`. The new
  head's title even frames the seed 2FA bypass as an intentional *"Fixed … Seeded 2FA Prompt
  Bypass"*. **Still the merge blocker on #316.**
- 🟡 **bug-0251 (scope creep) still stands.** A UI-titled PR still silently carries the
  `auth.config.ts` + 3 seed edits with no mention in an a11y/tooltip title — the bug-0247/0248
  pattern. The `b3acc18` revision narrowed the *test* problem but not the *bundling* problem.
- 🟡 **New — bug-0253 (Minor, a11y/UX).** The native-`title` rewrite binds the copy button's
  `title`/`aria-label` to the transient `copied` state, but a native `title` does not update while
  the pointer stays on the button (browsers sample it at hover-start), and mutating `aria-label`
  on a static element doesn't re-announce to a screen reader. In the normal *hover-then-click*
  path the user keeps seeing **"Copy"**, never **"Copied!"** — so PR #316's own advertised
  "dynamic copied announcement" no longer works. Only the `content_copy → check` icon swap
  survives (fine as a fallback, invisible to AT). See [bug-0253](../bugs/bug-0253.md).
- ⚖️ **Trade-off assessment.** Radix→native is a *reasonable simplification* for a hover hint and
  it removes a provider dependency and the Slot fragility — but for a button whose whole purpose
  is a **state-changing** confirmation, native `title` is the wrong primitive (bug-0253). The
  clean answer is: keep the icon swap, and either restore Radix Tooltip for the copy button (the
  provider is in scope via `SidebarProvider` — bug-0249 was retracted) or add an `aria-live`
  announcement; keep `title` static.

**Recommendation:** 🔴 **Request Changes / do not merge as-is** — same blocker as 2026-08-13:
drop the `twoFactorPromptedAt` seed writes (bug-0250) and split the auth/seed edits out of the UI
PR (bug-0251). The tooltip layer is now simpler but regresses the copy confirmation (bug-0253);
fix that before this lands. Good news: the retracted provider crash (bug-0249) and the nested
`asChild` fragility (bug-0252) are both gone in this head.
