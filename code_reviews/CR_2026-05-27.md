## Open Pull Requests (1)

### PR #8 — `fix/bug-0005-publicid-sqids` (head `7733ec3`)

- **Files changed:** 2 (`apps/auth-server/src/users/users.service.ts`, `apps/auth-server/src/users/users.service.spec.ts`)
- **Additions / Deletions:** +59 / -7
- **Intent:** Replace the `baUserId.slice(0,12)` / `slice(12,24)` placeholder publicIds for `SaUser` / `SaInvitation` with proper Sqids encoded from the autoincrement PK. Uses a two-step pattern: `create` with `tmp_<unique>` placeholder, then `update` with `sqids.encode(id)`.

#### Findings

| Sev | Area | Finding |
|---|---|---|
| 🟡 | Concurrency / Uniqueness | `tempSaUserPublicId = 'tmp_' + baUserId` and `tempInvitationPublicId = 'tmp_' + token` are unique today (BetterAuth user id, 32-byte random token), but they're being inserted into the same `publicId` column that carries a UNIQUE constraint. Document this invariant in the code; if either source ever becomes non-unique (e.g., retry on the same token) the create will P2002. Consider mapping the conflict explicitly or using a deferred-uniqueness pattern. |
| 🟡 | Performance | Every `createUser` and every `resendInvitation` now does **2 writes per row inside the transaction** (`create` + `update`). At scale, that's 4 extra writes per user-create transaction (2× SaUser, 2× SaInvitation) — measurable on Postgres under load. Acceptable for the auth flow, but worth a follow-up to allocate the id up front (`SELECT nextval('saUser_id_seq')`) and `INSERT` with the encoded publicId in one statement. |
| 🟡 | Code Duplication | The `create → update → encode` pattern is now repeated in three places (`createUser` × 2, `resendInvitation` × 1). Extract a helper like `createWithEncodedPublicId(tx, table, data)` in `packages/db/` to keep the pattern consistent for future entities and to localize the fix when bug-0005-style issues recur. |
| 🟡 | Tests — Mock Hygiene | The new spec mutates the mock at runtime via `(mockPrisma.saInvitation as unknown as { update?: jest.Mock }).update = jest.fn()...`. The cast bypasses the typed mock map and silently couples the test to runtime mutation order. Add `update: jest.fn()` to the top-level `jest.mock(...)` factory like the rest of the methods. |
| 🟢 | Correctness | The `await` chaining inside `prisma.$transaction` correctly preserves rollback semantics — if the second update throws, the stub create rolls back. |
| 🟢 | Tests — Coverage | Asserts that the rewritten `publicId` does NOT start with `tmp_`. Good guard against regression. |

**Recommendation:** **Request Changes** — extract the helper (or document the invariant), normalize the mock setup, and consider the single-statement variant. Not a blocker for ship, but the duplication will be cheaper to fix now than after the next two entities adopt Sqid publicIds.
