- Branch: `palette-ux-validation-rebasing-11334916006266374535`
- Files changed: 13 · +100 / −7

**Findings**

- 🔴 **Critical — seed regression against 2FA prompt gate.** `demo-multitenant.ts`, `demo-resource-server.ts`, and `seed.ts` now write `twoFactorPromptedAt: new Date()` on user creation. The gate at `apps/admin/lib/two-factor-prompt.ts` returns `true` only when `promptedAt` is null (or older than `intervalDays`). Setting the timestamp at seed time means seeded platform admins + demo users are treated as **already prompted**, silently suppressing the 2FA enrollment prompt for `intervalDays` (14 by default) after every fresh seed. If the intent was "mark as prompted so tests don't hit the prompt page," it also masks any regression in the enrollment flow for exactly the users your tests exercise. Recommendation: leave the field `null` in seeds, or gate it behind an explicit `SEED_SUPPRESS_2FA_PROMPT` env flag.
- 🟡 **Warning — write is inside `ensureUser` upsert path.** In both demo seeds the assignment sits in the branch that creates the row, but subsequent re-seeds will *not* refresh the value. That's fine for idempotency, but combined with the finding above, it means CI/dev DBs will permanently carry the "prompted at seed time" timestamp across seed re-runs — you can't recover by re-seeding.
- 🟡 **Warning — `useEffect` rebasing runs on every `users` reference change.** `UsersTable`'s new effect (`[users]`) fires whenever the server-component parent re-renders and passes a new array reference, even if content is identical. Harmless today (setState with same object identity is a no-op after React's bailout), but if `selectedUser` later gains a shallow copy in the finder, this will trigger drawer re-renders on every `router.refresh()`. Consider comparing by `prev?.id` and returning `prev` when the row is unchanged.
- 🟢 `autoSignIn: false` on BetterAuth `emailAndPassword` — correct hardening, prevents implicit session creation on registration. Matches enterprise expectation.
- 🟢 Validation split (`nameRequired` / `urlRequired`) + `noValidate` + new tests are clean, additive, and localized (en + fr).
- 🟢 Missing i18n or unit coverage: none noted for changed lines.

**Recommendation:** 🔴 **Request Changes** — remove `twoFactorPromptedAt: new Date()` from seeds (or make it opt-in). Everything else is fine.

Whichever merges second will rebase noisy. Recommend closing #314 in favor of #315 **after porting** the two things unique to #314: (a) `FormField` refactor and (b) the e2e `two-factor-prompt` handler.
- 🟡 **Warning — e2e selector fragility.** `apps/admin-e2e/auth-state.setup.ts` matches the prompt-skip button with `/skip for now/i`. If the page also renders a "Don't skip for now" or a "Skip 2FA setup for now" variant in the future, this regex will match multiple buttons and Playwright will throw. Prefer an exact string or a `data-testid`.
- 🟡 **Warning — race between `waitForURL` and prompt appearance.** The setup expects either a landing route *or* `/login/two-factor-prompt` within 20s, then clicks "Skip for now" and waits another 10s. If BetterAuth ever redirects landing → prompt asynchronously after the first `expect(page).toHaveURL(...)` resolves against a landing route, the `if (page.url().includes(...))` check misses it and the storage state gets saved mid-transition. Consider a single deterministic wait: land on prompt (if 2FA disabled + not prompted) → click Skip → land on `/(users|apps|orgs|permissions|roles)`.

- 🟢 New tests target the two new client-side validation branches directly and assert `createAppAction` / `updateAppAction` are **not** called — good negative-path coverage.
- 🟢 Does **not** touch seed files, so does **not** carry the #315 seed regression.

**Recommendation:** 🟡 **Needs Discussion** — decide whether to keep #314 or fold its two unique deltas (FormField refactor + e2e handler) into #315.
