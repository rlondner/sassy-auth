## PR #316 — 🎨 Palette: Standardized Table Copy and Row Action Accessible Tooltips

- Author: `google-labs-jules[bot]` (opened by @rlondner) · Branch:
  `palette/accessible-table-tooltips-6451768424245745641` · Base: `master`
- 18 files · **+163 / −79**

**What it intends:** wrap the Sqid copy button and the `more_vert` row-action trigger of the 5
admin tables in Radix `<Tooltip>` from `@sassy-auth/ui`, with localized `aria-label`s + a
dynamic "copied!" announcement; expand `common.*` en/fr strings; update table tests.

### Findings

- ⚪ **[RETRACTED] "Tooltip with no provider → tables crash" ([bug-0249](../bugs/bug-0249.md)) —
  false positive.** Initial reasoning (Radix `Tooltip.Root` needs a `TooltipProvider`, and
  `grep apps/admin` found none) was **wrong**: `SidebarProvider` (packages/ui
  `…/sidebar.tsx:140`) renders `<TooltipProvider delayDuration={0}>` around the whole admin
  shell (`AdminShell → SidebarShell → SidebarProvider → SidebarInset → {table pages}`), so a
  provider **is** in scope. No crash. PR #317 (the report) was closed + branch deleted. This is
  the same false positive the 2026-08-04 review recorded — kept in `bug-0249.md` to prevent a
  third re-file.
- 🔴 **Critical — bundled seed 2FA-prompt suppression ([bug-0250](../bugs/bug-0250.md)).**
  `seed.ts`, `demo-multitenant.ts`, `demo-resource-server.ts` add
  `twoFactorPromptedAt: new Date()`. `shouldPromptTwoFactor` returns `true` only when
  `promptedAt` is null, so seeded platform admins + demo users are treated as "already prompted"
  → **no 2FA enrollment prompt** for `TWO_FACTOR_TRUST_DAYS` (14). Not cleared by re-seed (write
  is in the create branch of an idempotent upsert). Identical change also in PR #315. Absent on
  `master`. **Fix:** leave the field null, or gate behind an explicit
  `SEED_SUPPRESS_2FA_PROMPT` flag fenced off production.
- 🟡 **Warning — scope creep + stub-only tests ([bug-0251](../bugs/bug-0251.md)).** A
  UI-titled PR silently edits `auth.config.ts` (`autoSignIn: false`) and all three seed files
  with no mention in title/body — the bug-0247/0248 pattern again. The table tests
  `jest.mock('@sassy-auth/ui', …)` with `Tooltip: Passthrough` / `TooltipTrigger: Trigger`, so
  the real primitive never runs — coverage of a stub (bug-0093 recurring). The substantive
  hidden change is the bug-0250 seed regression.
- 🟡 **Minor — nested double-`asChild` on the row-action trigger ([bug-0252](../bugs/bug-0252.md)).**
  `TooltipTrigger asChild` → `DropdownMenuTrigger asChild` → one `<button>` in all 5 tables.
  Plausible Radix Slot fragility (tooltip may not dismiss when the menu opens) — low-confidence,
  flagged for a runtime check, not a confirmed defect.
- 🟢 **Positives.** The `aria-label` for the copy button now uses `t('common.copy')` /
  `t('common.copied')` and the `more_vert` button's previously **hardcoded** `"more actions"` is
  now `t('common.moreActions')` — a genuine i18n/a11y improvement. en/fr `common.*` additions are
  clean and symmetric. `autoSignIn: false` is defensible hardening **in isolation** (the problem
  is that it rides in unreviewed under a tooltip title, and duplicates #315).

**Recommendation:** 🔴 **Request Changes / do not merge as-is.** Blocker: drop the
`twoFactorPromptedAt` seed writes (bug-0250). Then split the auth/seed edits out of the UI PR
(bug-0251), de-duplicate against #315/#314, and de-mock at least one table test so the real
Tooltip primitive is exercised. (The tooltip rendering itself is fine — the provider-crash
concern was a false positive, bug-0249.)
