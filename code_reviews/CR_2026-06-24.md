### PR #140 — `🎨 Palette: Standardized table tooltips & Monorepo CI fixes` — google-labs-jules[bot] *(updated 2026-06-23, in window)*
- **Files:** 31 changed · **+303 / −169**
- **Scope:** Three unrelated concerns merged into one PR
  1. Admin UI: wrap row-action `<DropdownMenuTrigger>` and copy buttons in shadcn `Tooltip`, add `TooltipProvider` to root `layout.tsx`, add `common.moreActions/copy/copied` i18n keys (EN+FR), translate previously-English FR `common.*` strings (`save/edit/delete/confirm`).
  2. CI: drop pinned `pnpm/action-setup@v4` `version: 9`; add `pnpm exec turbo build --filter=!@sassy-auth/auth-server` step before Prisma generate in `.github/workflows/e2e.yml`.
  3. Auth-server: silence ~60 TS errors by inserting `: any` annotations and replacing `type Tx = Parameters<Parameters<typeof prisma.$transaction>[0]>[0]` with `type Tx = any` across permissions/RBAC, users, roles, permissions, orgs, apps, invitations, and seed code.

- **Findings**
  - 🔴 **Critical — type erosion across the authorization layer.** ~56 `: any` annotations introduced, the majority inside security-sensitive paths: `common/permissions/check-permission.ts`, `check-permission-for-app.ts`, `assert-caller-can-grant-system-perms.ts`, `users.service.ts` (role/permission resolution, escalation guard), `roles.service.ts`. Concretely:
    - `saUser.roles.forEach((ur: any) => ur.role.permissions.forEach((rp: any) => callerPerms.add(rp.permission.name)))` — the entire permission-name set is now built from `any`-typed inputs. A future refactor that renames `permission.name`, drops `role`, or changes the include shape will compile cleanly and silently produce an **empty `Set<string>`**, which fails-open on the `if (perms.has(required)) return` checks downstream.
    - `assertCallerCanGrantSystemPerms(callerBaId, systemPermNames as string[])` — the `as string[]` cast in `users.service.ts` exists only because `(rp: any)` upstream destroyed inference. The escalation guard now relies on a string assertion against an `any`-derived array.
    - `type Tx = any` (apps, orgs, permissions, roles, users, seed) — discards `Prisma.TransactionClient` and removes compile-time enforcement that only Prisma delegate calls run inside the transaction. A stray `prisma.xxx` (non-`tx`) call inside the callback would break atomicity and now compiles.
    - These are not test-only changes; production controllers call these services.
  - 🟡 **Warning — PR conflates unrelated concerns.** UI tooltips, CI build pipeline, and a wholesale TS-suppression pass are bundled. Cannot revert (1) without losing (2)/(3), cannot review (3) in isolation. Per CLAUDE.md / spec-driven workflow, each should be a separate vertical slice.
  - 🟡 **Warning — root cause of the TS errors not addressed.** The PR description says "60+ pre-existing TypeScript errors in auth-server (transactions & implicit any) to unblock the build". The proper fix is `Prisma.TransactionClient` for the Tx type and `Prisma.<Model>GetPayload<{ include: typeof X_INCLUDE }>` (already used elsewhere in `users.service.ts`, e.g. `USER_INCLUDE`) for query results. The PR has the pattern available in the same file and chose `any` anyway. Filing as tech-debt risks permanence.
  - 🟡 **Warning — CI determinism regression.** Removing `version: 9` from `pnpm/action-setup@v4` lets the action pick `packageManager` from `package.json` (good if set) or its own default (drift risk). Confirm root `package.json` has `"packageManager": "pnpm@<x.y.z>"`; otherwise different runners can install different pnpm minors, defeating `--frozen-lockfile`.
  - 🟡 **Warning — i18n key inconsistency.** New `common.copy / common.copied / common.moreActions` added, but `apps-table.tsx` still passes `aria-label={copied ? t('common.copied') : t('common.copy')}` while keeping `aria-label="more actions"` (hardcoded English) elsewhere depending on the file. Audit all `aria-label=` literals across the six table components for FR coverage.
  - 🟡 **Warning — accessibility/UX regression risk on `ThemeToggle`.** Native `title={label}` attribute removed in favor of a Radix `TooltipContent`. The new tooltip only appears while the button is in `TooltipProvider` scope (now provided by root layout — OK), but it no longer surfaces on touch devices the way a `title` did. Verify with a Playwright a11y assertion.
  - 🟢 **Clean — FR `common.*` strings.** Previously held EN values (`"save": "Save"`); now correctly translated.
  - 🟢 **Clean — `TooltipProvider` placement.** Wraps `NextIntlClientProvider`'s children at the root, single source of truth.
  - 🟢 **Clean — new `theme-toggle.test.tsx`.** Reasonable passthrough mock for the tooltip primitives.

- **Test coverage gap:** The auth-server type changes ship with **zero new tests**. The escalation-guard, permission-check, and transaction paths all gained `any` annotations without a regression test asserting that a malformed include shape would still throw rather than silently grant.

- **Recommendation:** **Request Changes.** Split into three PRs:
  1. UI tooltips + i18n (mergeable as-is, modulo aria-label audit).
  2. CI build step + pnpm pinning verification.
  3. TS error fix using `Prisma.TransactionClient` and `Prisma.<Model>GetPayload<>` — not `any`. Block on this until done; do not merge the type erosion into `master`.
